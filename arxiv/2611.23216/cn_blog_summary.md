# Benchmarks vs. Merges：高分模型没多完成工作

编程模型在 SWE-Bench Pro 上高出 10.8 分，能否转化为更多被项目保留的代码？论文利用 Claude Fable 5 被强制停用 19 天的外部事件，区分“模型更强”与“真实产出更多”：Fable 5 可用仅对应 7 天 PR 合并率提高 **1.4 个百分点**（95% CI $[-1.4,+4.3]$，不显著），另外五次模型升级的合并率平均变化为 **-0.9 个百分点**。

## 核心创新：用自然实验隔离模型影响

- 2026 年 6 月 12 日至 7 月 1 日，出口管制使 Fable 5 无法访问；开发者并非主动停用，同一批人被迫改用其他模型。Fable 5 与期间最强的 Opus 4.8 在 SWE-Bench Pro 上分别为 80.0% 和 69.2%。
- 停用分析比较 297 名使用过 Fable 5 的开发者与 8,908 名始终使用 Opus 4.8 的对照者，采用双重差分，控制开发者与日历日固定效应，并以发布前时期作 placebo，扣除共同时间变化。
- 升级分析覆盖 1,208 名切换模型的开发者和 15,442 个 PR，比较同一开发者升级前后的变化；这部分是观察性关联，不作同等强度的因果解释。
- 研究通过 PR 描述和 commit 的模型标注识别模型，抽查 200 个 PR 的升级前、后匹配率分别为 96% 和 99%。主要指标是 **7 天合并率**与**每周合并 PR 数**。

## 关键结果：分数增长没有变成合并产出

- 处理组 PR 的 Fable 5 使用率从 82.3% 降至 0.9%，合并率却基本不变。主估计不支持超过约 **4.3 个百分点**的平均提升；placebo 为 -2.6 个百分点，也不显著。
- 五次主升级的点估计全部为负，汇总为 **-0.9 个百分点**（95% CI $[-1.9,+0.2]$）；每周合并 PR 数仅变化 **+2.4%**（$[-4.9\%,+10.2\%]$），创建 PR 数变化 +2.7%，均不显著。
- 自动检查失败率变化 +0.3 个百分点，测试或构建失败变化 +0.2 个百分点，同样没有显著改善。多种权重、观察窗口及“30 天内未 revert”等稳健性检查未推翻结论。
- 直接汇总不同模型的 PR 会误导排名：未经调整时 Fable 5 落后 Opus 4.8 2.6 个百分点；控制同一开发者、同一仓库后差距缩至 -0.9 且不再显著，说明简单比较混入了人与项目差异。

## 为什么榜单增益没有进入日常工作？

- **任务可能本就在旧模型能力范围内。**开发者倾向委派容易验证、出错成本低的任务；升级前后，PR 描述长度、文件数和新功能比例均无实质变化，没有明显改派更难任务。
- **merge 是有用但不完整的产出信号。**2,019 个 PR 中，95% 由作者自己合并，90% 没有其他账号批准，不能直接等同于独立评审或代码质量。
- **存在天花板，但不是唯一解释。**切换者升级前已有 94.5% 的 PR 在 7 天内合并；不过 1 小时合并率、未合并子样本、每周产量和自动检查也都没有改善。
- **benchmark 只覆盖工程的一小段。**通过测试无法完整衡量澄清需求、适配项目约定、响应评审、返工与维护成本。

## 结论与边界

论文并未证明强模型毫无价值，而是表明：在这批 Claude Code 公开 PR 工作流中，困难 benchmark 任务的增益没有自动转化为更多合并产出。结论受 19 天停用窗口、模型标注选择、混合旧代码及单次升级统计功效限制，也不能直接推广到所有工具与组织。未来还需测量任务难度、独立评审、返工和节省时间，才能判断高分模型真正创造价值的位置。论文已公开脱敏数据与复现代码：[benchmarks-vs-merges](https://github.com/ningkko/benchmarks-vs-merges)。
