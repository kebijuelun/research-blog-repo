# Rounding Alignment：对齐三处舍入稳住 BF16 RL

同一个 BF16 Checkpoint，vLLM 采样、Hugging Face 训练却可能形成两个数值策略，破坏 LLM 强化学习依赖的 On-Policy 假设，令数学推理训练先提升、后崩溃。论文只调整 RoPE、SwiGLU 和残差 RMSNorm 的舍入位置，便让 4 个 Qwen 系列模型都避免了基线崩溃，Token 级 KL 降低 9.1%–25.5%；仅对齐 RoPE 也能稳定全部实验，训练延迟仅增 0.90%–2.04%，峰值显存不变。

## 问题不在 BF16，而在何时舍入

推理与训练系统即使加载相同权重，也可能因精度转换、Kernel 实现和归约顺序不同而计算出不同概率。PPO Clip 只能限制后续更新，无法消除更新前已经存在的策略差异。

- **融合 Kernel**：可将中间值保留在 FP32 寄存器中，直到区域输出才转为 BF16。
- **分开执行**：往往先把中间结果写成 BF16，再交给下一个算子。
- **关键后果**：两边最终都输出 BF16，后续算子收到的输入却已经不同。

最小对照实验进一步验证了这一机制：Compiled—Compiled 与 Eager—Eager 均稳定，两种交叉组合则都在准确率提升后崩溃。稳定的条件不是某一种执行模式，而是推理与训练执行相同的数值过程。

## 方法：只改三处，不动整个系统

作者检查 Qwen2、Qwen3 的计算图，定位三个受融合影响的区域，并在训练端对齐中间精度和 BF16 输出位置：

- **RoPE 路径**：归一化、旋转位置编码的乘积与求和保留 FP32，最后再输出 BF16。
- **SwiGLU**：SiLU 结果不提前舍入，以 FP32 完成门控乘法。
- **残差 RMSNorm**：让归一化直接读取未舍入的 FP32 残差和。

笔者认为，这一设计的实用之处是干预足够小：推理引擎、矩阵乘法与 Attention Kernel、BF16 权重和 RL 目标都不变，也不新增修正项或超参数。

## 结果：零误差并非稳定的必要条件

固定权重遍历三区域的 8 种组合后，全部对齐在三个模型上取得最低 KL，相对全 BF16 分别下降 25.5%、9.1% 和 12.5%。Shapley 归因显示，RoPE 贡献了联合收益的 76.9%–91.8%，是首要干预对象。

但“更多 FP32”并不必然更好：局部组合可能增大 KL，关键是两侧舍入位置一致。真正的 RL 对照中，RoPE 单区域、三区域对齐和 Zero-Mismatch Backend 都避免崩溃；前两者仍保留非零小差异。换用 DAPO-Math-17k 后，结论依然成立。

成本上，RoPE 对齐只增加 0.90%–2.04% 训练计算延迟且不增加峰值显存；三区域对齐增加 5.33%–10.92% 延迟和 0.41–0.89 GiB/GPU 显存。因此，RoPE 是更轻量的首选，三区域方案适合进一步压低静态策略差异。

这项实验目前仅覆盖两个数学数据集和 Qwen 架构家族；推广到其他模型时，仍需重新检查计算图，验证“定位敏感舍入—定点对齐”是否充分。
