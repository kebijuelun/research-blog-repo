# Temporal Shortcuts：用事件索引纠正 VLA 记忆

记忆增强 VLA 的高分可能来自“读时钟”而非记住事件，这会让机器人在没有任务进展时提前停止；两次 5 秒暂停使 PickXtimes 成功数从 47/50 降至 16/50、SwingXtimes 从 44/50 降至 10/50，而无需重训的事件索引在 7 个探针上追回了 74% 的可恢复差距。

## 核心发现：空白时间会制造“虚假进度”

- 研究以 RoboMME 的 PickXtimes、SwingXtimes 计数任务和 FrameSamp-Modul 为主，其记忆包含 32 个按时间均匀采样的历史帧及绝对时间编码。
- 作者注入三类“空事件”：暂停、手腕空转和空抓。它们消耗时间，却不改变任务依赖的世界状态。
- 关键对照是 visible/hidden：物理中断完全相同，后者只把空事件帧及时间戳从记忆中隐藏。隐藏后，两项任务在暂停下分别恢复到 45/50 和 47/50，证明损伤来自记忆，而非机械臂姿态。
- 失败并非普通受扰：暂停与空转下，PickXtimes 的 34/34 个失败、SwingXtimes 的 36/40 个失败都是提前停止。仅两次 1.5 秒暂停，成功数就降至 24/50 和 21/50；随机微停顿也会触发同类问题。

## 两条机制：显式时钟与槽位占用

- **时间本身就是进度捷径。**仅输入当前时间预测已完成重复数，在 RoboMME 两项任务上准确率达 0.890 和 0.802，显著高于 0.467 和 0.423 的多数类基线；多组真实遥操作数据也存在这种相关性，但因果干预仅在仿真中完成。
- **缩放时间戳即可翻转失败方向。**不改变历史帧，时间戳乘以 1.5 时，PickXtimes 从 47/50 降至 18/50，32 个已分类失败全部提前按按钮；乘以 0.5 时成功 24/50，主要转为额外重复。长暂停实验进一步支持“读时钟”，而非“每段暂停算一次重复”。
- **删除时间编码仍不够。**NoClock 在暂停下仍只剩 21/50 和 14/50；把暂停帧统一替换成暂停前最后一帧，损伤几乎不变。连续空帧占据记忆槽位本身就会推进隐式进度，12 个空槽位已能复现大部分损伤。

## 修复：改变记忆索引，而非粗暴改数据

暂停数据增强并未教会模型数事件：强增强虽消除了 PickXtimes 的暂停额外损伤，却把无事件成功数从 32/50 降至 24/50；弱增强也未能同时保住正常计数与抗暂停能力。

更有效的是测试时直接采用**事件索引**：当机器人返回已保留状态且外部场景一致时，将闭环压成一个代表帧和一个时钟 tick；持续静止时仅保留前 5 帧。抓取、释放、负载切换及场景变化则作为不可跨越的保留边界。

- 在已发布模型的 7 个探针上，合计成功数由 111/350 提升至 248/350，追回 visible 与 hidden 之间差距的 74%。
- held-out 新环境种子上由 118/350 提升至 243/350，净增 35.7 个百分点，7 项中 6 项达到显著。

结论不是时间信息永远有害，而是记忆应由“发生了什么”推进，持续时间只在任务需要时作为独立输入。事件索引仍有边界：可能误压缩真实循环，对单向空抓、随机微停顿效果有限，且尚未验证真实传感噪声下的部署可靠性。
