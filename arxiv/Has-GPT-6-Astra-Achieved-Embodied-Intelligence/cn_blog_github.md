# GPT-6-Astra 实现具身智能了吗？12 个基准、8 台真机与下一代评测标准的一次全面检验

当一个通用大模型不再只是"指挥"机器人，而是直接闭环输出末端执行器动作时，它的能力边界在哪里？这篇由商汤研究院、ACE Robotics、南洋理工 S-Lab 等组成的联合团队发布的技术报告，对 GPT-6-Astra 做了一次近乎"榨干式"的体检：在 12 个主流具身基准上，用统一的协议（in-context learning + 最高 10 倍步数预算）测出它的能力上限。最硬的数字是：在 LIBERO-Long++ 上成功率达到 100%（此前 SOTA 仅 82.0%），在 DexJoCo 灵巧手任务上 87.3%（SOTA 40.3%）——几乎翻倍。但作者真正想回答的不是"它有多强"，而是"这对领域意味着什么"：报告后半部分用 8 个真实机器人平台和一套全新的基准设计原则说明，**GPT-6-Astra 已经跨过了"具身能力"的门槛，却还没跨过"实用具身智能"的门槛**。

## 一、研究设计：一套"把模型用到极限"的统一协议

以往的具身评测大多是"为模仿学习策略量身定做"的：收集示范、训练策略、在同任务的留出集上测试。直接用这种方式评 GPT-6-Astra 并不公平——它不做任何权重更新。作者的解法是用两个条件拉平信息差：

- **In-context learning（ICL）**：允许模型在测试前"研读"基准的训练集示范，把学到的东西写成一个冻结的**知识包（knowledge package）**，测试时随每个 episode 一起提供。模型权重全程不变。
- **扩展交互预算（extended budget）**：把官方步数上限放宽到最多 $10\times$。动机很直接：评测中经常观察到 GPT-6-Astra 能发现动作失败、修改策略并自我恢复，严格的步数限制会把这个过程"掐死"在中途。

![ICL 协议](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/arxiv/Has-GPT-6-Astra-Achieved-Embodied-Intelligence/blog_images/icl_protocol.png)

> 图解：每个任务先由 GPT-6-Astra 研读训练数据并写出知识包 $K$，测试前冻结。每个测试 episode 开启全新会话，在标准（$1\times$）或扩展（$10\times$）预算下运行。模型权重不变、$K$ 不变、episode 之间不传递任何信息——这保证了评测的隔离性。

协议的关键纪律是：扩展预算不是"重开十次"，而是在同一个 episode、同一个模拟器状态和同一段对话里继续执行，保留全部交互历史和环境后果；$1\times$ 的结果被单独冻结记录，不会被续跑覆盖。

## 二、主结果：12 个基准上的能力上限

12 个评测设置覆盖五类形态：桌面机械臂（LIBERO-Long++、LIBERO-PRO、LIBERO-Ultra-Long、RoboDojo、RoboLab）、人形机器人（SIMPLE）、移动平台（BEHAVIOR）、灵巧手（DexJoCo、Bench2Dex）、导航（VLN-CE R2R/RxR、LHPR-VLN）。

## 三、ICL 知识包：不更新权重的"训练"

这部分是我认为全文对工程实践最有启发的内容。GPT-6-Astra 在准备阶段自主决定研读什么、保留什么，但跨基准沉淀下来的知识包都收敛到六个组件，这个结构本身就是一份"机器人 agent 上下文工程"的清单：

![知识包内容](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/arxiv/Has-GPT-6-Astra-Achieved-Embodied-Intelligence/blog_images/icl_package.png)

> 图解：知识包的六个反复出现的组件——任务指引、运动参考、视觉参考、可执行 helper、检查与恢复、元数据与出处。测试时 $K$ 与当前观测一起被读取，用于检索、适配和校验动作。

1. **任务指引（Task guidance）**：任务目标、执行阶段划分、子任务顺序与约束的书面策略。
2. **运动参考（Motion references）**：从示范中提取的轨迹段、抓取构型、相位锚点等数值样例。
3. **视觉参考（Visual references）**：示范关键帧与接触区域裁剪图，用于与当前观测比对。
4. **可执行 helper（Executable helpers）**：正逆运动学、参考检索、动作生成等可复用 Python 程序。
5. **检查与恢复（Checks & recovery）**：可观测的完成判据，以及"失败症状 → 纠正动作"的对照表。
6. **元数据与出处（Metadata & provenance）**：机器人规格、接口约定、材料来源与离线校验记录。

回溯分析显示，所有被审计的基准上 GPT-6-Astra 都遵循同一工作流：读任务指引 → 通过 helper 检索候选运动 → 对照视觉参考检查执行结果。它**不是回放示范，而是适配示范**——例如在 Bench2Dex 的 Ball Box Loading 中，它重映射参考关节角并补偿了 4–5 cm 的工作台高度差，同时保留示范中的双臂支撑几何；在 DexJoCo 的 Photograph 任务中，一次滑脱后它改选了另一条参考拾取轨迹。

ICL 的收益有多大？在 SIMPLE 基准的对照实验里最清楚：标准预算下，zero-shot 成功率 70.8%，加上任务级 ICL 后升至 90.8%（+20 个百分点），与已发表的专用模型 Psi-0（90.0%）相当；且在 81 个两种设置都成功的 episode 上，平均动作步数从 376.9 降到 210.4（-44.2%），平均测试耗时从 47.0 分钟降到 31.4 分钟。代价是 token 消耗从 2.64M 涨到 6.40M，外加每任务一次性准备成本 8.34M token 和 90.4 分钟。

| 指标 | Zero-shot | ICL | Psi-0（参考） |
|---|---|---|---|
| Common-4 成功率 | 85/120（70.8%） | **109/120（90.8%）** | 108/120（90.0%） |
| 平均动作步数 | 376.9 | 210.4 | -- |
| 平均测试 token（百万） | 2.64 | 6.40 | -- |
| 平均测试耗时（分钟） | 47.0 | 31.4 | -- |

> 博主点评：这个设计的聪明之处在于，它把"训练"变成了一次性的离线写作过程，产出的是人类可审计、可复用的资产（笔记 + 代码 + 图），而不是一坨梯度。但它的软肋同样明显——知识包高度任务相关。

**ICL 的迁移瓶颈**在 RoboDojo 的 Open 组暴露得最清楚：这 8 个任务没有任务专属示范，只能用从其他四组任务研读出的通用知识包，结果成功率在所有组中垫底（$1\times$ 仅 15.0%）。训练数据覆盖不到的分布，ICL 也救不回来。

## 四、扩展预算：成功率是"买"来的，代价是时间和钱

把步数上限从 $1\times$ 放宽到 $10\times$，几乎每个基准的成功率都在涨，但曲线形状各不相同：

![成功率 vs 步数预算](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/arxiv/Has-GPT-6-Astra-Achieved-Embodied-Intelligence/blog_images/step_sr.png)

> 图解：横轴是官方步数上限的倍数，纵轴是成功率；点为实测值，粉色曲线为拟合趋势，灰线是上界（假设所有耗尽预算仍未成功的 episode 在无限预算下都有潜力成功）。RoboDojo 先快速上升再进入收益递减；DexJoCo 较早触及平台期；Bench2Dex 在 $5\times$ 到 $10\times$ 之间还在持续获益。

成功的另一面是成本。作者给出了一条朴素的估算规则：绝大多数 token 是缓存输入（约 98%），按**1M token ≈ 1 美元**计。

![成本统计](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/arxiv/Has-GPT-6-Astra-Achieved-Embodied-Intelligence/blog_images/cost.png)

> 图解：(a) 每个基准单任务的平均 token 用量，(b) 平均耗时，自下而上堆叠为 ICL 准备、$1\times$ 运行、扩展到 $10\times$ 的增量。$10\times$ 增量较小是因为多数 episode 在成功或终局失败后提前终止，并未用满预算。

两组数字最能说明问题：

- **RoboDojo**：$1\times$ → $10\times$，成功率 27.6% → 81.9%，但单 episode 平均成本从 12.5M token / 55 分钟涨到 38.6M token / 216.6 分钟。每个成功 episode 的 token 成本几乎不变（约 45M → 47M），说明更多的钱花在了"最终仍然失败"的难 episode 上。
- **LIBERO-Long++**：$1\times$ 下成功率已超 97%，但每个 episode 仍要烧约 100 万 token 和近一小时；Ultra-Long 则涨到约 900 万 token、近两小时。

还有一个常被忽略的口径问题：RoboDojo 的标准预算是 200–1,900 个控制步，以 25 Hz 控制频率换算成"实际运动时间"只有 8–76 秒，而单 episode 平均推理与工具耗时是 55 分钟——**思考时间是运动时间的约 24 到 198 倍，中位数约 100 倍**。模拟器在模型思考时是暂停的，这笔时间在 benchmark 里是"免费"的；在真实机器人上它不是。这个观察直接埋下了后文基准改革的伏笔。

## 五、残余失败：钱和示范都给足之后，还差什么

即便 ICL 和 $10\times$ 预算都给满，仍有系统性失败。作者从失败视频和 agent 日志中归纳出三类行为失败模式：

![残余失败模式](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/arxiv/Has-GPT-6-Astra-Achieved-Embodied-Intelligence/blog_images/fig7_failure_cases_v9.png)

> 图解：每对图展示关键事件前后的状态，紫色箭头标注相关物体。(a) 物理成功验证失败；(b) 无法从有后果的动作中恢复；(c) 长程任务中进度保持失败。

- **验证物理成功（Verification）**：模型能察觉"任务还没结束"，却说不出"哪个物理条件没满足"，于是纠正不收敛。典型案例：Bench2Dex 拼图任务中，它认为四块拼块已成矩形，反复微调，结果每次"纠正"反而把拼块拨开；RoboDojo 挂杯子任务中，头相机里杯柄与挂钩的像素重叠被当作"挂上了"，同一时刻腕部相机却显示杯子躺在桌上。视觉上的"看起来像"与任务真实的接触/支撑/对齐条件之间存在鸿沟。
- **从有后果的动作中恢复（Recovery）**：物理世界里每次尝试都从上一次留下的状态继续，有些改变不可逆。倒洒的液体扶起杯子也收不回；DexJoCo Assembly 里销钉落地，模型判定不可达后直接"停车"放弃，大部分预算原样浪费。成功的恢复往往伴随策略的本质改变而非重复——如 DexJoCo Fold Glasses 中改从侧面接近、先试提验证抓握再完成任务。
- **长程进度保持（Progress preservation）**：已完成的子目标不会自动保持完成。RoboDojo 收纳任务中，笔记本和耳机都已放好，回头调整一个耳罩却把耳机整个拉下了支架，预算耗尽前没能重新挂上；BEHAVIOR 的 can_meat 任务中，已拿在手里的罐子在下一段动作中倾斜掉落，进度只能重建。长程任务难不只是因为步数多，而是因为必须一边推进一边守护已有成果。

再加上两条方法层面的局限——**ICL 知识包难以迁移到未见任务**、**时间与 token 成本高到无法支撑实时部署**——报告对"GPT-6-Astra 是否已实现具身智能"给出了第一层答案：基准层面接近，实用层面尚远。

## 六、Harness 消融：模型之外的另一半战场

解决了"模型能做什么"之后，下一个问题是"什么样的外围系统（harness）能把能力兑现出来"。作者在 RoboDojo 的 42 个任务上做了受控消融，核心结论可以用一张"成本-性能"散点图概括：

![Harness 消融](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/arxiv/Has-GPT-6-Astra-Achieved-Embodied-Intelligence/blog_images/harness_token_performance_v8.png)

> 图解：横轴为 token 成本（百万），纵轴为五类任务得分的平均。虚线交于 agentic GPT-6-Astra 基线参考点，把平面分为四个象限——左上是"又便宜又好"的理想区。可以看到 ICL + 闭环 VLA 位于右上（性能最高但最贵），历史压缩等设计则把配置推向左侧。

### 6.1 System 2 与 System 1 如何协作

以 GPT-6-Astra 为慢思考"System 2"、RoboDojo 微调后的 $\pi_{0.5}$ 为快反射"System 1"，比较三种协作方式：

| 配置 | SR (%) ↑ | Tokens (M) ↓ |
|---|---|---|
| Baseline（直接控制） | 15.56 | 2.560 |
| 纯 VLA（$\pi_{0.5}$） | 6.91 | -- |
| + VLA 开环（GPT 给子目标，VLA 直接执行） | 5.83 | 0.387 |
| + VLA 闭环（VLA 提议、GPT 逐个审） | 23.61 | 7.664 |
| + VLA 闭环（$L=4$，每次审 4 个动作） | 25.83 | 2.796 |
| + ICL | 29.67 | 9.567 |
| **+ ICL & VLA 闭环** | **54.17** | 19.335 |

三个要点：

- **开环委托几乎无效**（5.83%，比纯 VLA 还低）：把子目标扔给 VLA 执行，等于放弃了 GPT 的判断力。
- **闭环审查有效但昂贵**：逐动作审查把成功率拉高约 20 个百分点，token 却暴涨；把审查窗口拉长到 $L=4$，token 降 63.5% 的同时成功率反而升到 25.83%——"审一串"比"审一个"更划算。
- **ICL + 闭环 VLA 是最强组合**（54.17%），比最佳非 ICL 配置高 28.34 个百分点，但 token 约为其 6.9 倍。性能与成本的权衡依然尖锐。

### 6.2 动作表示与动作分块

| 配置 | SR (%) ↑ | Tokens (M) ↓ |
|---|---|---|
| Baseline（绝对笛卡尔 EEF 目标，$L=1$） | 15.56 | 2.560 |
| 方向性运动指令 | 18.06 | 1.908 |
| 直接关节角控制 | 9.72 | 1.120 |
| 固定动作分块（$L=4$） | 11.39 | 0.435 |
| 自适应动作分块（$L\in\{1,2,3,4\}$） | **20.00** | 1.146 |

- **直接输出关节角效果最差**（-5.84 个百分点）：多模态模型的推理空间与低层关节控制空间之间存在"表示鸿沟"；语义上更对齐的末端执行器指令明显更好。
- **固定长分块省 token 但伤成功率**（$L=4$ 时 -4.17 个百分点）：提交一串动作意味着放弃了中途根据观测修正的机会。
- **让模型自选分块长度是最优折中**：成功率最高（20.00%）且 token 不到基线一半。可预测的动作段合并提交，不确定的接触交互则缩短承诺。

### 6.3 Agent 组件：加组件不如加对组件

四个候选组件逐一加到基线上（42 个任务）：**反馈子代理**（评估执行结果、建议继续/调整/重试）收益最大，平均分 +7.22、成功率 +9.16 个百分点，token 仅增 7.03%；**历史压缩**（保留最近 4 轮、早前交互滚动摘要至 2,000 token）成功率 +5.55 个百分点的同时把 token 砍掉 66.41%，是名副其实的"又便宜又好"；**规划子代理**整体收益较小（+3.25 分）且集中在 Memory 类任务；**执行子代理**反而拖累了成绩。结论很明确：有效的 agent 设计取决于新增推理是否支撑了执行，而不是组件的数量。

## 七、真实世界验证：模拟里的两大前提，在真机上都不成立

模拟协议的两大支柱——"测试任务的成功示范唾手可得"和"额外步数免费"——在物理世界都不存在。于是作者设计了真实世界变体：**zero-shot**（无示范、无知识包，只有人类撰写的结构化上下文如工具说明、关节限位、安全约束）、**wall-clock 预算**（通常 60 分钟，因为真实世界里时间本身就是安全、硬件损耗和人力的成本），共部署 8 个平台、5 类形态。

| 平台 | 形态 | 任务与结果（成功/尝试） |
|---|---|---|
| Franka 3 + Robotiq 2F-85 | 单臂夹爪 | 方块堆叠 6/6；折布 2/4；插插头 0/3 |
| Franka Panda | 单臂夹爪 | 胶带卷堆叠 3/3；折毛巾 2/2、折布 1/2；插插头 0/5 |
| AgileX PiPER + Pika | 单臂夹爪 | 容器套叠 3/3；折衣 3/3；插插头 0/3 |
| AgileX Piper 双臂 | 双臂夹爪 | 12 个桌面任务 14/14 全部成功 |
| Tianji M6S + Wuji 灵巧手 | 双臂灵巧手 | 玩具抓取 3/3（人写脚本）；瓶子 1/3；模型自写抓取代码 0/3 |
| Galaxea R1 Pro | 轮式移动操作 | 找洗衣机按按钮 2/2；桌面任务 9/9；收花 0/2（躯干过热终止） |

| Unitree G1 + Wuji 手 | 人形（29 DoF） | 桌面抓放 2/3；转身-走近-停下 3/3 |

> 图解：zero-shot 真实世界控制，从简单到复杂形态，按时间顺序取自发布视频，角标给出成功/尝试数。(c) 接收碗被碰移位后 GPT-6-Astra 重新规划；(e) Tianji M6S 的 Wuji 灵巧手在人写抓取脚本下完成抓取。

三个核心发现：

**发现 1：一个模型驱动所有形态，但成败取决于任务性质。**刚性抓取-放置在真机上与模拟表现一致（17/18），双臂进一步扩展了 zero-shot 能力边界；但可变形物体、精密接触（插插头三个平台合计 0/11）和长程移动任务仍然明显更难。

**发现 2：能做什么取决于能看见什么——主动视觉。**插花任务里，夹爪从上方竖直握茎，随动的腕部相机天然看不到花瓶口。单臂 Franka 3 上任务失败；双臂 Piper 上，GPT-6-Astra 主动把空闲手臂的腕部相机移到能看到瓶口的位置，再完成插入。**视角本身成了动作空间的一部分**。这个行为在遥操作示范里几乎不存在（人类操作员用自己的眼睛看场景），所以模仿学习策略无从学起——这是 zero-shot agent 的独有优势。

![主动视觉](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/arxiv/Has-GPT-6-Astra-Achieved-Embodied-Intelligence/blog_images/rw_active_vision.png)

> 图解：插花任务的主视角与腕部视角对比。(a) 单臂 Franka 3：腕部相机看不到瓶口，插入失败；(b) 双臂 Piper：持花臂的腕部视角只有花茎，GPT-6-Astra 移动自由臂直到其腕部相机对准瓶口（方框帧：无花瓶 → 接近 → 瓶口入镜），插入成功。

**发现 3：慢速 System 2 可以直接驾驭高频 System 0 控制器。**在真实 Unitree G1 上，GPT-6-Astra 不碰腿部关节，只通过厂商速度接口（IMU 转向、0.15 m/s 定时行走、停止）完成"转身、走到桌前、距桌约 10 cm 停下"（3/3），同时用 14 个手臂关节目标和二元手开合完成桌面抓放（2/3）。行走中它会根据新图像把前进指令从 0.8 s 逐步缩到 0.15 s——出于"不许碰桌子"的约束而自我保守化。这证明的是慢速反馈监督下的可行性，而非实时视觉伺服。

真实世界还带来了模拟里没有的硬约束：**安全**（超出控制器限制的接触触发保护性停止，直接终结试验，且模型无法从硬件故障中恢复）；**机械极限**（Wuji 灵巧手手指关节在负载下停转，Galaxea 躯干过热终止长任务）；**实时性**（G1 上约 90% 的运行时间花在"想"上，单次操作试验超过一小时，中位 API 延迟 24.84 秒）。模拟里"用步数换成功率"的交易，在真机上做不起。同样，ICL 依赖的示范数据在真实部署中常常昂贵或根本不存在——人类撰写的上下文管用（灵巧手配人写脚本 3/3 vs 模型自写代码 0/3），但本质上仍是专家 prompt engineering，中间形态（跨形态示范、模拟自生成示范、机器人自身部署历史、跨机器人共享知识包）是一片未被系统探索的广阔设计空间。

## 八、走向下一代具身基准：世界不为 agent 暂停

前面所有证据都指向一个判断：现有基准很大程度上在测量"agent 利用基准所提供资源的能力"，而不是部署能力。提高难度的老路解决不了这个问题。作者借鉴语言 agent 评测（SWE-bench、OSWorld 等"以结果论英雄"的协议）提出三条原则，并搭了一个家庭场景原型来验证。

### 8.1 三条设计原则

1. **任务源自人类需求，以人的方式陈述**。现有基准的任务都是"机器人能被示范成功"的任务；部署中的机器人必须做人需要的事，不管此前有没有机器人做过。而且任务陈述应以**结果的效用**而非固定目标状态来评判——"做早餐"可以是烤面包（0.5 分）、鸡蛋吐司（0.8 分）或全套（1.0 分），且价值随时间衰减（住户 15 分钟后出门）。真实需求还附带没人明说的义务（Duty）：没看管的炉灶、没关的水龙头、agent 自己打开没关的柜门——这些与显性请求（Intent）放在同一次部署中考核。
2. **测试时获取经验，而非提供示范**。不提供任何领域内训练 episode 或场景特定示范；agent 必须通过自己的探索把通用先验落地到陌生的家和陌生的身体——测绘布局、试探 affordance、摸清怪异的家电。判分的谓词定义在对 agent 保密的物理量上（如"中心温度 ≥ 70°C 才算熟"），探索与动作一样消耗世界时间、产生副作用。
3. **世界持续运转，不为推理暂停**。模拟器在模型思考时暂停，等于把推理时间从成绩里抹掉了。新基准中，从观测到下一条指令之间的时间——无论花在推理、工具还是通信上——世界都按上一条指令继续演化，就像物理机器人一样。判分器在世界时钟上审视**整条轨迹**（包括 agent 宣布完成后的一段时间），义务被表达为带期限的轨迹约束（如"冰箱门打开后 1 分钟内必须关上"），思考时间由此成为成绩的一部分。

### 8.2 家庭原型：当基准什么都不给，GPT-6-Astra 暴露了什么

团队在 NVIDIA Isaac Sim 中搭建了一套可交互的一居室公寓：公开资产 + 户型图，coding agent 在人工审核下按真实尺度摆放物品，所有部件绑定物理——铰接、接触、基于位置的流体与布料、家电的加热与烹饪过程，强调**因果保真**（agent 决策所依赖的一切，从物体质量摩擦到热量从炉头到锅到食物，都要有正确的因果关系）。

![家庭环境构建流程](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/arxiv/Has-GPT-6-Astra-Achieved-Embodied-Intelligence/blog_images/ele_pipeline.png)

> 图解：公开资产（1）与户型图（2）组成可交互的家；coding agent 在人工审核下按真实尺度摆放日常物品（3）；每个部件绑定物理（4）；任务只陈述需求——"做早餐"意味着 agent 要自己弄明白冰箱、空气炸锅和烤面包机（5）；agent 只能通过机器人机载相机观察，其思考会推进世界时间（6）。

在 zero-shot、接触式抓取、无示范的条件下，GPT-6-Astra 暴露出三类在饱和基准上根本看不见的失败：

![家庭场景失败案例](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/arxiv/Has-GPT-6-Astra-Achieved-Embodied-Intelligence/blog_images/household-failures-v5.png)

> 图解：(a) 整理书桌时碰落桌上物品、手肘推歪显示器；(b) 开冰箱放牛奶后转身去搬水果，冰箱门从世界时间 300 s 开到 765 s；(c) 一手拉着冰箱门，站位却让另一只手够不到培根，松手去够门又关上了；(d) 不会关不熟悉的水龙头，水槽溢水到地板；(e) 决定"鸡蛋凝固就关火"的决策花了 8 秒世界时间，等火关掉已是鸡蛋凝固后约 90 秒，蛋糊了。紫色轮廓标注相关物体，时间戳为已流逝的世界时间。

- **注意力只在手上的物体，丢了整个家**：冰箱最终是关上的、书最终是放好的——只看终态的判分器会漏掉过程中的一切狼藉。这正是判分必须在整条轨迹上进行的原因。
- **没有示范就摸不清陌生机构的门道和自己的站位**：拉开门却不知道身体该站哪、对着该旋转的水龙头一直推。在有示范可蒸馏的基准上，这个弱点完全不显现。
- **基于过时观测做决策**：模型推理的方式仿佛世界会为它等待——在旧基准里世界确实等，在真实部署里不等。

这些案例虽少且是定性观察，但指向一致：在既有基准上，"决定做什么"的能力已经足够；而在只提需求、不给示范、不停摆的家里，还必须"把决定落成动作"——这正是当前的短板所在。

### 8.3 开放性挑战

作者也坦承这类基准落地的四个难题：**判分证据**（物理事实难以自动判定，VLM 成功检测器在接触丰富的装配任务上平衡准确率最高仅 60%，且会被 agent 自己的推理文本误导）；**模拟保真度**（判分器读的是模拟器状态，建模错误与 agent 行为无法区分，而长程家务的 sim-to-real 预测性尚未被验证）；**不停摆世界的成本**（推理期间所有物理过程都要模拟，成绩会受延迟、硬件和服务负载影响）；**评测成本**（一次部署长达一小时以上，重复试验昂贵）。

## 九、总结

- **能力上限**：在"ICL 知识包 + 10 倍步数预算"的统一协议下，GPT-6-Astra 在 12 个基准上大幅超越 SOTA，LIBERO-Long++ 达 100%，多个基准接近饱和。
- **两大杠杆**：ICL 把训练集示范蒸馏成可复用知识包（SIMPLE 标准预算 +20 个百分点），扩展预算让涌现的失败恢复能力兑现为成功率（RoboDojo 约翻三倍）；但前者难迁移、后者极昂贵。
- **残余短板**：物理成功验证、不可逆失败恢复、长程进度保持是三类系统性失败；token 与时间成本距离实时部署相差数个量级。
- **Harness 是另一半战场**：闭环 System 1–System 2 协作、语义对齐的末端执行器指令、自适应动作分块、反馈子代理与历史压缩是有效设计；堆组件数量无效。
- **真机落差**：zero-shot 下刚性抓取可靠、主动视觉令人惊艳、System 2 可驾驭 System 0 控制器，但精密接触、可变形物体、长程移动和安全/过热/实时约束仍是硬墙。
- **下一代基准**：任务从人类需求出发、不给示范、世界不停摆——家庭原型证明这样的评测能暴露出饱和基准完全看不见的能力缺口。

一句话展望：GPT-6-Astra 已经跨过了"具身能力"的门槛，剩下的关键命题是如何把基准上的成功翻译成可靠、高效、可规模化的真实世界部署——而评测本身的设计，将决定这个领域接下来往哪走。
