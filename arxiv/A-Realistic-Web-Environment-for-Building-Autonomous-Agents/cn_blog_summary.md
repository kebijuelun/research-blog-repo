# WebArena：用真实自托管网站检验自主智能体

WebArena 要解决的是：智能体能否在真实网页中长程探索并真正完成任务，而不只是模仿标准点击轨迹；在 812 个任务上，最佳 GPT-4 智能体端到端成功率仅 **14.41%**，远低于人类的 **78.24%**。

## 核心创新：真实网站、可复现环境、结果验证

- **功能完整的自托管网站**：环境包含电商、社交论坛、GitLab 协作开发和 CMS 四类平台，并配备地图、计算器、Scratchpad、离线 Wikipedia 与网站手册，支持跨站、多标签页操作。
- **真实性与可复现性兼得**：网站采用真实开源应用和现实数据，通过独立 Docker 镜像交付，可重置到确定初始状态，避免线上改版、验证码和内容变化干扰比较。
- **评价功能正确性**：不要求复现参考动作，而是检查最终答案、URL、数据库或页面状态。例如更新 README 后，验证器直接检查指定仓库的实际内容。

## 任务与交互设计

基准由 **241 个任务模板**实例化为 **812 个高层意图**，平均每模板 3.3 个例子，覆盖信息检索、站点导航、内容与配置操作，也包含应回答 `N/A` 的不可完成任务。典型任务需要先在 Wikipedia 检索博物馆，再用地图规划路线，最后修改 GitLab 仓库，串联信息检索、工具使用、推理和内容修改。

智能体可通过截图、HTML DOM Tree 或 Accessibility Tree 观察网页；基线默认使用更紧凑的 Accessibility Tree。动作涵盖点击、输入、滚动、标签页管理和 URL 导航，元素可用坐标或唯一 ID 定位，后者将定位转化为 $n$ 选一的分类问题。

## 程序化验证如何工作

- 文本答案采用 `exact_match`、`must_include` 和基于 `gpt-4-0613` 的 `fuzzy_match`，允许合理的格式与语义表达差异。
- 页面和内容操作先用数据库查询、API 或 JavaScript 选择器定位关键状态，再检查目标属性与关键词。
- 对语义评价器的人工检查中，40 个例子有 39 个与人类判断一致；两个 GPT-4 版本在各 900 个日期、时长格式测试上均达 100% 准确率，但这不代表所有开放式语义评价都已充分验证。

## 实验揭示的关键瓶颈

- **推理有帮助但远远不够**：启用 UA hint 时，CoT 使 GPT-3.5 成功率从 6.41% 升至 8.75%，最佳 GPT-4 仍只有 14.41%。
- **探索与拒绝存在权衡**：UA hint 让 GPT-4 在不可完成任务上达到 77.78%，却把 **54.9% 的可完成任务**误判为不可完成；关闭提示后整体成功率升至 14.41%，不可完成识别率降至 44.44%。
- **成功难以稳定复用**：在至少成功一次的 61 个模板中，GPT-4 仅 4 个达到 100% 成功率，GPT-3.5 一个也没有。
- 主要失败来自过早停止、观察偏置、忽略页面细节与历史状态。后续系统需要更强的分层规划、状态跟踪、搜索回溯、失败恢复、自我纠正和记忆复用，而非只提升单步动作预测。

WebArena 因而不只是排行榜：它把评测重点推进到“能否可靠完成真实任务”，也为研究人机协作、阅读文档学习及跨任务策略复用提供了可复现基础。
