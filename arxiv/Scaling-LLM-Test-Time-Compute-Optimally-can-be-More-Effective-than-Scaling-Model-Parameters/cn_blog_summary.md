# Compute-Optimal Scaling：按难度分配算力，4倍提效

给 LLM 更多推理时间，不该只是机械地多采样，而应按题目难度和预算选择搜索或修改策略，减少对扩大模型参数的依赖。在 MATH 上，这套 compute-optimal scaling 相对 Best-of-N 最高实现约 **4 倍测试时算力效率提升**；FLOPs 对齐时，小模型增加推理计算还能在部分题目上胜过约 **14 倍参数**的大模型。

## 核心方法：难度决定算力怎么花

作者将测试时计算拆成两个可组合部件：

- **Proposal Distribution（候选分布）**：通过并行采样或顺序修改产生答案，决定探索新解法还是修正已有思路。
- **Verifier（验证器）**：用奖励模型筛选答案，或由过程奖励模型（PRM）评价中间步骤，引导 Best-of-N、Beam Search 和 Lookahead Search。

关键不是寻找永远最强的算法，而是给定题目与预算，选择最合适的配置。作者对每题采样 **2048 个答案**，按基础模型 pass@1 将题目分成五个难度区间，再按难度和预算选策略，并用两折交叉验证避免选策与评估混用数据。没有标准答案时，可用 PRM 最终答案分数的均值预测难度，主要规律仍然成立。

## 两条路线：搜索与修改各有边界

**PRM 搜索。** 作者用 Monte Carlo rollout 自动生成逐步软标签，避免人工逐步标注。完整答案评分时，只取最后一步的 PRM 分数整体优于取最小值或连乘；PRM 也优于 ORM，且样本越多优势越明显。

低预算下 Beam Search 优于 Best-of-N，但预算增大后可能反超为劣，Lookahead 通常更差：更强的搜索会放大验证器偏差，诱发重复步骤或过短解答。按难度调节搜索强度后，代表性结果可用 **16 次生成接近或超过基线 64 次生成**；容易题应少优化，中等及较难题更受益，最难题仍受基础能力限制。

**Revision Model。** 模型把此前错误答案放入上下文，学习针对性修改，而非重新生成。顺序修改整体略优于并行采样，但约 **38% 的正确答案会在下一步被改错**，因此必须用验证器或多数投票保留整条轨迹中的最佳结果。

容易题更适合顺序修改，较难题需要保留并行探索。按难度分配两者配比后，**64 次生成可超过 256 次 Best-of-N**，即约 4 倍效率提升。专为修改模型输出训练的 ORM 也优于直接复用基础模型的 PRM，说明验证器必须匹配答案分布。

## 测试时计算不能无条件替代预训练

是否值得用小模型多推理，取决于题目难度及推理 token 与预训练 token 之比 $R$：容易、中等题目及低推理负载下，测试时计算更可能划算；最难题和高推理负载下，扩大预训练更可靠。论文只比较“扩大参数、固定训练数据”的扩展方式，并未覆盖同步扩展数据与参数的方案。

需注意，难度估计的 **2048 次采样成本未计入最终算力比较**，实验也集中于 MATH 和 PaLM 2-S*。因此，这项工作的核心价值是证明自适应分配的收益上限，而非已经消除全部额外开销的部署方案。
