# StagedSpec：树状草稿让解码提速 3.16 倍

本地小批量 LLM 推理常被困在显存带宽上：每生成一个 Token 都要重读整套权重，拖慢低延迟、个性化的端侧应用。Staged Speculative Decoding 让小模型先猜，把单条草稿扩展成树，再递归给小模型配备更便宜的草稿器。在 762M GPT-2-Large、RTX 4090 和 HumanEval 上，它将确定性解码从 150 提升至 **475 tokens/s，加速 3.16 倍**；Top-k 采样也实现 **1.98 倍加速**，且不改变输出质量与采样分布。

## 瓶颈不在算力，而在权重搬运

自回归生成包括并行处理 Prompt 的 Prefill，以及逐 Token 串行生成的 Decode，后者才是主要瓶颈。Batch Size 为 1 的 16-bit 解码算术强度约为 1；GPT-2-Large 每次推理约需 1.4 GFLOP，但参考 PyTorch 实现的计算利用率仅 **0.13%**，GPU 大部分时间在等数据。

普通投机解码让 Draft Model 连续预测多个 Token，再由 Oracle Model 批量验证，用额外计算换取更少的大模型串行调用。然而，一条草稿链越长，整体猜中的概率越低，尾部计算容易白费。

## 两项改进：草稿成树，模型分级

- **树状投机批次**：在关键位置保留多个候选分支，不再把预算押在一条长链上。这样能提高每批预期接受的 Token 数，也改善了较大 Batch、较低 Draft/Oracle 对齐度下的扩展性。Draft 只需计算内部节点，同层分支还能并行，构造树的串行批次数主要取决于树深。
- **配套的 Attention 机制**：按树深设置位置编码，以 Causal Mask 保证节点只能读取祖先；本批 KV Cache 暂存，采样确定路径后，仅追加被接受路径的切片。
- **分阶段投机**：给 Draft 再配一个更便宜的 Draft²。Draft² 为 Draft 提供候选，Draft 加速构造候选树，Oracle 最终验证所有输出 Token。它不是三个模型各写一段，而是逐级降低串行解码成本。

笔者认为，其关键不是“猜得更长”，而是“猜错后仍有分支可用”，并把可预测工作尽量交给便宜、并行的层级。

## 实验结果与适用边界

实验采用 762M Oracle、40M Draft 和 Katz Backoff Trigram Draft²，评测 HumanEval 的 164 个 Prompt：

| 解码方式 | Baseline | 标准投机解码 | Staged Spec. | 相对 Baseline | 相对带宽消耗 |
|---|---:|---:|---:|---:|---:|
| 确定性 | 150 | 350 | **475 tokens/s** | **3.16×** | **0.23** |
| Top-k（$k=50$、$T=1$） | 150 | 219 | **298 tokens/s** | **1.98×** | **0.35** |

两种设置下，Staged Spec. 相比标准投机解码都快 **1.36 倍**。确定性解码的带宽消耗减少约 **77%**，说明树状候选确实摊薄了权重读取成本。不过，真实 Prompt 的加速可从约 **2 倍**到最高 **10 倍**：空白、缩进等低熵内容易由小模型处理，关键 Token 更依赖 Oracle。当前实现还有约 **35% 的 Python 基础设施开销**。

## 总结

- 小批量解码的核心瓶颈是显存带宽，而非峰值算力。
- 树状批次提高候选覆盖率，分阶段投机降低草稿生成成本。
- Oracle 保留最终验证，因此提速不牺牲质量控制。
- 收益随内容熵显著变化；更强底层草稿器、高效实现和更大模型是后续方向。
