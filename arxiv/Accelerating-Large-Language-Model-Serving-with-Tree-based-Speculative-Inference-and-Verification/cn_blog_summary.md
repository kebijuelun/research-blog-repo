# SpecInfer：树状投机推理加速 LLM 服务（精华版）

LLM 生成每个 Token 都要完整跑一遍大模型，推理被显存带宽和串行依赖卡死——ASPLOS 2024 的 SpecInfer 把投机解码从"猜一条序列"升级为"猜一棵树"，让大模型一次前向并行验证整棵候选 Token 树，且输出分布严格等价于原模型。最终：分布式推理比 vLLM、TGI、FasterTransformer 快 **1.5-2.8 倍**，Offloading 推理比 FlexGen 快 **2.6-3.5 倍**，生成结果逐 Token 不差。

## 为什么慢，以及为什么猜序列不够

- 增量解码每步只产出一个 Token，却要把 LLM 全部参数从显存读一遍，GPU 算力大量闲置。
- 序列级投机推理用小模型（SSM）先猜一串再验证，但猜测成功率随长度**指数衰减**，能力差距天然存在。
- SpecInfer 的视角转换：不是"让大模型更快"，而是"让大模型每次被调用时产出更多"。

## 核心方法三件事

**1. 猜成一棵树，而不是一条链。** 树上每个节点唯一对应一条候选序列，共享前缀只存一份。建树有两条路：

- **扩展式**：SSM 与 LLM 不一致时，LLM 的选择通常藏在 SSM 的 top-k 里——随机采样下 top-1 命中率仅 52-57%，top-5 直接到 96-97%。用静态扩展配置控制分叉，避免指数爆炸。
- **合并式**：Collective Boost-Tuning 无监督微调多个各有所长的 SSM（类似 Boosting），再把各自的树按公共前缀合并。多 SSM 放不同 GPU 并行，不增加投机延迟；SSM 比 LLM 小 100-1000 倍，显存开销不到 1%。

**2. Tree Attention + 树并行解码。** 对整棵树做一次前向，等价于逐序列解码：

- DFS 序遍历、所有分支共享一份 KV Cache，保持"祖先 KV 就绪"不变式；
- 拓扑感知因果掩码：整树节点放进同一个 kernel，对不在同一路径上的 Token 对置 -∞，结果与逐序列计算完全等价，同时消掉大量 kernel 启动开销。

**3. 验证保证无损。** 贪心验证逐节点比对，命中则收下、失配则以 LLM 输出收尾；随机采样用多步投机采样（MSS）：以 $\min(1, P_{\text{LLM}}/P_{\text{SSM}})$ 概率接受分支，拒绝后用残差分布归一化继续。定理证明采样分布与 LLM 严格一致，且拒绝率不高于朴素采样（树退化为单链时 MSS 即此前的序列级算法）。

## 实验结论

- **分布式推理**（A10 集群，LLaMA-7B/65B、OPT-13B/30B）：单机多卡快 1.5-2.5 倍，多机快 2.4-2.8 倍；比序列级投机再快 1.2-1.5 倍。
- **Offloading**（单卡 24GB 跑 OPT-30B）：比 FlexGen 快 2.6-3.5 倍。
- 树宽 5 时每步平均验证 Token 数从 2.18-2.95 提升到最高 3.91（贪心）；Batch 越大空闲算力越少、加速比越小——SpecInfer 最适合低延迟场景。
- 消融：树并行解码大 Batch 下比拆序列解码快最高 1.8 倍；MSS 比朴素采样每步多验证约 1.27 倍 Token。

## 一句话总结

SpecInfer 把 LLM 从"逐 Token 解码器"改造成"Token 树验证器"，靠更宽的候选覆盖、整树并行验证和严格无损的采样证明，把闲置的 GPU 算力兑换成了实打实的端到端延迟收益——今天主流框架中的树状投机解码正是沿着这条路走下来的。代码已开源在 FlexFlow 仓库。
