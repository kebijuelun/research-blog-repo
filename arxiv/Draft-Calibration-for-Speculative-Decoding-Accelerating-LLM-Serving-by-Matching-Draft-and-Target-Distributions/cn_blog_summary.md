# Draft Calibration：校准草稿分布，吞吐提升22.08%

投机解码的瓶颈不只是草稿模型能否猜中下一个 token，更是其完整概率分布与目标模型有多接近；这篇工作用几乎零额外计算的训练后校准，在总并发 16–128 的在线服务中，将平均接受长度提升 **8.82%–10.89%**，输出吞吐提升 **5.13%–22.08%**。

## 核心发现：猜对 top-1，不代表分布对齐

- 对目标分布 $p$ 与草稿分布 $q$，单个草稿 token 的期望接受率为 $\sum_x\min(p(x),q(x))=1-\frac12\lVert p-q\rVert_1$。因此，即使最高概率候选相同，草稿模型给它分配的概率过低，仍会拉低接受率。
- 作者检查 EAGLE-3、DFlash、DSpark 的九组模型组合，并用数学、代码、聊天领域八个基准的 4,155 条 prompt 评测。草稿与目标的 top-1 一致率大致都在 70% 以上，top-16 候选集合重合度仍超过 40%，说明候选排序总体已学会。
- 但在 top-1 一致的位置，草稿模型给出的概率普遍更低、分布熵更高：问题不是不知道选谁，而是比目标模型更“不自信”、分布偏平。

## 最实用的方法：独立调低草稿温度

- 将目标温度 $T_t$ 与草稿温度 $T_d$ 解耦，以 $q_{\mathrm{cal}}=\mathrm{softmax}(z/T_d)$ 锐化候选分布，不改变候选排序，也不修改模型权重或重新训练骨干。
- 只要在生成候选和拒绝采样时一致使用校准后的 $q$，最终输出仍服从目标分布，保留投机解码的无损性质。
- 各设置的最优点均落在 $T_d\in[0,0.8]$；其中 **$T_d\in[0.4,0.6]$ 在所有主要模型和任务上都有一致收益**，通常已接近最优。逐任务调温仅比跨任务共享温度多一点收益，说明一个全局旋钮就够实用。
- 在线实验先冻结三组模型的共享温度，再在 2,082 条 held-out 请求上跨三个随机种子测试。九种聚合条件的接受长度与吞吐全部提升，p50、p95 请求延迟分别下降约 **5.60%–12.43%** 和 **5.84%–16.11%**。

## 收益边界与更复杂方法的结果

- **温度不是越低越好。** DeepSeek 训练版草稿模型原本就更接近目标分布：EAGLE-3、DFlash、DSpark 的最佳接受长度增益分别只有 2.05%、0.10% 和 0%。校准收益取决于原始草稿的对齐程度。
- **更强参数化未必更好。** 逐 rank 调温的对角 Dirichlet Scaling 几乎没有超过标量温度，完整矩阵反而略差，说明全局温度已捕获主要可修复误差。
- **token 级自适应仍有空间，但尚未兑现。** 直接读取当前目标分布的 token oracle 明显更强；仅在 greedy 草稿与原分布采样之间切换，就能恢复完整温度搜索约 70%–76% 的 oracle 增益。然而，简单可学习校准头接近甚至略差于全局温度，且 oracle 只是诊断上界，不能当作可部署结果。
- 轨迹回放通过缓存 hidden states，在数分钟 GPU 时间内完成超过一百万次评估，适合低成本筛选趋势，但不能精确替代在线接受长度或吞吐。

这项工作的核心价值，是找到了一个几乎免费的部署旋钮；下一步则需把 token 自适应信号引入训练，并弄清不同训练方案造成分布差距的原因。
