# LoopSkim：多层校验让循环模型无损解码提速

循环语言模型以重复执行共享参数增强能力，却让每个 token 串行完成全部循环，解码延迟成为主要代价。LoopSkim 把原本就会经过的中间深度变成验证器，在精确算术下保持输出不变；H200、BF16、单请求主实验中，无需训练版本相对自回归解码平均提速 **7.66 倍（greedy）和 4.87 倍（$T=1$）**。

## 核心方法：多层校验，尽早纠错

- **多 token、双链草稿**：默认 n-gram 链从上下文复制候选，无需训练或额外前向传播；可选 16.8M 参数单层草稿头预测后续浅层状态。两条链竞争，保留通过入口校验的连续前缀更长者。
- **入口与中间校验**：入口只接纳最长一致前缀；草稿组继续前进时，各深度 readout 与后续 token 比较，在首个矛盾处立即替换，并截断该位置及之后的内容，避免错误直到完整深度才暴露。
- **完整深度提交**：浅层结果和草稿只影响调度，只有完整深度 readout 能提交 token。关键不是改变输出的 early exit，而是更早纠错。
- **无损采样**：固定每个位置、词表项的 Gumbel 噪声，Raven 初始状态也只由 seed、位置和隐藏维度决定，使完整深度仍等价于普通 top-$p$ 采样，同时提高深浅层校验一致性。共享噪声达到理论最大耦合值的 **99.4%–99.9%**。

## 关键结果

- 无训练版相对 LoopSpec 的加速比之比平均为 **1.73 倍**，加头后为 **1.99 倍**；统一引擎后仍分别快 **1.64–2.08 倍**和 1.85–2.35 倍。
- Greedy 下，入口后的替换有 **94%** 发生在完整深度前，完整深度只需替换 0.43% 的输出 token。去掉中间校验后仅保留 73%–92% 吞吐；Raven-Llama 采样去掉共享噪声后只剩 33.1%。
- Held-out 数据上，无头与有头版相对 LoopSpec 平均快 **1.69 倍和 1.90 倍**；优势还延伸到长输出、批量和 RTX 5090。
- FP32、关闭 TF32 的 3,300 条 prompt、845,772 个 token 上，LoopSkim + head 与作者 AR **逐 token 完全一致**。BF16 仍会受 kernel 与计算形状影响，实际输出不保证完全一致。

## 收益边界

LoopSkim 用更多并行计算换低延迟：总循环量为 AR 的 **4.74–7.74 倍**，并非免费减少计算。当前验证模型最高 3.5B，生产引擎集成仍待完成；批量、上下文长度和文本可重复性都会影响收益。
