# RoboRSI：让机器人在真实家庭中稳定、高效、可复用地"自我进化"

大模型写代码驱动机器人已能干活，但执行经验如何沉淀为可复用能力，而非每次失败后打散乱补丁？RoboRSI 用自顶向下技能层级树（TSR）给出答案：四个仿真基准全部最高成功率，比最强 baseline 高 2.7~11.0 个百分点；真机 104 轮、24 小时自进化，两个场景零人工干预清理 5+4 个物体。

## 方法：TSR + 四智能体闭环

现有 coding agent 机器人像没有记忆的新员工：失败经验越攒越多，却没挂回任务结构，补丁总打在"失败被观察到的地方"而非起源。RoboRSI 的解法：

- **技能层级**：任务族 → 原子任务（带后置条件）→ 基础技能 → 复合技能（稳定序列固化为参数化代码），技能可被多分支共享。
- **四 Agent 分工**：Manager 分解任务并审查发布，Planner 出计划，Engineer 执行，Reviewer 独立诊断。
- **TSR 机制**：沿调用路径验证后置条件，把失败归因到**最早出错节点**，修订只限其负责的子层级；发布前须过审查 + 功能测试 + 历史回放三重门——补丁打在起源处，治标变治本。

## 结果

- **真机**：场景重摆后技能代码与配置完全不动，全程零人工纠正；53 个修订触发中仅 4 个需要人类知识，且每条纠正都固化为可复用契约。
- **仿真**（5,974 episode，同 backbone 同预算）：LIBERO-PRO 上超 OpenETA 11.0 分；一天无人值守自迭代五轮，LIBERO 任务覆盖从 32 涨到 71，仅耗 7.0 小时。
- **失败分析**：baseline 约三分之二失败是"提前宣告完成"，RoboRSI 仅 10%~14%。
- **复用**：`grasp_object` 只在一个任务上修订，随后被其他任务 42 个成功 episode 自动调用。

## 消融

- 诊断与执行解耦：RoboTwin 解决任务数从 9/50 升到 36/50。
- TSR vs 平铺修订：同一失败下 TSR 改 50 行即过发布门，平铺重写改动更大却不能发布。
- 代码固化：成功率 +7.5 分，token、模型调用、时间分别降 29.4%、27.2%、17.0%。

核心主张：经验只有挂回任务结构才能复用——归因到负责的能力、有执行证据支持、验证后才许发布。
