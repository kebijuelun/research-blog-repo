# NarrowSpec：缩窄投机解码草稿，GB10最高提速1.44倍

NarrowSpec 打破了投机解码草稿默认继承目标模型隐藏宽度的设计，用更窄的草稿残差流降低迭代开销。在 880 条 SPEED-Bench 提示、batch 1、temperature 0 下，B200 端到端解码提速 **1.06–1.12 倍**，DGX Spark（GB10）提速 **1.13–1.44 倍**。

## 核心创新：宽度可以独立于草稿范式

- 解码延迟可写成 $\mathrm{TPOT}=T_{\mathrm{iter}}/\mathrm{AL}$：前者是草稿生成与目标验证的迭代耗时，后者是平均接受长度。NarrowSpec 不只追求“猜得准”，还直接压缩草稿计算。
- 将草稿隐藏宽度设为目标宽度的 **1/2 或 1/4**，目标特征输入和词表输出保持不变。QKV、O、MLP 投影、目标特征接入及词表投影随之缩小；Attention head 几何、MLP 中间维度和 KV cache 不变。
- 该方法不改变草稿算法，因此同时适用于并行的 DFlash 和自回归的 EAGLE-3，即使后者已经裁剪词表，仍能继续获益。

## 关键方法：从头训练，并折叠边界映射

窄草稿在相同数据预算下从头训练，而非剪枝全宽模型；遇到目标宽度张量时，用 Adapter 完成宽窄转换。EAGLE-3 每减半一次宽度就将学习率翻倍，并调整初始化范围，不能直接照搬全宽超参数。

部署时，DFlash 将 Output Adapter 与借用的目标 LM head 折叠为 $W_{\mathrm{fold}}=W_{\mathrm{lm}}W_{\mathrm{out}}$，服务时只运行窄词表头。折叠在代数上精确，但 BF16 下不保证逐位一致。EAGLE-3 则可把 Input Adapter 折进 embedding，省去 7 次运行时映射，但需权衡常驻显存；半宽默认折叠后，草稿净增权重反而达到全宽的 1.28–1.55 倍。

## 实验结论：半宽已够用，低带宽设备更适合继续缩窄

- **B200**：四个“草稿族—目标模型”组合全部加速。半宽最多只损失 **3.0%** 接受长度，其中两个组合没有下降；四分之一宽并非总是更快，最优宽度取决于接受率损失。
- **GB10**：四分之一宽在四个组合中全部最快。半宽、四分之一宽的草稿迭代分别提速 1.15–1.25 倍和 1.24–1.48 倍。低带宽设备上窄 kernel 仍能保持较高带宽利用率，因此收益被放大。
- **延迟拆解**：半宽和四分之一宽分别让草稿本身提速 **1.25–1.46 倍、1.43–1.75 倍**，目标验证耗时变化均不超过 1%，证明收益来自草稿而非验证变化。
- **鲁棒性**：temperature 1 下端到端提速相对 temperature 0 的变化不超过 0.03×；batch 扫至 512 时没有窄草稿慢于全宽，最高提速 1.21 倍；上下文从 8k 增至 32k，迭代加速变化不超过 1.6%。

## 实践边界

B200 可优先尝试半宽，GB10 更值得尝试四分之一宽，同时应重新调参并确认词表投影真正变窄。极窄模型并非普遍安全：四分之一宽 DFlash-Qwen 在 RAG 上损失 14.8% 接受长度，端到端仅 0.95×。此外，每个变体只有一次训练、一个 seed，比较的是相同数据预算而非收敛状态；目前也只覆盖两类草稿、两个目标模型和最长 32k 上下文。
