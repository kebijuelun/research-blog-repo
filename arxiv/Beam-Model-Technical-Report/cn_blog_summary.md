# Beam：双专家在线蒸馏，兼顾智能体效率与安全

Beam 要解决的是大模型接管代码仓库、终端和跨应用工作流时，长链路能力、推理成本与安全边界难以兼得的问题；它以每 Token 仅激活 23.4B 参数实现比许多同级模型低 3–4 倍的推理计算量，并在 Terminal-Bench v2.1 上取得 80.1 分。

## 核心方法：一套连续训练与治理系统

- **稳定而稀疏的底座**：Beam 是总参数 501.3B 的稀疏 MoE，每 Token 从 256 个专家中激活 8 个。局部/全局注意力按 5:1 交错，局部窗口为 512 Token；QKNorm、逐 Head 门控与深度缩放残差 DSRes 共同稳定深层训练，训练结束时专家负载仅为完美均衡的 1.04 倍。
- **数据质量优先于规模**：23.8T Token 预训练中，代码与 STEM 合计占 59.34%。通用过滤规则会误删数学、代码和 STEM 的 80%–88% Token，因此团队按领域分治，并用质量提升与删除量之比筛选规则。自研质量分类器带来 1.35 倍平均计算效率，质量感知上采样再提升约 10%。
- **两阶段 Midtraining**：先用 850B Token、32K 上下文强化逻辑、代码和 STEM，再用 100B Token 扩展至 512K，最终外推到 1M；第二阶段采用 50% 有机长文、15% 合成 QA/指令遵循和 35% Recall 数据，平衡长上下文收益与能力回退。
- **双专家与 MOPD**：智能体专家优化推理、编码和工具调用，对齐专家优化准确、安全、指令遵循与对话质量。合并时不是平均权重，而是让学生生成自己的轨迹，再由对应教师在实际访问的上下文上提供全词表分布监督；传输 Hidden State、分块计算 KL，将通信和临时 Logit 显存从 $O(NV)$ 分别降至 $O(Nd_T)$ 和 $O(CV)$。
- **可验证、全异步的 RL**：数百万任务最终筛至近 100 万个，经过可执行 Verifier、抗作弊 Judge 和去污染。生成与训练解耦，并以采样核归一化、Routing Replay 和 FP32 关键路径减少训练—推理错位；约 10.5K 张 GB300 运行 4 周，整个后训练产生超过 1 亿条 Rollout。

## 结果：效率突出，但并非全面第一

- **能力合并**：MOPD 学生整体恢复两位教师的能力，Terminal-Bench 从智能体教师的 77.7 提升至 80.1，SWE-Bench Pro v1 从 62.2 提升至 67.1；DeepSWE 等任务仍有差距。公开对比中，最新 GLM、Kimi 和 DeepSeek 在多项原始能力上领先，Beam 的核心优势是 Token 效率。
- **部署**：NVFP4 将 Checkpoint Shard 从 BF16 的 933.81 GiB 降至约 273.5 GiB，22 个 Benchmark 平均分仅下降 0.45；4 卡部署在固定长度测试、50 tok/s/user 下实现每 GPU 吞吐 6.0 倍提升。1.93B 的 DFlash 2 再带来 1.9–3.0 倍单请求解码加速。
- **安全**：ISE 中有害请求拒绝或转向率为 88.9%，无害请求遵从率为 81.5%；量化版本未出现明显安全退化。不过动态多轮施压下有害遵从仍达 14.5%，政策提示虽将两类间接注入 ASR 降至 0.3% 和 0.0%，也不等于对自适应攻击免疫。

Beam 的真正贡献是把数据验证、奖励完整性、训练—推理一致性、能力合并、部署和安全纳入同一套可扩展方法。其局限也很明确：部分对比混用不同 Harness 与评测口径，一些安全结论受小样本、Judge 和固定攻击限制，仍需真实部署和更开放工件的检验。
