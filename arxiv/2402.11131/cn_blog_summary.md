# Speculative Streaming：不要草稿模型的投机解码

大模型推理的头号瓶颈不是算力而是显存带宽，传统投机解码虽能加速却要额外训练并常驻一个草稿模型，系统复杂度倍增。Apple 这篇 ICML 2024 工作提出 **Speculative Streaming（投机流）**：把投机能力直接融进目标模型，一次前向同时完成验证与投机。结果硬核：**1.8–3.1 倍加速，质量不降反升，额外参数比 Medusa 少约 10000 倍**。

## 核心思路：单模型内的多流注意力

- 将模型顶部 $N_s$ 层的标准注意力（MHA）替换为**多流注意力（MSA）**：主流隐状态在中间层复制出 $\gamma$ 条"投机流"，第 $j$ 条流负责预测未来第 $j$ 个 token。
- 投机流之间通过注意力互相可见、且都能 attend 主流，**显式建模了草稿 token 间的依赖**——这是它比 Medusa 独立多头猜得更准、接受率更高的关键。
- 两个务实设计：投机流**不引入额外 KV Cache**，内存占用与单模型一致；从中间层初始化投机流，投机流只走最后 $N_s$ 层，砍掉约 $(N-N_s)/N$ 的 FLOPs。

## 两个关键机制

- **并行投机与验证**：每次前向同时验证上一轮的草稿树、并生成下一轮草稿。草稿呈 top-$k$ 树状结构，靠常量加性注意力掩码在单次前向中批量验证，接受最长匹配路径。
- **并行树剪枝**：树规模随 $k$ 指数膨胀会让推理退化为 compute-bound。解法是用 early-exit 技巧——中间层隐状态过一个秩仅 8 的低秩矩阵加原有输出头，估计转移概率、整棵剪掉低概率子树，几乎零参数开销。
- **训练目标**：联合优化下一 token 与 $\gamma$ 个未来 token 预测，LoRA 微调 5 个 epoch 即可，端到端训练天然保证投机与验证对齐。

## 实验结论

- **对比 Medusa**：在 SqlContext、DialogSum、E2E-NLG 三个任务、OPT/Phi/OpenLlama 多个模型上，9 个组合中加速比与 CR Ratio 绝大多数占优；Medusa 需 4 亿+ 额外参数，本文仅需约 4 万（差距约 4 个数量级）；质量持平甚至更优（如 OPT-1.3b 在 SqlContext 上 EM 从 84.98 升至 87.40）。
- **对比双模型 SD**：双模型虽目标调用略少，但每步要自回归跑 22–42 次草稿调用，SS 的草稿开销几乎为零，**延迟普遍降低 40–50%**。
- **理论边界**：代入典型参数（$\gamma=4$、目标/草稿延迟比 10）可得，双模型方案每步要多前进 40% 的 token 才能打平 SS——只有草稿模型"又小又准"时双模型才占优，而这在下游微调场景中很难满足。
- **消融**：树剪枝有效压住高 $k$ 区间的延迟；MSA 层数越多指标越好，实践甜点为顶部 2–8 层。

## 局限

需在下游任务上微调，无法即插即用；加速比受任务投机难度影响（摘要类约 1.9 倍，低于结构化任务的 2.4–3.1 倍）。
