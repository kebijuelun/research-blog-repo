# The Llama 3 Herd of Models：405B 开源旗舰全解读

2024 年 7 月，Meta 把一只 405B 参数的"巨兽"放进了开源社区。这篇 92 页的技术报告回答了一个当时悬而未决的问题： **开源模型能不能在旗舰规模上追上 GPT-4** ？答案是能——Llama 3 405B 用一套"数据、规模、简单性"三管齐下的朴素方法论，在 15.6T token 上预训练出一个稠密 Transformer，MMLU 达到 87.3，人类偏好评估与 GPT-4 (0125) 大致打平。这篇文章把报告中预训练、后训练、推理、安全、多模态的全部关键细节拆开讲透。

## 总览：一群模型，三个阶段

Llama 3 不是一个模型，而是一群（Herd）模型。家族成员如下表所示，本文所有结果均基于 2024 年 7 月发布的 Llama 3.1 版本：

| 模型 | 指令微调 | 多语言 | 长上下文 | 工具使用 | 发布时间 |
|---|---|---|---|---|---|
| Llama 3 8B / 70B | ✗ | ✗ | ✗ | ✗ | 2024 年 4 月 |
| Llama 3 8B / 70B Instruct | ✓ | ✗ | ✗ | ✗ | 2024 年 4 月 |
| Llama 3.1 8B / 70B / 405B | ✗ | ✓ | ✓ | ✗ | 2024 年 7 月 |
| Llama 3.1 8B / 70B / 405B Instruct | ✓ | ✓ | ✓ | ✓ | 2024 年 7 月 |

旗舰模型是一个 **405B 参数的稠密 Transformer** ，上下文窗口最长 **128K token** ，原生支持多语言、代码、推理和工具使用。它的训练消耗了 $3.8 \times 10^{25}$ FLOPs，几乎是最大版 Llama 2 的 50 倍。

![Llama 3 整体架构](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/arxiv/The-Llama-3-Herd-of-Models/assets/llama3_language_architecture.png)

> 图解：Llama 3 的训练主线。左侧是预训练阶段：海量多语言文本经过 tokenizer 变成离散 token，模型做 next-token prediction；右侧是后训练阶段：在预训练 checkpoint 上做多轮 SFT（监督微调）与 DPO（直接偏好优化），把"会说话的模型"打磨成"懂指令的助手"。

Meta 在论文里反复强调三个关键杠杆，这也是理解全文的钥匙：

- **数据** ：预训练语料从 Llama 2 的 1.8T token 扩展到约 15T token，且清洗流程更精细；
- **规模** ：405B 参数 + 15.6T token，按 scaling law 估算恰好是这笔算力预算下的近似计算最优规模；
- **管理复杂度** ：刻意不追花哨技术——不用 MoE（混合专家）而用标准稠密 Transformer 保训练稳定性，不用 PPO 而用 SFT + DPO 的简单后训练组合。笔者认为，这种"工程上的克制"是 Llama 3 最值得借鉴的哲学：在大规模训练里，可靠性本身就是性能。

语言模型之外，论文还用 **组合式（compositional）方法** 给 Llama 3 接上了图像、视频和语音能力：先分别训练视觉/语音编码器，再用 adapter（适配层）把它们"插"进冻结的语言模型。这样做的好处是各模态团队可以并行开发，且文本能力不受任何影响。这些多模态模型仍在开发中，尚未发布。

下面沿着训练 pipeline 的顺序，从预训练开始逐层拆解。

## 预训练：把 15.6T token 洗干净、喂进去

### 数据：清洗比规模更见功力

Llama 3 的预训练语料知识截止到 2023 年底，全部经过多轮清洗。Web 数据的处理流程堪称"教科书级"，值得逐条看：

**文本抽取** ：Meta 自研了 HTML 解析器，在去除导航栏等模板噪声的精确率与正文召回率之间做平衡，人工评测优于第三方解析器。对数学和代码页面做了专门处理，还会保留图片的 `alt` 属性文本——因为很多数学公式是以预渲染图片形式存在的，公式就在 `alt` 里。一个有趣的消融结论： **markdown 标记对网页为主的训练是有害的** ，因此全部移除。

**三级去重** ：

1. URL 级去重，同一 URL 只保留最新版本；
2. 文档级全局 MinHash 近重复去重；
3. 行级激进去重——每 3000 万文档的分桶中，出现超过 6 次的行直接删除。这会误删一些高频优质文本，但实证收益显著。

**启发式过滤** ：用 n-gram 重复覆盖率删日志和报错信息；用"脏词"计数过滤漏网的成人网站；用 token 分布的 KL 散度剔除离群文档。

**模型化质量过滤** ：让 Llama 2 chat 模型判断文档质量，再蒸馏出 DistilRoberta 打分器给每篇文档打分。代码和数学网页另有专用流水线：用 prompt tuning 定向识别含数学推导、STEM 推理、代码与自然语言交织的页面。多语言数据则先用 fasttext 分到 **176 种语言** ，各语言内部单独去重和过滤。

**数据配比** 由一个知识分类器（下采样艺术娱乐等过度代表的类别）加 scaling law 实验共同决定，最终配方为：

| 数据类别 | 占比 |
|---|---|
| 通用知识 | 约 50% |
| 数学与推理 | 约 25% |
| 代码 | 约 17% |
| 多语言 | 约 8% |

**退火数据（Annealing Data）** 是训练尾声的"精饲料"：混入少量高质量代码和数学数据、上采样高质量领域数据。消融显示，退火让 8B 模型的 GSM8k 提升 24.0%、MATH 提升 6.4%，但对 405B 提升可忽略——旗舰模型的上下文学习能力已经足够强，不需要"考前划重点"。Meta 还反向利用退火来评估新数据源的质量：把训到一半的 8B 模型在 40B token 上退火，新数据占 30% 权重，比对每个数据集单独跑 scaling law 高效得多。

### 架构：标准稠密 Transformer，只做四处改动

Llama 3 没有采用 MoE，而是坚持标准稠密 Transformer——理由很简单：最大化训练稳定性。相比 Llama 2 只有四处改动：

1. **GQA（分组查询注意力）** ：全部型号统一 8 个 KV 头，提升推理速度、缩小 KV cache；
2. **文档级注意力掩码** ：同一序列内不同文档之间不做 self-attention，对超长序列的持续预训练很重要；
3. **128K 词表 tokenizer** ：100K 来自 tiktoken 加 28K 非英语 token，英文压缩率从 3.17 字符/token 提升到 3.94 字符/token——同样算力下模型能"读"更多文本，且不损害英文分词；
4. **RoPE 基频提高到 500,000** ，更好支持长上下文。

三个型号的超参数一览：

| 超参数 | 8B | 70B | 405B |
|---|---|---|---|
| 层数 | 32 | 80 | **126** |
| 模型维度 $d_{model}$ | 4,096 | 8,192 | **16,384** |
| FFN 维度 | 14,336 | 28,672 | **53,248** |
| 注意力头数 | 32 | 64 | **128** |
| KV 头数 | 8 | 8 | 8 |
| 峰值学习率 | $3 \times 10^{-4}$ | $1.5 \times 10^{-4}$ | $8 \times 10^{-5}$ |
| 激活函数 | SwiGLU | SwiGLU | SwiGLU |
| 词表大小 | 128,000 | 128,000 | 128,000 |
| 位置编码 | RoPE | RoPE | RoPE（$\theta = 500{,}000$） |

### Scaling Law：两步法预测旗舰表现

405B 的规模不是拍脑袋定的，而是 scaling law 外推出来的。但 Meta 指出现有 scaling law 的两大痛点：只能预测 next-token loss 而非具体基准表现；且外推噪声大。他们的解法是 **两步法** ：

1. 先建立"计算最优模型在下游任务上的正确答案负对数似然"与训练 FLOPs 之间的 **线性关系** ；
2. 再建立该负对数似然与任务准确率之间的 **sigmoid 关系** （这一步用上了用更高算力训练的 Llama 2 家族模型）。

具体做法是在 $6 \times 10^{18}$ 到 $10^{22}$ FLOPs（约 4 个数量级）的计算预算下训练 40M 到 16B 的小模型，用二次多项式拟合 IsoFLOPs 曲线，抛物线最低点即该算力下的计算最优模型。假设算力 $C$ 与最优训练 token 数满足幂律：

$$
N^\star(C) = A C^\alpha
$$

拟合得到 $(\alpha, A) = (0.53, 0.29)$，外推到 $3.8 \times 10^{25}$ FLOPs，预测应在 **16.55T token** 上训练一个 **402B** 参数模型——最终取整为 405B。一个关键观察是：算力越大，IsoFLOPs 曲线在最低点附近越平坦，旗舰性能对"模型大小与 token 数"的权衡非常鲁棒，所以 402B 还是 405B 其实差别不大。

![Scaling law 两步预测](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/arxiv/The-Llama-3-Herd-of-Models/assets/scaling_laws_benchmark.png)

> 图解：在 ARC Challenge 上验证两步预测法。左图横轴为训练 FLOPs、纵轴为正确答案的归一化负对数似然，二者呈线性；右图横轴为该负对数似然、纵轴为 ARC-C 准确率，呈 sigmoid 关系。两步串联后，外推 4 个数量级仍能准确预测旗舰模型的基准表现（仅略微低估）。

### 基础设施：16K 张 H100 上的工程学

405B 的预训练最多动用了 **16K 张 H100 GPU** （80GB HBM3），跑在 Meta 生产集群上。这一节是超大规模训练工程的宝贵实录：

- **存储** ：基于 Tectonic 分布式文件系统，7,500 台 SSD 服务器提供 240 PB 容量、2 TB/s 持续吞吐。最大挑战是 checkpoint 写入的高突发性——每块 GPU 要瞬间写出 1MB~4GB 的模型状态；
- **网络** ：405B 用 RoCE（基于融合以太网的 RDMA），三层 Clos 拓扑，pod 内 3,072 GPU 全对分带宽无超额订阅，汇聚层 1:7 超额订阅；用 E-ECMP 把每对 GPU 间的 16 条流分散到不同路径解决"大象流"负载均衡；
- **并行化** ：TP（张量并行）+ CP（上下文并行）+ PP（流水线并行）+ DP（数据并行）的 **4D 并行** ，BF16 MFU（算力利用率）达 38%–43%；
- **数值稳定** ：反向梯度累加和 FSDP 的梯度规约全部用 FP32。

![4D 并行示意](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/arxiv/The-Llama-3-Herd-of-Models/assets/4D_parallelism.png)

> 图解：16 块 GPU 上的 4D 并行分组示例，分组顺序为 [TP, CP, PP, DP]，越内层的并行要求越高带宽（TP 限单机内），最外层 DP 可容忍跨多跳网络的延迟。每个 GPU 的位置用四维向量标识。

其中流水线并行有两个值得单独说的改进：一是调度上允许同一 stage 连续处理的 micro-batch 数 $N$ 灵活设置，在 DFS 与 BFS 之间找到通信/显存的最优点；二是 **首末 stage 各减一层 Transformer** 来平衡显存——首 stage 只剩 embedding，末 stage 只剩输出投影和 loss 计算。最终 8K 序列预训练完全不需要激活重计算。

可靠性数据也很震撼：54 天内共 **466 次任务中断** ，其中 419 次意外中断里约 78% 归因于硬件问题，GPU 类问题占 58.7%（GPU 故障 148 次、HBM3 显存问题 72 次）。但全期只有 3 次需要人工介入， **有效训练时间超过 90%** 。还有两个有趣细节：正午高温会通过 GPU 动态调频造成 1–2% 的昼夜吞吐量波动；数万 GPU 同时升降功耗会造成数据中心数十兆瓦级的瞬时功率波动，逼近电网极限。

### 训练配方：三阶段与渐进翻倍

405B 的预训练分三个阶段：

1. **初始预训练** ：AdamW 优化器，峰值学习率 $8 \times 10^{-5}$，线性 warmup 8,000 步，cosine 衰减，共 120 万步。batch size 和序列长渐进翻倍：初始 4M token / 4,096 序列长，252M token 后翻倍到 8M / 8,192，2.87T token 后再翻倍到 16M token。整个训练非常稳定，几乎没有 loss 尖峰；
2. **长上下文预训练** ：最后阶段才分 6 档把序列从 8K 渐进扩展到 128K（此前不做是因为注意力计算随序列长平方增长），每档必须满足"短上下文性能完全恢复 + 大海捞针任务完美通过"才晋级，共用约 800B token；
3. **退火** ：最后 40M token 上学习率线性降到 0，上采样极高质量数据，并对退火期间的 checkpoint 做 **Polyak 平均** 得到最终模型。

预训练把"读世界"的能力塞进了模型，但它还不会"听指挥"——接下来轮到后训练登场。

## 后训练：六轮迭代的自举飞轮

### 总流程：RM → 拒绝采样 → SFT → DPO

Llama 3 的后训练是一个六轮循环：每轮先在预训练 checkpoint 上用人标偏好数据训练奖励模型（RM），再用 RM 做拒绝采样（Rejection Sampling, RS）生成高质量回复，接着 SFT，最后 DPO。每一轮都基于最新模型收集新数据——模型变强、数据变强、模型再变强，形成自举飞轮。

![后训练流程](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/arxiv/The-Llama-3-Herd-of-Models/assets/posttraining_overview.png)

> 图解：Llama 3 后训练 pipeline。顶部是奖励模型分支（人工偏好标注训练 RM），中间是拒绝采样（同一 prompt 采样 K 个回复、RM 选最优），然后进入 SFT 与 DPO。整个循环迭代六轮。

相比 InstructGPT 那套 PPO 方案，Meta 刻意选择了更简单的 DPO——实验发现 DPO 在大模型上算力需求更低且效果更好，尤其在 IFEval 这类指令遵循基准上。

### 建模细节：四个不显眼但关键的改动

**聊天协议** ：为支持工具调用（一轮对话内可能要向 user、`ipython` 等不同目的地发多条消息），Llama 3 设计了多消息聊天协议，用 header token 标记消息来源与目的地，用终止 token 区分"消息结束但继续输出"与"轮到对方说话"。

**奖励模型** ：去掉了 Llama 2 loss 中的 margin 项（数据规模上来后收益递减）；标注员可在 chosen 回复基础上再编辑出更好的 "edited response"，形成 *edited > chosen > rejected* 的三级排序；训练时把 prompt 和多个回复拼成一行（回复随机打乱），消融显示这能提升效率且不损失精度。

**SFT** ：最大模型学习率 $10^{-5}$，训练 8.5K–9K 步，mask 掉 prompt token 的 loss。注意一个微妙事实：虽叫"监督"微调，但大量训练目标其实是模型自己生成的。

**DPO** 有两项关键算法修改，笔者认为这是全文最实操的经验之一：

1. **mask 格式化 token** ：header 和终止 token 在 chosen 与 rejected 回复中都出现，DPO 的对比式 loss 会要求模型同时提高和降低它们的概率，目标冲突会导致尾部重复、突然蹦出终止符等异常行为——所以把它们从 loss 中剔除；
2. **NLL 正则** ：对 chosen 序列加系数 0.2 的负对数似然项，防止 chosen 回复的 log 概率在对比训练中下降。

最后还有一招 **模型平均（model soup）** ：把不同阶段、不同超参得到的模型做权重平均，稳定优于单个最优模型。

### 数据：质量控制四件套

偏好数据按四级强度标注（significantly better / better / slightly better / marginally better），RM 训练用当时全部数据，DPO 只用最新批次（更贴合当前 policy 分布），两者都只保留"明显更好"级别的样本。拒绝采样时每个 prompt 从最新模型采 10–30 个输出，配合 PagedAttention 的动态 KV cache 分配和共享缓存页， **吞吐量提升超过 2 倍** 。

由于大部分 SFT 数据是模型生成的，清洗至关重要。除了规则清洗（治"过度道歉"、emoji 泛滥等毛病），Meta 还用了模型化剪枝四件套：

- **主题分类** ：微调 Llama 3 8B 做粗粒度 + 细粒度主题分桶；
- **质量打分** ：RM 分数 top 四分位 + Llama 自评双信号，两者分歧率很高， **取并集** 召回最好；
- **难度打分** ：用 Instag（意图标签越多越复杂）加 Llama 三分制难度评分；
- **语义去重** ：RoBERTa 聚类后按"质量分 × 难度分"排序，贪心保留与已选样本余弦相似度低于阈值的样本。

### 七大能力定制：针对性"补课"

通用配方之外，Meta 对七项能力做了专项增强，每个都有值得借鉴的招式。

**代码** ：先训练一个 **代码专家模型** ——从主预训练分支出来，在 1T token（85% 以上是代码）上继续预训练，最后几千步把上下文扩到 16K，用于生成高质量代码标注。合成数据共 270 万条，三条路线：

1. **执行反馈** ：让模型生成编程题并解答，然后用静态分析（parser + linter）和动态分析（自动生成单元测试并容器内执行）验证正确性，失败则把错误信息喂回模型迭代自我修正—— **约 20% 的解最初是错的，经自我修正后通过** 。这个设计的动机很扎心：405B 用自己生成的数据训练无益甚至有害，必须引入"执行"这个外部真理来源；
2. **语言翻译** ：把 Python/C++ 的数据翻译成 TypeScript/PHP 等小语种，MultiPL-E 上小语种显著提升；
3. **回译** ：给代码生成注释/文档，再让模型仅凭文档"回译"出代码，用与原代码的忠实度自评过滤。

![代码翻译示例](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/arxiv/The-Llama-3-Herd-of-Models/posttraining/assets/code_translation_example.png)

> 图解：合成数据之编程语言翻译。左侧为 Python 源码，右侧为 Llama 3 翻译后的 PHP 代码，经语法解析、编译、执行验证后进入 SFT 数据集。

![System prompt 提升代码质量](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/arxiv/The-Llama-3-Herd-of-Models/posttraining/assets/code_system_prompt_example.png)

> 图解：拒绝采样时用代码专用 system prompt 的效果对比。左：无 system prompt 的回复；右：有 system prompt 后，模型自动加了注释、变量名更有意义、还省了内存。

**多语言** ：训练一个在 90% 多语言 token 上继续预训练的 **多语言专家模型** 来收集非英语标注。SFT 数据来源为：人工标注 2.4%、其他 NLP 任务改写 44.2%、拒绝采样 18.8%、翻译的推理数据 34.6%。原则上避免机器翻译数据（防翻译腔和文化偏见），唯一例外是数学推理数据——数学语言简单，翻译质量问题少，MGSM 收益巨大。

**数学与推理** ：针对五大挑战逐一出招：缺 prompt 就建数学技能分类法定向征集；缺思维链就让模型生成多条解答按答案正确性过滤并自验证；中间步骤错误就训练 **逐步奖励模型** 过滤，难题用 MCTS（蒙特卡洛树搜索）生成推理轨迹；工具能力不足就交替输出文本推理和 Python 代码、以执行结果为反馈；训练-推理不一致就用错误生成做纠错数据。

**长上下文** ：只用短上下文 SFT 数据会显著回退长上下文能力，而人工标注长文档不现实，于是全靠合成：长文档切 8K chunk 生成 QA、层级摘要（先摘要各 chunk 再摘要的摘要）、以及删除代码仓库中被至少 5 个文件依赖的关键文件让模型补全。关键消融结论： **只需混入 0.1% 的合成长上下文数据** ，就能在长、短基准上同时最优；且 DPO 阶段只用短上下文数据不损害长上下文表现。

**工具使用** ：训练模型使用三个核心工具——Brave Search 搜索引擎、Python 解释器、Wolfram Alpha。模型能在多轮对话中先写计划、顺序调用、每次调用后推理。数据上分单步调用、多步调用（类 ReAct 的交错推理轨迹）、文件上传三类合成，再用消息级人工标注逐步复杂化。零样本函数调用数据从 The Stack 挖掘真实函数，产出 35.7 万条样本。

![多步工具调用](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/arxiv/The-Llama-3-Herd-of-Models/assets/llama-search-code.png)

> 图解：Llama 3 执行多步任务的轨迹示例：先规划，再交替调用搜索引擎与 Python 解释器，每次拿到工具输出后继续推理，最终合成答案。

**事实性** ：核心原则是后训练要让模型 **"know what it knows"（知道自己知道什么）** ，而不是注入新知识。具体用"知识探测"流程：从预训练数据抽片段 → 生成事实性问题 → 无上下文采样 10 条回答 → 以原文为参照打正确性和信息量分 → 对"一致有信息量但不正确"的问题生成拒答。偏好数据分三类：拒答优于错误回答、正确回答优于拒答（防过度拒答）、正确回答优于错误回答，比例约 4:4:10。

**可控性** ：通过人工设计各种 system prompt（控制回复长度、格式、语气、人设）收集偏好样本，让模型对下游应用"言听计从"。

## 推理优化：让 405B 跑得起

模型训完了，但 BF16 精度下 405B 连一台 8 卡 H100 服务器都塞不下。Meta 用了两招。

**流水线并行推理** ：机内用张量并行（NVLink 带宽高），跨机用流水线并行。一个关键洞察是： **推理没有反向传播，流水线气泡不再是问题** ，因此可以用微批（micro-batching）提高吞吐——相同局部 batch size 下微批并发执行，吞吐-延迟权衡更优。

**FP8 量化** ：对 FFN 层的大部分参数与激活（约占推理计算时间 50%）应用 FP8，自注意力层不量化。三项质量修复缺一不可：

1. **首尾 Transformer 层不量化** ；
2. 动态缩放因子 **钳制上界 1200** ——高困惑度 token（如日期）会产生超大激活值，导致 scale 过大、出现下溢、解码出错；
3. **行级量化** （对参数与激活矩阵按行算 scale），优于张量级。

评估方法上 Meta 有个重要观点：标准基准常显示 FP8 与 BF16 持平，但 **基准分数反映不出偶发的输出损坏** ，更可靠的做法是比较 10 万条响应在两种精度下的奖励模型分数分布。

![BF16 vs FP8 奖励分布](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/arxiv/The-Llama-3-Herd-of-Models/assets/bf16_vs_fp8_new.png)

> 图解：Llama 3 405B 在 BF16 与 FP8 下各生成 10 万条响应的奖励模型分数分布，两条曲线几乎重合，证明三件套修复后的 FP8 对输出质量的影响可以忽略。

效率上，FP8 相比双机 BF16 方案 **pre-fill 吞吐最高提升 50%** ，解码阶段的吞吐-延迟权衡也显著更好。FP8 的实现已开源。

![FP8 推理吞吐](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/arxiv/The-Llama-3-Herd-of-Models/assets/prefill_fp8.png)

> 图解：pre-fill 阶段吞吐-延迟权衡对比，FP8（405B 可单实例运行）相对各种流水线并行设置的 BF16 都有明显优势。

## 实验结果：开源模型追平 GPT-4

### 预训练模型：同级全面领先

预训练 Llama 3 在八大类基准上与同级开源模型对比，8B 几乎在所有类别超过 Mistral 7B 和 Gemma 7B，70B 大幅超过 Llama 2 70B 和 Mixtral 8x22B。抽几个 405B 的代表性数字：MMLU 85.2、GSM8K 89.0、ARC-C 96.1、TriviaQA 91.8、HumanEval 61.0，基本与 GPT-4 处在同一水位。

Meta 还做了两件评测方法论上很扎实的事。一是 **MMLU 鲁棒性研究** ：扰动 few-shot 标签结构、答案标签符号（换成 `$`、`&`、`#`、`@` 甚至稀有 token）、答案顺序、prompt 格式四个维度，发现模型对所有扰动都很鲁棒，405B 尤其稳健。二是 **污染分析** ：用 8-gram 重叠估计各基准被污染的比例与增益，坦承 PiQA、HellaSwag 等基准污染率不低（且增益可观），而 MATH、SQuAD 即便污染率高也几乎无增益——这种自我解剖的透明度值得点赞。

## 安全：从训练数据到系统护栏的全栈设计

Llama 3 的安全工作覆盖五个层次：预训练数据清洗与记忆化评估、安全微调、新能力（多语言/长上下文/工具）安全评测、网络与化生武器风险 uplift 评估、红队测试，外加系统级护栏。

**记忆化** ：用滚动哈希索引测量逐字记忆率，405B 在 50-gram 和 1000-gram 设置下分别为 1.13% 和 3.91%，与同尺寸 Llama 2 大致持平——规模变大并没有显著加剧记忆化。

**安全微调** 的核心方法论是一对指标的平衡： **违规率（VR）与误拒率（FRR）** 。永远拒答的模型最安全但毫无用处。关键发现包括：安全数据质量比数量更重要；对抗样本与边界样本（"本可以安全回答"的提示）要战略性配比，越难的风险领域用越高比例的边界样本； **8B 模型需要比 70B 更高比例的安全数据** 才能达到同等安全水平——规模本身就是一种安全能力。

![安全数据配比与模型规模](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/arxiv/The-Llama-3-Herd-of-Models/safety_evals/newplot_hailey.png)

> 图解：每个点是一种"安全 vs 有用性"数据配比下的模型表现。小模型需要更高比例的安全数据才能压低违规率；大模型更能区分对抗与边界语境，VR-FRR 平衡更优。

**多语言安全** 的结论很直接：英文安全知识不能直接迁移到其他语言，必须逐语言收集数据。 **长上下文安全** 针对 many-shot jailbreaking（用大量"上下文中的不安全示范"诱导越狱）做了专项缓解——在 SFT 中加入"上下文存在不安全示范时仍安全回应"的样本，即使 256-shot 攻击也能把违规率压到 10% 以下（基线为 31%），且对有用性几乎无损。

**网络与化生武器风险评估** 的结论让人松一口气：405B 对恶意代码解释器提示的遵从率为 10.4%；提示注入成功率 21.7%（比 GPT-4 Turbo 和 Gemini Pro 更易被注入，但优于 Mixtral）；作为自主攻击 agent 的实验中，侦察阶段表现尚可，但漏洞利用与后渗透尝试 **全部失败** 。62 名志愿者的两阶段网络攻击 uplift 研究和 6 小时的化生武器团队演练均显示： **使用 Llama 3 相比仅用互联网没有显著的能力提升** 。

**红队** 发现的有效攻击手法值得所有从业者警惕：多轮拒答抑制、假设性场景包装（有时只加 "hypothetically" 一个词）、人设角色扮演、免责声明式回应引导、逐步升级违规；多语言混用比单语言更易越狱；工具调用中存在"一次请求多个工具、其中一个违规则全部执行"的不安全工具链问题。

**系统级安全** 是 Meta 给出的工程解法，三个组件全部开源：

- **Llama Guard 3** ：基于 Llama 3 8B 微调的输入/输出安全分类器，覆盖 13 个危害类别加代码解释器滥用，全量部署时英文违规率降低 86%（代价是误拒率上升 102%，可按类别单独启用以精细权衡）；int8 量化版体积缩小超 40%、性能几乎无损；
- **Prompt Guard** ：基于 mDeBERTa-v3（86M 参数）的提示攻击过滤器，对直接越狱检出率 99.9%、间接提示注入检出率 71.4%；
- **Code Shield** ：基于静态分析的不安全代码检测器，覆盖 7 种编程语言。

![多语言安全对比](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/arxiv/The-Llama-3-Herd-of-Models/safety_evals/ml_grouped_bar_comparison.png)

> 图解：英文与多语言短上下文基准上的违规率（VR）与误拒率（FRR）分组柱状图，对比 Llama 3 405B（含/不含 Llama Guard）与三家匿名竞品。Llama 405B + Guard 在所有支持语言上至少与竞品系统一样安全。

## 多模态：组合式接入视觉与语音

### 视觉：冻结主干，外挂眼睛

视觉模块由三部分组成，语言模型主干全程冻结，这是组合式路线的精髓：

- **图像编码器** ：ViT-H/14（630M 参数），在 25 亿图文对上训练；关键设计是 **多层特征提取** ——除最后一层外还取第 4、8、16、24、31 层的特征（对比学习会丢掉细粒度定位信息），再加 8 个 gated self-attention 层，总计 850M 参数；
- **图像 adapter** ：Flamingo 风格的 cross-attention 层，每隔 4 个 self-attention 层插入一个，在约 60 亿图文对上预训练（405B 的 cross-attention 层参数高达约 100B）；退火阶段提高图像分辨率，退火数据约 5 亿张，包含视觉定位、截图解析、合成 caption、合成结构化图像（图表/表格/公式）等专项数据；
- **视频 adapter** ：均匀采样至多 64 帧，用 perceiver resampler 做时序聚合，另加视频 cross-attention 层。

训练工程上有三个异构性挑战的解法值得记录：流水线 stage 固定为"4 层 self-attention + 1 层 cross-attention"以平衡图文计算；图像 token 数（平均 2,308）远多于文本（192），引入序列并行均衡负载；图像梯度逐层放大导致数值不稳定，梯度累积改用 FP32。

后训练采用 SFT（配 model soup 权重平均）→ DPO（参考模型用 EMA 更新而非冻结，效果更好）→ 拒绝采样（补充思维链推理）→ **质量调优（QT）** ：在极小但极精的数据集上最后微调，显著提升人评且不伤基准。

评测结果（全部 zero-shot）：Llama 3-V 405B 在 MMMU 拿到 64.5、DocVQA 92.6、TextVQA 84.8， **所有基准上超过 GPT-4V** ，略逊于 Gemini 1.5 Pro 和 Claude 3.5 Sonnet，文档理解上尤其有竞争力。视频方面，70B 在 PerceptionTest 拿到 60.8、TVQA 87.9，与从头原生多模态训练的模型相当——尽管 3 分钟的视频只采样了约每秒 1/3 帧。

### 语音：embedding 直插 token 流

与视觉的 cross-attention 注入不同，语音模块把编码结果直接变成 token 表示拼进文本流，让语音直接享用语言模型的全部能力：

- **语音编码器** ：1B 参数的 Conformer（24 层），用 BEST-RQ 自监督算法在 1500 万小时多语言语音上预训练（对 mel 谱随机掩码、用码本量化重建）；
- **Adapter** ：约 100M 参数，卷积降采样 + rotary Transformer + 线性层，把语音表示映射到语言模型的 embedding 维度。训练时语言模型冻结。

支持 **34 种语言** 。一个精巧设计是：system prompt 只在目标侧带语言标识（如 `Repeat after me in {language}:`），源侧语音不带——这保住了 zero-shot 翻译方向的通用性，还能处理语码混合的语音。SFT 数据含 23 万小时人工转写（ASR）、9 万小时语音翻译（AST，双向 33 种语言）、以及 6 万小时合成的口语对话数据。

![语音接口架构](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/arxiv/The-Llama-3-Herd-of-Models/assets/llama-speech-6x.png)

> 图解：Llama 3 语音接口架构。输入侧，语音经编码器与 adapter 变为 token 表示喂入语言模型，通过 system prompt 切换 ASR（转写）、AST（翻译）、自由对话等模式；输出侧，流式 TTS 系统在模型解码的同时实时生成语音波形。

评测结果全面超过语音专用模型：FLEURS 34 语言平均 WER 8.2（70B），优于 Whisper v3 的 14.4；语音翻译 FLEURS 33→英 BLEU 33.7，优于 SeamlessM4T v2 的 28.6。定性上，模型没用过语码混合训练数据却能理解混合语言语音，且只训练过单轮对话却能连贯多轮对话。

**TTS（语音合成）** 走了一条很新奇的路线：不微调语言模型，而是把 **Llama 3 8B 第 16 层的 embedding** 作为上下文特征喂给传统的文本规范化（TN）和韵律建模（PM）模块，实现流式合成。消融很说明问题：TN 准确率上，无 embedding 加 3 token 右上下文只有 73.6%，无 embedding 加全双向上下文 88.0%，而 **有 Llama embedding 只需 3 token 右上下文就达 90.7%** ——大模型的上下文表示可以替代长前瞻窗口，这正是流式低延迟合成的关键。人评中 PM 对流式基线偏好率 60.0%。

## 总结与展望

- **三杠杆方法论** ：Llama 3 证明"高质量数据 + 大规模 + 控制复杂度"的朴素路线足以造出旗舰模型，花哨架构不是必需品；
- **开源追平闭源** ：405B 在基准上与 GPT-4 打平、人评与一线闭源模型互有胜负，开放权重模型首次站上旗舰水位；
- **工程实录价值极高** ：16K H100 集群的 4D 并行、43% MFU、466 次中断的故障解剖、FP8 三件套，都是超大规模训练的稀缺公开经验；
- **后训练的自举飞轮** ：六轮 RM/RS/SFT/DPO 迭代 + 执行反馈等合成数据管线，让模型自己生产自己的训练数据；
- **安全是全栈工程** ：从数据清洗、安全微调到 Llama Guard 3 系统护栏，VR 与 FRR 的跷跷板贯穿始终；
- **组合式多模态** ：冻结主干 + adapter 外挂的路线以极小代价获得有竞争力的图像/视频/语音能力。

局限也很清楚：开放域事实性仍落后 GPT-4o 约 10 个点，多模态模型尚未发布，GPQA 等高难推理上与 Claude 3.5 Sonnet 有明显差距。Meta 在结论中说，高质量基础模型的发展仍处于早期——而 Llama 3 把整条造模型的流水线摊开给所有人看，本身就是对下一代模型最大的助推。
