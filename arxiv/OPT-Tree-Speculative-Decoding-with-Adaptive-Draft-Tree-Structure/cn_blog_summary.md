# OPT-Tree：自适应草稿树让投机解码提速3.2倍

大模型自回归解码每步只生成一个 token，投机解码又常因固定草稿结构浪费节点预算；OPT-Tree 通过随输入动态调整树的深度与分支，让有限节点覆盖更可能被接受的续写。它在 MT-Bench 和 GSM8K 的所有测试组合中均取得最高平均接受长度（MAL），相对原始自回归解码最高提速约 **3.21 倍**。

## 核心创新：把“选什么树”变成在线优化

序列草稿会重复计算公共前缀，Binary Tree、EAGLE Tree 等固定树虽消除冗余，却不能按上下文分配预算。OPT-Tree 不额外训练树形预测器，而是复用草稿模型的概率信号，在每个解码步骤重新构树，也可与 EAGLE 等草稿方法组合。

## 关键方法：概率打分、贪心扩展、Top-n 裁剪

- **累积概率**：每个节点除 token 外，还记录从根到该节点各条件概率的乘积 $\hat p$；路径越深，$\hat p$ 越小。
- **优化目标**：以所有非根节点 $\hat p$ 之和估计期望接受长度，即 $E(A)=\sum_{(\hat y,\hat p)\in T}\hat p$，在节点预算 $n$ 下寻找分数最高的树。
- **构树流程**：从当前最后一个 token 初始化根节点，逐层选择高概率候选扩展，再保留 $\hat p$ 最大的 $n$ 个非根节点。父子概率的单调性保证这些节点形成含根的连通子树。
- **成本刹车**：当继续加深的分数增量不超过阈值 $\delta$ 时停止。作者建议结合草稿与目标模型单次推理时间之比 $\mu$，将 $\delta$ 控制在 $\mu$ 与 1 之间，避免接受长度增长却被 drafting 成本抵消。

目标模型随后借助 Tree Attention Mask 并行验证整棵树，接受与目标路径匹配的最长草稿前缀，并顺带生成下一个 token，在保持输出一致的同时一次推进多个 token。

## 实验结论：强草稿模型受益更明显

- GSM8K 上，LLaMA-2-70B + EAGLE 达到 **20.50 Tokens/s、3.21 倍加速**；MT-Bench 上同一组合为 3.05 倍。
- MT-Bench 上，LLaMA-2-70B + LLaMA-2-7B 的 MAL 从 EAGLE Tree 的 **4.97 提升至 7.74**；Vicuna-33B + Vicuna-7B 从 4.64 提升至 6.51。
- 约 8000 个解码步骤的统计支持 $E(A)$ 与实际接受长度正相关。强草稿模型配合超过 500 节点时，MAL 仍可增长至约 **10 个 token**，但 500 节点的高验证成本已无法带来实际加速。

## 总结

OPT-Tree 真正优化的是节点预算分配，而非单纯扩大草稿树。更长的接受片段不必然等比例转化为吞吐：drafting 深度、验证成本、硬件和阈值都需共同权衡。未来需进一步降低深层起草与大规模并行验证成本，让算法上的接受长度上限更稳定地转化为真实速度。
