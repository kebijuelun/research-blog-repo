# PaLM-E：统一感知与机器人规划

大语言模型会推理，却常常“看不见”真实场景；通用视觉语言模型会答题，也未必能据此规划机器人。这个断层卡住了大模型走向物理世界的关键一步。PaLM-E 把图像、机器人状态等连续传感器信号直接嵌入语言 Token 空间，让一个模型同时完成具身推理、视觉问答和语言任务。在仅有 320 条规划样本的 TAMP 任务上，跨任务联合训练让 ViT 方案的成功率翻倍以上；最大的 PaLM-E-562B 还在不做任务专用微调的情况下取得 OK-VQA 66.1 分。

![PaLM-E 的多模态输入与多任务能力总览](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/arxiv/2303.03378/figures/palm-e-teaser-v4-4.png)

> 图解：中间是 PaLM-E 的统一接口：图像经 ViT 编码、具身状态经专门编码器处理后，与文字一起送入 PaLM，输出既可回答问题，也可驱动控制模块。四周展示同一模型覆盖的任务：移动操作、任务与运动规划、桌面操作、视觉问答与描述，以及纯语言任务。绿色和蓝色表示连续观测，橙色表示文本 Token。

## 为什么“会语言”还不等于“会行动”

想象让机器人处理“我洒了饮料，拿点东西来清理”这样的请求。它不仅要联想到海绵，还要知道海绵在哪、抽屉是否打开、抓取是否成功，以及失败后下一步怎么办。纯文本 LLM 或许能列出合理步骤，却无法仅凭文字确认现场状态。

这就是**接地（grounding）**问题：语言中的概念必须与视觉和物理传感器中的真实对象建立联系。此前主要有三条路线，但各有缺口：

- **通用 VLM**：Flamingo 等方法让 LLM 注意图像，PaLI 等模型擅长 VQA、描述和 OCR；但机器人需要的精细几何关系、可行动性与长程规划，并不等同于普通视觉问答。
- **直接输出动作的模型**：RT-1、Gato 等将视觉和语言映射为动作，语言主要承担任务指定；PaLM-E 则保留文本作为高层规划表示，因而能利用 LLM 内部的世界知识，也能自然进行问答。
- **LLM 加外部接地模块**：SayCan 用 affordance（当前状态下技能是否可执行）约束计划，其他方法借助视觉反馈、程序生成或场景图。PaLM-E 的不同之处是让模型自身接收传感器输入并直接生成计划，不依赖额外的接地模型。

与 Frozen 将视觉编码器接向冻结 LLM 的思路相比，PaLM-E 把范围扩展到状态向量和 3D 神经场景表示，并面向真实的具身决策。论文还报告其 VQAv2 表现比 Frozen 高出 45% 以上，但真正重要的推进是：模型不再只“谈论图像”，还能根据图像安排行动。

## 核心方法：把传感器读数写成“多模态句子”

PaLM-E 的直觉很像给 LLM 配一套“感官翻译器”：摄像头和状态估计器说的是连续数值，编码器把它们翻译成 LLM 已熟悉的向量，再把这些向量插进句子的相应位置。严格来说，这些**多模态句子（multimodal sentences）**就是文本 Token 嵌入与连续观测嵌入交错组成的序列。

例如，模型可以接收：

`Q: What happened between <img_1> and <img_2>?`

其中 `<img_1>`、`<img_2>` 并非图像文件名，而是图像编码器产生的向量序列。相比把图像固定放在 prompt 开头，这种设计允许图像出现在任意语义位置，也能自然组合多张图和多种传感器。

### 从自回归文本到连续观测注入

PaLM-E 的骨干是 decoder-only LLM。对于文本序列 $w_{1:L}=(w_1,\ldots,w_L)$，标准自回归分解为：

$$
p(w_{1:L})=\prod_{l=1}^{L}p_{\mathrm{LM}}(w_l\mid w_{1:l-1})
$$

给模型一个前缀 $w_{1:n}$，它便根据上下文继续生成后续 Token：

$$
p(w_{n+1:L}\mid w_{1:n})=\prod_{l=n+1}^{L}p_{\mathrm{LM}}(w_l\mid w_{1:l-1})
$$

离散文本 Token $w_i$ 原本通过嵌入映射 $\gamma$ 进入 $k$ 维语言空间。PaLM-E 的关键是绕过离散化这一步，用观测编码器 $\phi$ 把连续输入 $O_j$ 直接映射到同一空间。前缀中的每个向量因此有两种来源：

$$
x_i=
\begin{cases}
\gamma(w_i), & \text{文本 Token}\\
\phi_j(O_j)_i, & \text{观测 }O_j\text{ 对应的向量}
\end{cases}
$$

一幅图通常对应多个向量，而非单个“大图向量”。这些向量与文本一样经过 Transformer 的 Self-Attention，并复用 LLM 已有的位置编码。笔者认为，这个设计的聪明之处在于没有另造一套机器人推理语言，而是尽量把新问题转化成预训练 LLM 已经擅长的序列建模问题。

### 输出如何真正驱动机器人

PaLM-E 始终自回归地生成文本，但文本有两种用途：

1. **直接作答**：用于具身问答、场景描述等任务。
2. **生成高层技能序列**：用于规划与控制。低层策略负责把“抓起绿色物体”之类的技能翻译成电机动作。

在控制回路中，PaLM-E 根据长期目标和当前观测生成下一步指令，机器人执行后返回新图像，PaLM-E 再决定继续还是重规划。它需要从训练数据和 prompt 中自行学会可用技能集合，论文没有额外机制过滤或约束输出。

因此，PaLM-E 不是端到端输出关节力矩的控制器，而是**组织和调度低层技能的高层策略**。这一边界很重要：它负责语义推理和长程拆解，实时运动控制仍交给已有策略。

## 输入表示：从像素网格到对象与 3D 场景

统一接口解决“怎么接入”，接下来的问题是“接入什么表示”。论文比较了状态向量、ViT、对象中心表示和 OSRT，实质上是在测试：机器人推理更需要通用视觉语义，还是显式的对象与几何结构。

| 输入方案 | 编码方式 | 主要特点与代价 |
|---|---|---|
| 状态向量 | MLP 将 $s\in\mathbb{R}^{S}$ 投影到语言空间 | 可直接输入位姿、尺寸、颜色等；简单高效，但依赖状态估计或真值 |
| ViT | 图像变成 $m$ 个视觉 Token，再用仿射变换对齐维度 | 利用大规模图像预训练；采用 ViT-4B、ViT-22B，也测试从头训练的 ViT+Token Learner |
| 对象中心 ViT | 用真值实例掩码 $M_j$ 分解图像，分别编码各对象 | 表示更接近物理对象，但需要 ground-truth 分割 |
| OSRT | 从多视图图像无监督发现 object slots，再由 MLP 投影 | 具备 3D 感知和对象结构，无需真值掩码，但需在领域内以新视图合成训练 |

ViT 输出的维度不必与 LLM 相同，因此要学习投影 $\psi$：

$$
x_i=\phi_{\mathrm{ViT}}(I)_i=\psi\big(\tilde{\phi}_{\mathrm{ViT}}(I)_i\big)
$$

OSRT（Object Scene Representation Transformer，对象场景表示 Transformer）则把多视图输入 $I_{1:v}$ 分解为对象槽 $o_j$。每个对象仍被编码成多个向量，使 LLM 获得比单向量更丰富的对象信息。

### 用实体标签消除指代歧义

桌上有多个同色方块时，“拿起红色方块”并不能唯一指定目标。PaLM-E 对对象中心输入增加实体标签：

`Object 1 is <obj_1>. … Object j is <obj_j>.`

之后，模型可在计划里直接输出 `obj_j`，低层策略也按同一标签识别对象。这相当于给视觉对象发放临时“身份证”，把感知中的对象槽与语言中的指代稳定绑定。

## 训练配方：联合训练、冻结与模型规模

PaLM-E 的训练样本包含连续观测、文本和前缀结束位置。特殊占位符先标出图像或对象在句子中的位置，再被编码器向量替换。只对前缀之后的文本答案计算平均 Cross-Entropy Loss，不要求模型重构输入图像。

论文基于三档 PaLM，构成三种主要配置：

| 模型 | 语言模型 | 视觉编码器 | 总参数量 |
|---|---:|---:|---:|
| PaLM-E-12B | PaLM-8B | ViT-4B | 12B |
| PaLM-E-84B | PaLM-62B | ViT-22B | 84B |
| PaLM-E-562B | PaLM-540B | ViT-22B | 562B |

训练时有两种选择。**全量微调**同时更新编码器、投影层和 LLM，适合充分对齐具身能力；**冻结 LLM**则只训练输入侧，让编码器学会产生冻结模型能理解的向量，可看作由输入条件控制的 soft prompt。在部分 OSRT 实验中，连对象槽表示也被冻结，仅训练很小的投影层。

更关键的是跨任务联合训练。完整混合数据中，具身数据仅占 8.9%，其余主要是互联网规模的视觉语言数据。这样做的假设是：网页图像教会模型对象与语义，不同机器人教会模型行动与几何，多样数据能让这些能力相互迁移，而不是彼此挤占。

## 实验总览：三种机器人，两条验证主线

实验同时覆盖仿真与真实机器人：

- **TAMP（Task and Motion Planning，任务与运动规划）**：抓取、堆叠多对象，计划组合空间大，许多动作序列不可行，要求精确推理位姿。
- **Language-Table**：桌面多对象推挤，语言空间大、接触动力学复杂，测试长程任务和少样本学习。
- **移动操作**：机器人在厨房中导航、找物、抓取并递送，测试 affordance、失败检测和长程规划。

第一条实验主线比较不同输入表示的性能、泛化和数据效率；第二条固定“预训练 ViT + PaLM”的主架构，检查一个通用模型能否同时胜任多任务，以及联合训练是否产生正向迁移。基线包括没有机器人数据训练的 PaLI，以及使用 oracle affordance 的 SayCan。

![三类机器人任务上的跨域迁移](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/arxiv/2303.03378/figures/4_Transfer_figure_for_PaLM-E.png)

> 图解：横轴对比只用单一机器人数据从头训练的模型，与使用 PaLM、ViT 预训练并在全部机器人和视觉语言数据上联合训练的单一模型；纵轴为成功率或准确率。蓝色、红色、黄色分别对应 TAMP、Language-Table 和移动操作 affordance。三组任务都因 full mixture 明显提升，右侧还说明模型由“每台机器人一个模型”变为“一个模型服务所有机器人”。

## TAMP：少量数据下，对象结构与迁移最有效

TAMP 的问题不是识别“桌上有什么”，而是判断“先挪开谁，才能抓到谁”。全局 VQA 任务 $q_2$、$q_3$、$q_4$ 分别询问对象与桌面的位置、对象间关系、计划可行性；规划任务 $p_1$、$p_2$ 分别要求抓取与堆叠。对象中心版本另有颜色问答 $q_1$，并用实体标签指代对象。

![包含 6 个对象的 TAMP 测试场景](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/arxiv/2303.03378/figures/damp.png)

> 图解：该测试场景包含 6 个不同尺寸、颜色和位姿的方块，而训练场景只有 3–5 个对象。模型需要把视觉关系转化为可执行的抓取顺序，物体增多会显著扩大计划搜索空间。

![包含 4 个对象的 TAMP 测试场景](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/arxiv/2303.03378/figures/damp2.png)

> 图解：这是训练分布内的 4 对象示例，机械臂附近存在堆叠关系。模型既要判断几何可行性，也要输出“先移开遮挡物，再抓目标”等多步计划。

## 移动操作：既会规划，也要判断能否执行

移动操作使用 RT-1 作为低层策略，训练数据包含 2,912 条运行序列。长程规划的 prompt 由人的指令、历史步骤和当前图像组成，PaLM-E 每次预测下一步，直到输出 `terminate`。

除规划外，论文还把两种关键能力写成 VQA：

- **Affordance prediction**：`Given <img>. Q: Is it possible to <skill> here?`
- **Failure detection**：`Given <img>. Q: Was <skill> successful?`

前者防止计划在当前场景根本做不通，后者让闭环系统知道何时重试或改计划。下表为 F1 分数。

| 模型／训练方式 | 失败检测 | Affordance |
|---|---:|---:|
| PaLI（zero-shot） | 0.73 | 0.62 |
| CLIP-FT | 0.65 | — |
| CLIP-FT-hindsight | 0.89 | — |
| QT-OPT | — | 0.63 |
| PaLM-E-12B，单机器人，从头训练 | 0.54 | 0.46 |
| PaLM-E-12B，单机器人，预训练，LLM 冻结 | 0.91 | 0.78 |
| PaLM-E-12B，full mixture，LLM 冻结 | 0.91 | 0.87 |
| PaLM-E-12B，full mixture，LLM 解冻 | 0.77 | 0.91 |

通用预训练让单机器人模型的 affordance 从 0.46 提升到 0.78，联合训练进一步达到 0.87；解冻 LLM 后达到 0.91。冻结方案在失败检测上更好，解冻方案在 affordance 上更好，再次说明两种训练路线各有适用场景。

## 语言能力保留：规模越大，遗忘越少

## 数据混合与复现细节

完整混合数据里，机器人数据不足 10%，通用视觉语言数据占主体。具体采样频率和占比如下：

| 数据集 | 采样频率 | 占比 |
|---|---:|---:|
| WebLI | 100 | 52.4% |
| VQ²A | 25 | 13.1% |
| VQG | 10 | 5.2% |
| CC3M | 25 | 13.1% |
| Object Aware | 10 | 5.2% |
| OK-VQA | 1 | 0.5% |
| VQAv2 | 1 | 0.5% |
| COCO | 1 | 0.5% |
| Wikipedia text | 1 | 0.5% |
| 移动操作机器人（真实） | 6 | 3.1% |
| Language-Table（仿真与真实） | 8 | 4.2% |
| TAMP（仿真） | 3 | 1.6% |

这组比例解释了一个看似反直觉的结果：机器人能力提升，并不总需要增加机器人数据。互联网视觉语言数据提供语义先验，少量具身样本负责把这些先验对齐到行动空间。对数据昂贵的机器人领域，这比单纯扩大采集规模更有吸引力。

不过，论文的实验也有明确边界。TAMP 的部分表示使用真值对象状态或掩码；OSRT 需要领域内多视图训练；真实移动操作的长程规划主要是定性评估；PaLM-E 依赖外部低层策略，技能集合和执行误差仍会影响最终成功率。562B 模型的训练与推理成本也没有作为可低成本复现的方案来呈现。

## 总结：真正关键的是“统一接口＋正向迁移”

- PaLM-E 用多模态句子把图像、状态和对象表示注入 LLM 嵌入空间，统一了问答与机器人高层规划。
- 跨机器人、跨视觉语言任务联合训练产生正向迁移；TAMP 低数据规划中，ViT-4B 两项成功率从约 31%–33% 提升到约 75%。
- OSRT 的 3D 对象表示在极少数据下最有效，说明结构归纳偏置能补充大规模预训练。
- 同一个 PaLM-E-562B 在 OK-VQA 达 66.1，并展现多图推理和多模态 Chain-of-Thought 等零样本能力。
- 冻结 LLM 可保留语言能力；解冻训练时，扩大规模将最大模型的 NLG 相对降幅缩小到约 3.9%。

PaLM-E 打开的下一步，是把更可靠的 3D 场景表示、可验证的闭环规划和更高效的模型规模结合起来，让通用模型不仅能给出合理答案，还能在真实世界里稳定完成行动。
