# Qwen2.5-VL 技术报告深度解读：会“定位”、能“看长视频”、还能“操作手机”的开源视觉语言模型

多模态大模型（LVLM）普遍存在一个尴尬：什么都会一点，但在细粒度视觉感知上总差一口气——看不清小字、定位不准物体、长视频看到后面忘了前面。Qwen2.5-VL 就是冲着这个痛点来的，它的核心思路可以概括为一句话： **用原生动态分辨率 + 绝对时间编码，让模型直接感知真实世界的空间尺度和时间节奏，而不是靠归一化“糊弄”过去** 。结果相当硬：旗舰版 Qwen2.5-VL-72B 在文档解析、GUI 定位等任务上全面超越 GPT-4o 和 Claude 3.5 Sonnet，在 ScreenSpot Pro 高分辨率 GUI 定位上拿到 43.6%（上一代 Qwen2-VL-72B 只有 1.6%），在小时级长视频基准 LVBench 上以 47.3 大幅领先 GPT-4o 的 30.8。更难得的是，7B 和 3B 的小模型也全面压制同级别对手，从边缘设备到高性能计算都能用。

![Qwen2.5-VL 能力总览](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/arxiv/Qwen2.5-VL-Technical-Report/figures/head.jpg)

> 图解：Qwen2.5-VL 能力总览图。展示了模型在文档解析（发票、表格、乐谱、化学式）、物体定位（框选/指点/计数）、长视频理解与事件定位、以及操作电脑和手机等 Agent 场景下的实际表现，覆盖从感知到行动的完整链路。

## 背景：现有 LVLM 的“三明治困境”

论文用了一个很形象的比喻：当前的多模态大模型像三明治饼干的中间夹层——各种任务都能做，但都不够出色。夹层的下面是 **细粒度视觉感知** （看得准、定位得准），上面是 **多模态推理** 。Qwen2.5-VL 这一代的策略很清晰：先把地基（细粒度感知）打牢，再用 Qwen2.5 LLM 的语言能力把上层推理顶起来。

具体来说，现有模型有四个瓶颈：

- **计算复杂度** ：高分辨率图片 token 爆炸，算力扛不住；
- **上下文理解有限** ：长视频、长文档处理不了；
- **细粒度感知差** ：小物体、密集文字、精确坐标输出能力弱；
- **序列长度不稳定** ：输入一长性能就掉。

Qwen2.5-VL 的技术贡献正好一一对应这四点：视觉编码器引入 Window Attention 降算力、动态 FPS 采样把时间维也变成“动态分辨率”、MRoPE 时间维对齐绝对时间、预训练语料从 1.2 万亿 token 扩到 4.1 万亿 token。下面我们逐层拆开看。

## 模型架构：三大件，处处为“原生分辨率”服务

![Qwen2.5-VL 整体架构](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/arxiv/Qwen2.5-VL-Technical-Report/figures/qwen2.5vl_arc.jpeg)

> 图解：Qwen2.5-VL 整体架构。左侧是重新设计的 Vision Transformer（ViT），以原生分辨率处理图片和视频帧；不同尺寸的图片、不同 FPS 的视频帧被动态映射为不等长的 token 序列。中间的关键设计是 MRoPE 的时间维 ID 与绝对时间对齐，让模型感知事件的真实节奏。视觉特征经 MLP Merger 压缩后送入右侧的 Qwen2.5 LM Decoder。ViT 内部采用了 SwiGLU 激活、RMSNorm 归一化和窗口注意力。

架构上仍然是经典的三段式，但每一段都做了针对性改造：

- **大语言模型** ：直接沿用 Qwen2.5 LLM 的预训练权重初始化，把 1D RoPE 改造为对齐绝对时间的多模态旋转位置编码（MRoPE），这是它语言能力不退化的关键。
- **视觉编码器** ：从零开始重新训练的 ViT，引入 2D-RoPE 和窗口注意力，原生支持任意输入分辨率。输入图片的宽高统一调整为 28 的倍数后，以步长 14 切分成 patch。
- **MLP 视觉-语言融合器（Merger）** ：不直接把 ViT 的 patch 特征塞给 LLM，而是先把空间上相邻的 4 个 patch 特征分组、拼接，再过两层 MLP 投影到与文本 embedding 对齐的维度。这一步把视觉 token 数量压缩到原来的四分之一，显著降低 LLM 的计算负担。

三个尺寸的具体配置如下：

| 配置项 | Qwen2.5-VL-3B | Qwen2.5-VL-7B | Qwen2.5-VL-72B |
| --- | --- | --- | --- |
| **ViT 隐层维度** | 1280 | 1280 | 1280 |
| ViT 层数 / 注意力头数 | 32 / 16 | 32 / 16 | 32 / 16 |
| ViT 中间层维度 | 3456 | 3456 | 3456 |
| Patch 大小 / 窗口大小 | 14 / 112 | 14 / 112 | 14 / 112 |
| 全注意力层索引 | {7, 15, 23, 31} | {7, 15, 23, 31} | {7, 15, 23, 31} |
| **Merger 输出维度** | 2048 | 3584 | 8192 |
| **LLM 隐层维度** | 2048 | 3584 | 8192 |
| LLM 层数 / KV 头数 | 36 / 2 | 28 / 4 | 80 / 8 |
| LLM 中间层维度 | 4864 | 18944 | 29568 |
| Embedding 共享 | ✓ | ✗ | ✗ |
| 词表大小 | 151646 | 151646 | 151646 |
| 训练 token 量 | 4.1T | 4.1T | 4.1T |

注意一个细节：三个尺寸的 ViT 完全相同（约 675M 参数），只有 LLM 部分在缩放。这意味着视觉能力不缩水，小模型也有一双“好眼睛”。

### 快而省的视觉编码器：窗口注意力是主角

原生分辨率输入的最大麻烦是：图片有大有小，计算量随 patch 数平方增长，训练和推理负载极不均衡。Qwen2.5-VL 的解法是在 32 层 ViT 里只保留 4 层全局自注意力（第 7、15、23、31 层），其余全部换成窗口注意力，最大窗口 112×112 像素（即 8×8 个 patch）。

这个设计的聪明之处在于：小于窗口尺寸的区域不需要任何 padding，直接按原始分辨率处理，计算量随 patch 数 **线性** 增长而不是平方增长；同时保留的 4 层全局注意力负责跨区域信息交换，不丢全局视野。位置编码用 2D-RoPE 捕捉二维空间关系。

视频方面则扩展到 3D patch 划分：静态图片沿用 14×14 patch，视频则把相邻两帧合并为一个单元，喂给 LLM 的 token 数量直接减半。此外，ViT 整体向 LLM 的设计风格看齐——归一化用 RMSNorm、激活函数用 SwiGLU，提升视觉和语言组件之间的计算兼容性和效率。

训练上，这个 ViT 是从零训练的（不用现成 CLIP 权重），依次经过 CLIP 式预训练、视觉-语言对齐、端到端微调几个阶段，并且全程按原始宽高比动态采样不同分辨率的图片，保证对任意输入尺寸的泛化能力。

### 原生动态分辨率与动态帧率

空间维度上，Qwen2.5-VL 把不同尺寸的图片动态转成对应长度的 token 序列，并且 **直接用输入图片的真实像素坐标** 来表示边界框和点，而不是传统的归一化坐标。这样一来模型学到的是真实的尺度信息——“这个框宽 200 像素”在不同分辨率的图里含义是明确的，泛化到没见过的分辨率也稳。

时间维度上，引入动态 FPS（帧率）训练和绝对时间编码。其他做法要么在文本里塞时间戳、要么加额外的预测头来做时间定位，Qwen2.5-VL 的做法更优雅：直接让 MRoPE 的时间维 ID 与真实时间戳对齐，模型通过相邻帧 ID 的间隔就能“感受”时间的流速，零额外计算开销。

### MRoPE：让位置编码对齐绝对时间

这里值得展开讲讲。Qwen2-VL 提出的 MRoPE（Multimodal Rotary Position Embedding）把位置编码拆成三个分量：时间（t）、高度（h）、宽度（w）。文本输入时三个分量用同一个 ID，等价于普通 1D RoPE；图片输入时时间 ID 固定，h/w 按 patch 的空间位置分配；视频输入时时间 ID 逐帧递增。

问题在于：Qwen2-VL 的时间 ID 只跟“第几帧”挂钩，跟真实时间无关。同样第 10 帧，在 1 FPS 采样的视频里是第 10 秒，在 10 FPS 里却是第 1 秒——模型根本分不清事件的快慢和发生的具体时刻。

Qwen2.5-VL 的改进就是一句话： **时间维 ID 与绝对时间对齐** 。不管采样帧率怎么变，同一秒的画面永远拿到同样的时间 ID。这样模型学到的是跨帧率一致的时间感，为后面“秒级事件定位”和“小时级长视频理解”打下了基础。

## 预训练：4.1 万亿 token 背后的数据工程

### 数据构成：量是其次，质和配方才是关键

预训练数据从 Qwen2-VL 的 1.2 万亿 token 大幅扩充到约 4.1 万亿 token，来源包括清洗后的网页数据和合成数据，类型覆盖图文描述、交错图文、OCR、视觉知识（名人/地标/动植物）、多模态学术题、定位数据、文档解析、视频描述与定位、Agent 交互数据等。几个重点方向值得细看：

**交错图文数据** 。这类数据有三大价值：支持图文混合的 in-context learning、缺图时保持纯文本能力不掉、信息覆盖面广。但网上的交错数据噪声大、图文关联弱。团队的解法是“清洗 + 四维打分”流水线，用内部评测模型从四个维度筛选：纯文本质量、图文相关性（图是否实质补充了文字而非装饰）、图文互补性（两者是否各提供独特信息）、信息密度平衡（避免一头重一头轻）。

**绝对坐标的 Grounding 数据** 。相对坐标无法表达物体在原图中的真实大小和位置，所以训练时边界框和点一律使用输入图片的实际像素坐标。数据来自公开数据集加自有数据，合成格式覆盖 XML、JSON 和自定义格式，还用上 copy-paste 增强、Grounding DINO 和 SAM 自动生成标注。为了开放词汇检测能力，类别扩展到 1 万种以上；为了让模型学会“拒绝”，还专门合成了查询不存在物体的负样本。点定位（pointing）数据则整合了 PixMo 的公开指向/计数数据、检测与分割数据、以及自动化流水线合成的细节指向数据。

**文档全解析（Omni-Parsing）数据** 。传统文档解析要串一串专用模型：版面分析一个、文字提取一个、图表理解一个。Qwen2.5-VL 的思路是让一个通用模型全包。做法是把表格、图表、公式、插图、乐谱、化学式等元素统一表示成一种带坐标的 HTML 格式（QwenVL HTML）：每个元素用 `data-bbox="x1 y1 x2 y2"` 标注版面位置，内容按阅读顺序组织。这样任何文档的完整信息——版面、文字、图表、插图——都能用统一格式表达。比如段落是 `<p data-bbox="...">内容</p>`，图表是 `<div class="chart" data-bbox="..."><img/><table>图表数据</table></div>`，乐谱和化学式也各有对应的标签结构。笔者认为这是全文最有“工程美感”的设计之一：统一的表示格式让模型的解析能力可以直接迁移到没见过的文档类型。

**OCR 数据** 。合成数据用视觉文本生成引擎产出高质量野外文字图片；多语言覆盖法、德、意、西、葡、阿、俄、日、韩、越等语种；图表数据用 matplotlib、seaborn、plotly 合成 100 万样本；表格数据用离线端到端模型处理 600 万真实样本，并过滤低置信度、重叠和单元格过稀的表格。

**视频数据** 。训练时动态采样 FPS 让帧率分布更均匀；针对半小时以上的长视频，专门用合成流水线把多帧描述合成长视频 caption；时间定位数据同时覆盖秒级格式和“时:分:秒:帧”（hmsf）格式，保证模型能理解和输出各种时间格式。

**Agent 数据** 。感知层面，收集移动端、网页、桌面三平台的截图，用合成引擎生成界面描述和 UI 元素定位标注——描述任务让模型“看懂”界面，定位任务让模型把元素外观和功能对应起来。决策层面，把三个平台的操作统一成共享动作空间的函数调用（function call）格式，多步轨迹来自开源数据和虚拟环境中的 Agent 框架合成。关键一步是为每个操作生成推理过程：把真值操作高亮在截图上，连同全局任务和操作前后截图交给人工/模型标注员写“为什么这么做”，再用模型过滤低质量推理。这种带推理的轨迹数据能防止模型死记硬背操作序列，在真实场景更鲁棒。

### 三阶段训练流程

| 阶段 | 视觉预训练 | 多模态预训练 | 长上下文预训练 |
| --- | --- | --- | --- |
| 数据 | 图文描述、知识、OCR | + 纯文本、交错图文、VQA、视频、定位、Agent | + 长视频、长 Agent、长文档 |
| Token 量 | 1.5T | 2T | 0.6T |
| 序列长度 | 8192 | 8192 | 32768 |
| 训练参数 | 仅 ViT | ViT + LLM | ViT + LLM |

第一阶段只训 ViT，让它和 LLM 对齐；第二阶段解冻全部参数，加入交错数据、多任务、VQA、多模态数学、Agent、视频和纯文本数据；第三阶段拉长序列到 32K，加入长视频、长 Agent 轨迹和长文档数据，强化长程依赖和复杂推理。

训练效率上有个实用技巧：视觉编码器参数少且有窗口注意力减负，瓶颈在 LLM，所以按样本喂给 LLM 的实际序列长度动态打包（packing）数据，保证各 GPU 负载均衡。

## 后训练：SFT + DPO 两段式对齐

后训练冻结 ViT 参数，分监督微调（SFT）和直接偏好优化（DPO）两个阶段。SFT 采用 ChatML 格式组织指令数据，与预训练数据格式区分但与 Qwen2-VL 保持一致。

**指令数据** 约 200 万条，纯文本和多模态各占一半（不过多模态条目因视觉 token 消耗的计算量远大于文本），以中英文为主并补充多语言。对话形态覆盖单轮/多轮、单图/多图，领域覆盖通用 VQA、图像描述、数学、代码、安全，以及专门的文档 OCR、定位、视频、Agent 子集。

**两阶段数据过滤流水线** 是质量保证的核心：

- 第一阶段：领域分类。用 Qwen2-VL-Instag（由 Qwen2-VL-72B 改造的专用分类模型）把问答对分到 8 个一级领域、30 个细粒度子类（例如 Coding 下分代码调试、生成、翻译、理解），便于按领域定制清洗策略。
- 第二阶段：分领域过滤。规则过滤负责去掉重复模式、截断/格式错误的回答、无关或有害的问答；模型过滤用 Qwen2.5-VL 系列训练的奖励模型从多维打分——问题看复杂度和相关性，答案看正确性、完整性、清晰度、相关性和有用性，视觉任务还要额外验证是否真正用对了图中的信息。

**拒绝采样（Rejection Sampling）增强推理** 。针对数学、代码、领域 VQA 这类需要多步推理的任务，用中间版本的模型在带真值的数据集上生成带思维链（Chain-of-Thought）的回答，只保留最终答案与真值一致的样本，再过滤掉中英混杂、超长、重复的输出。一个特有挑战是：多模态 CoT 的中间推理步骤可能忽略或误读视觉信息，团队为此设计了规则 + 模型的双重校验来检查中间步骤的模态对齐质量。论文也坦承这一点仍有改进空间。

**DPO 阶段** 只用图文和纯文本的偏好数据，每条样本只训一遍，高效对齐人类偏好。

## 总结

回顾全文，Qwen2.5-VL 的核心要点：

- **架构层面** ：从零训练的原生动态分辨率 ViT + 窗口注意力（仅 4 层全局注意力），计算量随 patch 数线性增长；MLP Merger 把视觉 token 压缩 4 倍。
- **位置编码** ：MRoPE 时间维对齐绝对时间，配合动态 FPS 采样，让模型获得与采样率无关的真实时间感——这是长视频理解和秒级事件定位的地基。
- **数据层面** ：预训练扩到 4.1 万亿 token，绝对坐标 grounding、统一 HTML 格式的文档全解析、带推理过程的 Agent 轨迹是三个最精细的数据工程。
- **后训练** ：领域分类 + 规则/模型双重过滤的 SFT 数据流水线，配合拒绝采样生成高质量 CoT，再经 DPO 对齐偏好。
- **成绩** ：72B 在文档 OCR、GUI 定位、长视频上超越 GPT-4o 和 Claude 3.5 Sonnet，纯文本能力不退反进；7B/3B 同尺寸领先，覆盖边缘到云端。

一句话展望：论文自己点出的下一步是多模态 CoT 中视觉信息与推理链的对齐质量，以及 OSWorld 这类复杂桌面 Agent 场景的差距——细粒度感知的地基已经打好，上层推理和行动的“夹层”还能更厚。
