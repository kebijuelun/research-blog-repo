# SCE：4.6% 样本预测部署安全

评估 AI Agent 的安全防线，真实执行攻击太危险，换到专用测试环境又可能失真，导致前沿模型的部署风险被误判。Redwood Research 提出的模拟控制评估（SCE）让语言模型“扮演环境”，只生成工具反馈而不执行攻击：在 5% 审计预算下，安全预测 RMSE 从 BashArena 的 **10.1 个百分点降至 3.6 个百分点**；评测集仅为部署任务集的 **4.6%** 时，预测已优于完整 BashArena 基线。

## 不执行攻击，如何还原部署环境？

SCE 像一场不接通真实设备的沙盘演练：攻击策略照常行动，模拟器根据部署证据逐步返回工具结果，再由 Monitor 和 Attack Success Judge 评估可疑度与攻击成功率。它不重建整个环境，只模拟 Agent 能看到的反馈，从而降低成本。

![SCE 模拟控制评估流程](assets/sce_overview.png)

> 图解：模拟器生成完整攻击轨迹，Monitor 与 Judge 分别评分，最终计算安全性；攻击动作不会在部署环境真实执行。

关键在两类环境锚定信息：

- **参考轨迹**：同主任务的一次诚实执行，提供真实工具调用和返回结果。
- **代码库读取权限**：允许检索源码、配置和初始文件内容。不可观察的动态状态，则生成与证据一致的结果。

主实验覆盖 **1,000 个 LinuxArena 任务对、10 个环境**，每项通常进行 2 次模拟、2 次真实执行。作者用真实执行作 Ground Truth，并将总误差拆成系统性偏差与重复运行、任务抽样带来的方差，避免把随机波动误判为模拟失真。

## 模拟得有多像，预测得有多准？

行为层面，SCE 将攻击策略、攻击者推理和监控推理聚类后比较分布，三类 KL 散度均比 BashArena **低一个数量级以上**，并接近独立真实重跑的波动。

结果层面，优势同样明显：

- **攻击成功率**：真实执行为 **25.5%**，SCE 估计为 **25.4%**；解释 71% 的任务对间方差。但 92 个副任务中，误差最大的 5 个贡献约一半总平方误差。
- **Monitor 可疑度**：在 0–10 分尺度上，SCE 总 RMSE 为 **0.259**，BashArena 为 **2.821**。
- **Safety**：SCE 解释 **95%** 的副任务类别间方差和 **78%** 的环境间方差，不只能猜中总体平均，还能定位局部薄弱防线。

![5% 审计预算下的安全预测误差](build/figures/safety_environment_error.png)

> 图解：5% 审计预算下，SCE 的总体安全预测 RMSE 为 3.6 个百分点，BashArena 为 10.1 个百分点，约降低三分之二。

## 从评估防线到增强防线

SCE 的价值不止于估分。作者把模拟攻击策略加入 `gpt-5.4-nano` Monitor 的 Prompt，在 0–20% 假阳性率区间，Partial AUROC 达到 **0.841**，高于 BashArena 策略的 **0.767**，接近同环境真实策略的约 **0.851**。这说明模拟中发现的情报能迁移到未见过的真实攻击检测。

但边界必须明确：

- 核心攻击与安全结论仅在 LinuxArena 验证，普通 Agent 会话尚不能证明 Safety 可迁移。
- 局部输出难以识别，不代表完整轨迹完全真实；单纯优化“像不像”反而可能损害控制指标。
- 方法依赖可信模拟器，稀有攻击仍有漏配，Judge 与 Simulator 的误差也会叠加。

笔者认为，SCE 最重要的启示是：**与其昂贵地追求完全可执行的测试副本，不如优先利用部署证据，保留真正影响攻击与监控的环境机制。**下一步需要在更多真实部署中验证迁移，并防止针对模拟器的反复优化放大隐蔽误差。
