# DFlash：最高加速6.1倍

大模型逐 token 串行解码拖慢了长文本与推理生成，DFlash 用并行扩散草稿和目标模型上下文注入同时解决“猜得慢、猜不准”，在 Qwen3-8B 上实现最高 **6.1× 无损加速**，多数基准的加速倍率接近 EAGLE-3 的 **2.5 倍**。

## 核心思路：让扩散模型专职打草稿

- 投机解码由小模型生成候选、目标模型并行验证，因此不改变最终输出质量；但 Medusa、EAGLE 等方案的草稿阶段仍主要串行展开。
- DFlash 不让扩散语言模型替代目标模型，而是用轻量级 Block Diffusion **一次前向并行预测整个 token 块**，再由目标模型验证并接受一致前缀。
- 相比生成 $\gamma$ 个 token 需要 $\gamma$ 次前向的自回归草稿，块级并行显著降低草稿延迟，也允许使用更深网络提高接受率。5 层 DFlash 生成 16 个 token 的草稿延迟，仍低于 EAGLE-3 生成 8 个 token。

## 关键方法：目标特征注入每一层

- **跨层特征提取**：目标模型 prefill 后，从第 2 层到倒数第 3 层均匀选取 5 层隐藏状态，拼接并投影为紧凑上下文特征。
- **逐层 KV 注入**：目标特征被投影为草稿模型每层额外的 Key、Value 并写入 KV cache。每层 Attention 都能直接读取目标上下文，避免仅在输入端融合导致信息随深度稀释。
- **轻量适配**：草稿模型与目标模型共享并冻结 Embedding 和 LM Head，只训练草稿 Transformer 层；新增共享投影在 Qwen3.5-35B-A3B 上约占 42 MB。

训练也围绕真实投机流程设计：随机选择干净 response token 作为块首锚点，遮蔽后续位置；块内双向注意、块间隔离，并用 Flex Attention 高效计算。固定每序列 512 个随机锚点，使长上下文训练成本有界。块内 Loss 按位置指数衰减，优先保证更早 token 正确，因为前缀一旦出错，后续预测便无法连续接受。

## 实验结论：接受更长，部署也确实更快

- Qwen3-4B/8B 非推理模式、贪婪解码下，DFlash 平均加速约 **4.9×**，平均接受长度约 **6.5**；温度 1 时仍约 **4.1×**。开启 thinking mode 后，三项推理任务在温度 0、1 下分别保持约 **4.5×、3.9×** 加速。
- SGLang 单张 B200 测试中，Qwen3-8B Math500 单并发最高 **5.1×**；并发提高后收益下降，但所列配置均有吞吐增益。vLLM 与多模型实验同样验证低、中并发优势，高并发仍需控制验证成本。
- 消融表明：KV 注入负责“猜得准”，扩散并行负责“猜得快”；随机锚点同时提高接受长度与速度。草稿从 3 层增至 8 层会持续提高接受长度，但 5 层综合加速更好，说明最高接受率不等于最快速度。
- 块长泛化具有单向性：块长 16 训练可缩至 8 推理，反向则效果不佳，为按并发动态缩短块长提供空间。长上下文方面，仅用 LongAlign-10K 的 1.6K 样本微调 3 个 epoch，hotpotqa 在 16K 下接受长度由 3.61 提升至 6.05。

DFlash 的价值在于重新定位扩散模型：不必独立竞争最终生成质量，作为专业化并行草稿器更能发挥优势。不过收益会随模型、任务、温度、块长和并发变化，最高 6.1× 并非所有部署的统一结果。
