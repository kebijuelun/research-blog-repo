# HiSA：按旋转角度稀疏点积，降损又提速

HiSA 要解决的是注意力计算中“保留一个 Query–Key 对，就必须算完所有特征维度”的冗余，同时削弱远距离高频位置信号的干扰：135M 模型在 4K 上下文下只计算 **29.3%** 的 QK 点积，验证损失反而从 dense 的 2.906 降至 **2.880**。

## 核心创新：从删 token 转向删点积

- 传统稀疏注意力裁剪整个 Key；HiSA（Hidden Sparse Attention）保留 token 对，只让部分 RoPE 频率对参与最终注意力分数，不修改 Query、Key 投影，也不需要路由器或 Top-$k$。
- RoPE 将分数分解为各频率对之和，其中内容来自向量模长与原始夹角，相对位置只通过 $\Delta\theta_l$ 进入。高频旋转快，适合近距离精细位置；低频更稳定，适合长程依赖。
- 因此，HiSA 的原则是：**近处保留全部频率，远处只保留慢频率**，将稀疏化扩展到 hidden dimension。

## 方法：一个角度预算决定静态窗口

唯一超参数是角度预算 $\Phi_{\max}$：仅当 $\Delta\theta_l<\Phi_{\max}$ 时保留对应点积项，默认取 $90^\circ$；设为无穷大即退化为 dense。第 $l$ 个频率对的窗口为 $\Delta_{\max,l}=\Phi_{\max}/\theta_l$，最大可达距离由最慢频率决定。模式只依赖位置和频率，训练、推理完全一致，kernel 可提前知道哪些计算和缓存能够省略。

Flash-HiSA 再将规则变成 GPU 友好的块计算：序列按 128 token 分块，特征按 16 维（8 个 RoPE 对）分 chunk，整块跳过被删除的计算，边界 chunk 通过 Query 置零处理。训练与推理必须使用同一块大小，因为它们对应同一个近似模型。

## 结果：损失、训练与解码

- **从零预训练**：4K、360M 模型的验证损失由 2.587 降至 2.575；扩展到 16K 后，精确 HiSA 只算 20.2% 的 QK 点积，PG19 损失由 3.205 降至 3.170。
- **训练速度**：精确 Triton kernel 仅 119k tokens/s；Flash-HiSA 达 238k tokens/s，与 dense FlashAttention-3 的 236k 基本持平，但块近似使点积比例升至 34.8%，损失增益有所缩小。
- **缓存与解码**：16K、batch 128 时，吞吐由 9.2k 提升至 **13.0k tokens/s**，KV cache 由 45.0 GiB 降至 **29.1 GiB**。约 42% 的吞吐提升中有 13% 来自更小的 Query tile，不能全部归功于稀疏规则。
- **dense 转换**：直接切换会使损失由 2.906 升至 2.937；继续训练 1.35B tokens 后达到 2.836，与同预算 dense 的 2.838 基本持平。因此它不是免训练裁剪，而是低成本架构转换。

## 机制证据与边界

删除频率对并观察输出变化的实验显示，dense 模型会逐渐抑制大旋转角分数项：训练 1B tokens 后，$180^\circ$–$360^\circ$ 区域低于无信息参考的格子比例由 33% 增至 48%；训练约 600B tokens 的 SmolLM-135M 中，超过 $180^\circ$ 的区域达到 87%–95%。这说明 HiSA 相当于把 dense 模型本来就要学习的抑制机制直接写入架构。

目前证据仍主要来自 135M、360M 模型和语言建模损失；稀疏收益也更早体现在解码，而非完整训练。更大模型、下游任务及更完整的 backward kernel 仍待验证。
