# StreamingLLM：保留注意力汇点，让流式对话稳定运行

要让只有有限训练窗口的大模型在多轮对话中持续运行，关键不是无限扩张上下文，而是在固定 KV Cache 下避免显存增长和性能崩溃；StreamingLLM 以无需微调的方式解决了这一部署难题。它让 Llama-2、MPT、Falcon、Pythia 等模型稳定处理最长 **400 万 token**，相对质量可接受的滑动窗口重计算，单 token 解码最高提速 **22.2 倍**。

## 核心发现：窗口崩溃源于删除“注意力汇点”

- 深层注意力会把大量权重分给序列开头，即使这些 token 与当前预测没有明显语义关系。Softmax 权重必须合计为 1，初始位置因此成为“剩余注意力出口”；删除其 KV 会显著改变注意力分布。
- Llama-2-13B 在 PG19 首本约 65K token 书籍上，纯窗口配置 `0+1024` 的困惑度高达 **5158.07**；保留四个初始 token 的 `4+1020` 降至 **5.40**。把四个初始 token 全换成换行符，困惑度仍为 **5.60**，说明关键是起始位置的汇点功能，而非开头词语的语义。
- 一个初始 token 通常不够：已有模型会把汇点分散到多个位置，默认保留 **四个**基本足够，再增至八个收益很小。

## 方法：固定大小的滚动 KV Cache

- 缓存由固定的少量 **Attention Sinks** 和持续滚动的近期 token 组成。新 token 到来时只淘汰滚动区最旧的 KV，缓存总量始终受限。
- 位置必须按缓存内顺序重新编号，不能沿用跳跃的原始文本编号。RoPE 需缓存旋转前的 Key，再按缓存内位置施加旋转；ALiBi 则对连续缓存施加距离偏置。
- 该机制可直接用于采用 RoPE 或 ALiBi 的现有自回归模型，无需微调；它不是简单“少删几行缓存”，位置处理不一致便无法完整复现稳定效果。

## 从头预训练：一个专用 Sink Token 即可

在每个训练样本开头加入可学习占位 token，可让各层和头集中使用专用汇点。Pythia-160M 实验中，加入一个 Sink Token 未损害七项零样本基准表现；流式评测采用 `1+1023` 时困惑度为 **18.01**，不再需要多个普通初始 token。增加第二个 Sink Token 没有稳定收益。

## 实验结论：稳定、快速，但不等于更会利用长上下文

- 多模型、多规模在最长 400 万 token 的流式语言建模中保持稳定，困惑度没有随输入增长持续恶化。
- 连续 ARC 问答中，Llama-2-13B-Chat 使用 StreamingLLM 的 ARC-E／ARC-C 准确率为 **80.89%／65.61%**，逐样本 One-shot 为 **78.16%／63.31%**；Dense Attention 因显存溢出无法完成，纯窗口注意力则接近随机输出。
- 更大近期缓存并不总带来更低困惑度，暴露的是模型上下文利用能力的上限，而非缓存机制失效。22.2 倍也是单张 NVIDIA A6000、特定模型与窗口设置下的峰值，并非所有部署的固定收益。

## 能力边界：可持续生成不等于长期记忆

StreamingLLM 只能直接利用当前缓存中的近期信息和汇点，滚出窗口的历史无法检索；StreamEval 中，答案距离超过缓存容量后，准确率最终降为零。LongBench 上，`4+3496` 会因丢失初始提示而落后截断基线，改为 `1750+1750` 才恢复到接近基线。因此，它适合多轮对话、短文档问答等短期记忆场景；长文档问答和摘要仍需结合上下文扩展、检索或其他记忆机制。
