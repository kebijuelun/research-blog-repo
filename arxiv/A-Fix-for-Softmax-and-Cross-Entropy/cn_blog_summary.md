# Softmax 修复记：一个补丁揪出交叉熵里的两个数值 Bug

你每天用的 softmax 和交叉熵，标准实现里藏着两个数值 Bug：模型高置信度时目标梯度会被浮点舍入错误归零，蒸馏时学生等于老师仍会算出"幽灵梯度"。Google DeepMind 这项工作用十几行 log 空间重参数化代码即插即用地修复了它们——效果惊人：Grokking 研究中困扰学界三年的 Slingshot 损失尖峰被证明就是这个 Bug，无权重衰减时标准交叉熵的测试准确率从 61% 崩到 23%，修复后平滑收敛到 85%。

## 两个 Bug

- **Softmax Collapse（坍塌）**：标准实现要算 $1 + e^{-m}$（$m$ 为 logit margin）。一旦 $m$ 越过"精度悬崖"（bf16 ≈ 5.5、fp32 ≈ 16.6、fp64 ≈ 36.7），$e^{-m}$ 加到 1 上被舍入吞掉，目标梯度精确归零，而非目标梯度仍为正——梯度之和不再为零，被 Adam 的归一化放大成训练事故。
- **Softmax Cancellation（对消）**：蒸馏中分别算 $\mathbf{q}$ 和 $\mathbf{p}$ 再相减，会发生灾难性对消，且前向 softmax 与反向 log-softmax 路径不一致，留下非零"幽灵梯度"——bf16 下高达 $10^{-3}$。

## 修复思路：永远不要对微小量加 1

让微小量始终在 0 附近求值，用 softplus / expm1 / log1p 三件套在 log 空间重写：hard-target 损失直接写成 $\operatorname{softplus}(-m)$，autodiff 自动保证梯度零和；蒸馏则从 logit 差出发在 log 空间算出 $\mathbf{q} - \mathbf{p}$，学生等于老师时梯度严格为零向量。无需转换到更高精度。

## 破案：Slingshot 竟是浮点 Bug

机制链条：margin 越过悬崖 → 目标梯度消失 → Adam 二阶矩 $\hat{v}$ 指数衰减 → 少数样本被拉回、梯度突然恢复 → 除以极小的 $\sqrt{\hat{v}} + \epsilon$ 产生巨大步进 → 损失尖峰，循环重演。修复后尖峰彻底消失，修复 CE 在 5 个种子上全部 Grok 到 100%，标准 CE 只有 94±5%。

## 意外收获：Margin 平衡定律

修复后揭示出 AdamW + 权重衰减下 logit margin 收敛到 $m^\star \approx \log(1/\epsilon)$。默认 $\epsilon = 10^{-8}$ 的平衡点 18.4 恰好落在 fp32 悬崖（16.6）上方——一个"无害默认值"与浮点悬崖构成的完美风暴。该定律在横跨 24 个数量级的 $\epsilon$ 扫描中逐点验证。

## 实验结论

- 模块化加法任务：修复版在 bf16 / fp32 / fp64 三种精度下全部稳定达到 99–100% 测试准确率；对照方法 Zero-sum Proj. 准确率跌破 50%，StableMax 的 margin 膨胀到 $10^3$–$10^4$。
- 四个 Grokking 基准：修复后的 fp32 训练曲线与 fp64 标准实现几乎重合——等价于双精度效果，却不付双精度代价。
- 蒸馏实验：修复版三种精度下全程钉在 KL = 0、100% 准确率；标准实现 bf16 下学生被幽灵梯度"拐跑"，准确率在 45%–90% 间剧烈震荡。

作者坦承极端场景在常规训练中不常见，这个补丁更像"基础设施级"保险——成本几乎为零，却能在高置信度预测、近距离蒸馏、低精度训练中兜底。它也提醒我们：面对诡异的训练动力学，先怀疑数值实现，再发明新理论。
