# ReaDy：把混合线性注意力模型的“循环状态”变成投机解码的动态上下文

投机解码是当前大模型推理加速的主流手段，但现有 drafter 只能依赖目标模型的 hidden features，未必包含后续草拟位置真正需要的上下文。ReaDy 首次把混合线性注意力（HLA）模型的**循环状态（recurrent states）**用作草稿阶段的补充上下文来源：在 Qwen3.8-27B、单张 NVIDIA B200 的七个基准上，相对自回归解码平均加速 **3.16 倍**，相比强基线 DSpark 吞吐再提升 **7.97%**，且七个基准无一落后。

## 为什么循环状态是第三条路

现有 drafter 的上下文来源各有短板：

- **Target hidden features**（EAGLE、DSpark）：反映的是目标模型在已观测位置“挑选”出的上下文，草拟块后部位置需要的关系未必被强调；
- **直接查 KV cache**（GliDe、LongSpec）：信息更全，但读取量随前缀长度线性增长，I/O 开销大。

HLA 模型的循环状态是**固定大小**的矩阵，紧凑积累历史关联，读取无需扫描不断增长的缓存。论文用两个命题支撑设计：其一，query 决定信息可见性——只要新 query 有正交于已有读出子空间的分量，就能拿到 hidden features 里没有的信息；其二，未来第 j 步读出中来自已提交前缀的贡献，恰好等价于用“有效 query”去读当前状态——因此为每个草拟位置学习专属 query 在数学上有据可依。

## 方法：位置条件化的状态读取

ReaDy 建立在 DSpark 之上，在最后一个草稿层新增一条状态读取路径：

- **低秩读取**：草稿表示经 rank-8 瓶颈投影形成 query，状态 value 维同样压到 rank 8；每次读出仅 8 维，最贵的“压缩状态”操作一个 block 只做一次，所有位置共享；
- **残差注入**：读出与 log-RMS 状态尺度特征拼接后经瓶颈 MLP 映射，以残差方式注入，分工明确——状态提供增量上下文，续写建模仍归 drafter 主干；
- **不改验证规则**：只读取与已提交 token 关联的状态，被拒续写的状态不保留；
- **工程优化**：融合 gather 内核使状态 gather 延迟降 71.8%、读取延迟降 28.1%，把固定大小状态的理论优势落到端到端吞吐上。

训练采用两阶段：先冻结 drafter 只训 state reader（20k 样本），再联合训练 reader 与 drafter 的 LoRA（50k 样本），目标模型全程冻结。

## 实验：七个基准全面提升

- 平均吞吐 302.78 tokens/s，对比 AR 的 95.86 为 3.16 倍加速；对比 DSpark 的 280.42 提升 7.97%，接受长度从 4.17 升到 4.53（+8.50%）；
- 对话类收益最大（MT-Bench +9.45%、Alpaca +9.83%），数学代码类提升 6.4%–8.7%；
- 前缀存活曲线每个位置都高于 DSpark：第 7 位存活率 GSM8K 从 45.98% 升到 58.17%，完整 7-token 块“整块通过”比例显著提高；
- **对照严谨**：“无状态访问的微调”只带来 2.17% 吞吐提升，ReaDy 在此基础上再提升 5.68%，把训练配方与状态读取的贡献干净分离。

## 消融：每分开销都有账

- **Reader rank**：8 是甜点，提到满秩 128 接受长度仅微升而吞吐增益反降；
- **状态来源层**：深层循环层最有用，(30, 62) 组合最佳，再加浅层反而掉到 6.22%；
- **注入层数**：只在最后一层注入一次即可，多装读入器只增开销不增接受；
- **注入位置**：post-attention 优于 pre-attention。

ReaDy 开启的思路——把目标模型的内部状态当作可查询的上下文服务——不止适用于 HLA，也值得在其他带紧凑记忆结构的模型上探索。
