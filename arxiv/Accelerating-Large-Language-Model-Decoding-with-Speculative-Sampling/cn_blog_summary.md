# Speculative Sampling：不改模型，解码提速 2.5 倍

大模型必须逐 token 自回归生成，且解码是内存带宽受限的——单 token 延迟正比于「模型参数量 / 总内存带宽」，模型越大越慢。DeepMind 的 Speculative Sampling（SpS，投机采样）用一个漂亮的思路破解：小模型先起草、大模型并行验收。在 Chinchilla 70B 上实现 **2~2.46 倍解码加速，且输出分布与原模型严格一致、不改模型不掉精度**，甚至突破了自回归采样的理论速度上限。

## 关键观察：多带几个 token 几乎免费

大模型一次前向调用「起步价」极贵，但并行给 K 个 token 打分和只采样 1 个 token 的延迟几乎相同——线性层、KV-Cache 的带宽开销与 K 无关，all-reduce 通信也是延迟受限而非吞吐受限。只要有个便宜来源提前猜出几个靠谱 token，大模型每次调用就能验收一整段。

## 方法：起草—打分—验收三步走

- **起草**：小模型（draft model）自回归生成 K 个候选 token；
- **打分**：目标模型一次并行算出 K+1 组 logits；
- **验收**：用改进的拒绝采样从左到右逐个决定草稿去留。

验收规则是数学核心：给定草稿 token $\tilde{x}$，以 $\min(1, q(\tilde{x})/p(\tilde{x}))$ 的概率接受（p、q 分别为草稿与目标模型的概率）；被拒则从 $(q-p)_+$ 归一化后的分布重采样。两个效率细节：

- 每轮保底 1 个 token，不会空转；
- K 个草稿全接受时还能从第 K+1 组 logits 白赚 1 个 token，一轮最多产出 K+1 个。

无损性证明只需几行：草稿被接受贡献 $\min(p,q)$，被拒重采样贡献 $\max(0, q-p)$，两者相加恰好等于 $q(x)$——输出分布与目标模型严格一致。nucleus、top-k、温度等策略只需先修改 p、q 再套用同样规则，且可与量化、MQA 等加速手段叠加。

## 工程要点与实验结果

草稿模型不是越小越好：现成的 7B 放到 16 张 TPU 上会因通信开销反而变慢，作者专门训练了宽而浅的 4B 模型（8 层，1.8ms/token），刚好跑满与 70B（14.1ms/token）相同的 16 卡硬件。在 batch size 1、K=4 下的实测：

- **XSum 摘要**：7.52ms/token（nucleus），加速 **1.92 倍**，greedy 下 2.01 倍，ROUGE-2 基本持平；
- **HumanEval 代码**：5.73ms/token，加速 **2.46 倍**，指标不降反升（45.1% → 47.0%）——代码含大量常见子序列，草稿容易猜中；
- 有效生成速度超过「模型大小/内存带宽」的自回归理论天花板。

超参数 K 并非越大越好：接受效率随 K 单调下降（一拒全废），起草耗时随 K 线性增长，XSum 在 K=3 处最优，过大的 K 还会推高延迟方差，影响 P90/P99。

## 小结

SpS 用「小模型起草 + 大模型并行验收 + 改进拒绝采样」实现了完全无损的推理加速，且正交于各类现有优化。其局限是需要额外训练草稿模型、加速比依赖两模型的分布契合度；它开启的自投机、树形草稿等方向，此后已成为大模型推理加速最活跃的领域之一。
