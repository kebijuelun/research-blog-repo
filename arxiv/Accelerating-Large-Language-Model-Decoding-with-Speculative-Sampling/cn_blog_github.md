# Speculative Sampling：不改模型，解码提速 2.5 倍

大模型生成文本必须一个 token 一个 token 地往外蹦，模型越大，每个 token 的等待时间越长——这是所有低延迟部署场景的共同痛点。DeepMind 这篇工作提出的 Speculative Sampling（投机采样，简称 SpS）给出了一个漂亮的解法：让一个小的“草稿模型”先猜出若干个 token，再让大模型一次性并行打分验收，用一套改进的拒绝采样保证输出分布与大模型完全一致。在 700 亿参数的 Chinchilla 上，SpS 拿到了 2 至 2.5 倍的解码加速，且 **不改模型、不掉精度** ，甚至突破了内存带宽给自回归采样划定的理论速度上限。

## 一、提出问题：自回归解码为什么慢

Transformer 的训练可以高度并行，但推理时的采样（Sampling）是自回归的：给定前缀 $x_1, \dots, x_n$，调用一次模型只能吐出下一个 token $x_{n+1}$。想生成 $T$ 个 token，就得串行调用 $T$ 次。

更麻烦的是，解码过程是 **内存带宽受限（memory bandwidth bound）** 的，而不是算力受限。每生成一个 token，模型的全部参数至少要在加速芯片的显存里过一遍。于是一个粗略但坚硬的结论是：

$$
\text{单 token 延迟} \propto \frac{\text{模型参数量}}{\text{总内存带宽}}
$$

模型越大，这个延迟越高。而且大模型还必须用模型并行切到多张卡上，每层之间的通信又叠加了额外开销。加速器昂贵的计算单元在解码时大量空转——这就是 SpS 要撬动的杠杆。

## 二、分析问题：一次调用，其实能“顺便”算多个 token

SpS 的第一个关键观察是： **用大模型并行给一段长度为 $K$ 的短草稿打分，和只采样一个 token 的延迟几乎相同** 。

为什么？作者把 Megatron 式分布式大模型的采样耗时拆成三块，逐块分析：

- **线性层** ：小 batch 下，前馈层、QKV 投影等 dense 矩阵乘是内存受限的。从处理 1 个 token 变成处理 $K$ 个（$K$ 很小），需要搬运的参数量不变，耗时基本不变。
- **Attention 机制** ：解码靠 KV-Cache 避免重复计算，KV-Cache 的大小只取决于已有序列长度，与 $K$ 无关，所以这一块的带宽开销也没有增量。
- **All-reduce 通信** ：模型并行在每层之后都要做一次 all-reduce，但传输的只是少量 token 的激活值，属于延迟受限而非吞吐受限，打分和采样的通信耗时也几乎一样。

换句话说，大模型一次前向调用的“起步价”极贵，但“多带几个 token”几乎是免费的。既然如此，只要有一个便宜的来源能提前猜出几个靠谱的 token，就能让大模型每次调用验收一整段，而不是吐一个字。这正是“投机”二字的由来。

## 三、解决问题：Speculative Sampling 三步走

解决了“能不能并行验收”之后，下一个问题是：怎么保证验收后的输出仍然服从大模型的分布？SpS 的完整流程分三步：

1. **起草（Draft）** ：用一个更快的小模型（ **草稿模型** ，draft model）自回归地生成 $K$ 个候选 token $\tilde{x}_1, \dots, \tilde{x}_K$；
2. **打分（Score）** ：用 **目标模型** （target model，即我们想从中采样的大模型）一次性并行计算 $K+1$ 组 logits，即 $q(x \mid x_1,\dots,x_n)$、$q(x \mid x_1,\dots,x_n,\tilde{x}_1)$，直到 $q(x \mid x_1,\dots,x_n,\tilde{x}_1,\dots,\tilde{x}_K)$；
3. **验收（Accept/Reject）** ：用一套改进的拒绝采样，从左到右逐个决定草稿 token 的去留。

直觉上，文本中经常有“下一个词很明显”的位置（比如代码里的 `for i in range(len(arr)):`）。如果草稿模型和目标模型在这些位置上的分布高度一致，草稿就会被整段接受， **大模型一次调用就产出多个 token** 。

### 改进的拒绝采样：无损的关键

这一步是整个算法的数学核心。给定前缀 $x_1, \dots, x_n$ 和草稿 token $\tilde{x}_{n+1}$，以如下概率接受它：

$$
\min\left(1, \frac{q(\tilde{x}_{n+1} \mid x_1, \dots, x_n)}{p(\tilde{x}_{n+1} \mid x_1, \dots, x_n)}\right)
$$

其中 $p$ 和 $q$ 分别是草稿模型和目标模型给出的条件概率。规则很直白：目标模型比草稿模型更看好这个 token（$q \ge p$），就必然接受；否则按概率 $q/p$ 接受。

如果被拒绝，则从“差值的正部”分布中重新采样一个 token，并结束本轮验收：

$$
x_{n+1} \sim \left(q(x \mid x_1, \dots, x_n) - p(x \mid x_1, \dots, x_n)\right)_{+}
$$

这里 $(f(x))_{+}$ 表示截断归一化：

$$
(f(x))_{+} = \frac{\max(0, f(x))}{\sum_x \max(0, f(x))}
$$

还有两个让效率更进一步的设计细节：

- **每轮保底一个 token** ：即使第一个草稿 token 就被拒，也会从重采样分布中得到一个合法 token，所以一轮循环至少前进一格，不会出现空转。
- **白赚一个 token** ：如果 $K$ 个草稿全部被接受，由于打分阶段已经算出了 $K+1$ 组 logits，可以直接从最后一组里再采一个 token。一轮最多产出 $K+1$ 个 token，而非 $K$ 个。

笔者认为这个设计的聪明之处在于：它把经典的拒绝采样“嵌入”到了自回归的链式结构里——接受则继续前进、拒绝则就地修正，每一步都严格校准到目标分布，而打分所需的全部 logits 在那一次并行前向里已经备齐了，没有任何重复计算。

另外，nucleus、top-k、温度调节等常用解码策略，只需先修改 $p$ 和 $q$ 的概率再套用同样的验收规则即可，作者观察到接受率对这些参数并不敏感。而且由于完全不触碰 Transformer 本体，SpS 可以和量化、Multi-Query Attention 等加速手段叠加使用。

### 为什么它是无损的：一个简短的证明

附录中定理证明了这个方案能精确恢复目标分布。核心推导只需几行：设草稿 $\tilde{x} \sim p$，最终输出为 $X$。$X = x$ 有两条路径——草稿恰好是 $x$ 且被接受，或者草稿被拒后重采样到 $x$。

第一条路径的概率是：

$$
\mathbb{P}(\tilde{x} = x) \cdot \mathbb{P}(\text{接受} \mid \tilde{x} = x) = p(x) \min\left(1, \frac{q(x)}{p(x)}\right) = \min(p(x), q(x))
$$

而草稿被拒绝的总概率恰好等于重采样分布的归一化分母：

$$
\mathbb{P}(\tilde{x} \text{ 被拒}) = 1 - \sum_{x'} \min(p(x'), q(x')) = \sum_{x'} \max(0, q(x') - p(x'))
$$

因此第二条路径的概率为 $\max(0, q(x) - p(x))$。两条路径相加：

$$
\mathbb{P}(X = x) = \min(p(x), q(x)) + \max(0, q(x) - p(x)) = q(x)
$$

输出分布与目标模型 **严格一致** （仅受硬件数值精度影响）。这意味着 SpS 拿到的加速是“免费”的——不以任何采样质量为代价，这是它与各类有损加速方案最本质的区别。

## 四、草稿模型怎么选：不是越小越好

分布一致性由验收机制兜底，所以草稿模型的选择非常自由，唯一的约束是： **接受率要够高、自身延迟要够低，能覆盖起草的开销** 。

论文讨论了几条路线：在目标模型里加多个输出头从头训练、用序列级蒸馏训一个能并行预测 $K$ 个 token 的模型、把目标模型的中间激活作为草稿模型的输入等。这些方法草稿质量可能更高，但要么改动目标模型，要么需要大量蒸馏数据和算力，大规模落地不划算。

作者的选择是： **直接用同系列的小模型当草稿** 。这里有个反直觉的工程细节——不能直接拿现成的 7B 模型：

- Chinchilla 70B 通常在 16 张 TPU v4 上服务，延迟 14.1ms/token；
- 一个 Chinchilla 最优配置的 7B 模型，最低延迟是在 4 张 TPU v4 上取得的（5ms/token）；把它放到 16 张卡上，额外的通信开销反而让它 **更慢** 。

于是作者专门训练了一个 **宽而浅** 的草稿模型：宽度接近大模型、只有 8 层，刚好能跑满和目标模型相同的 16 卡硬件，同时把层间通信压到最低。此前有研究表明语言模型性能对深宽比相当鲁棒，所以这种“矮胖”结构并不牺牲多少预测能力。最终配置对比如下：

| 模型 | $d_{model}$ | Heads | Layers | 参数量 | 采样延迟 |
| --- | --- | --- | --- | --- | --- |
| Target（Chinchilla） | 8192 | 64 | 80 | 70B | 14.1ms/token |
| Draft | 6144 | 48 | 8 | 4B | 1.8ms/token |

草稿模型与大模型使用相同的 tokenizer 和训练数据，训练基础设施完全复用——从工程视角看，这是整条路线里最省事的选择。

## 五、实验验证：2 倍起步，代码任务 2.46 倍

作者在 Chinchilla 70B 上、batch size 为 1、$K=4$ 的设置下评测了两个任务：XSum（1-shot 新闻摘要，nucleus 参数 $p=0.8$，采样 11305 条、最长 128 token）和 100-shot HumanEval（代码生成，$p=0.95$、温度 0.8，采样 16400 条、最长 512 token）。结果如下：

| 采样方法 | Benchmark | 指标结果 | 单 token 平均耗时 | 加速比 |
| --- | --- | --- | --- | --- |
| ArS（Nucleus） | XSum（ROUGE-2） | 0.112 | 14.1ms | $1\times$ |
| SpS（Nucleus） | XSum（ROUGE-2） | 0.114 | 7.52ms | $1.92\times$ |
| ArS（Greedy） | XSum（ROUGE-2） | 0.157 | 14.1ms | $1\times$ |
| SpS（Greedy） | XSum（ROUGE-2） | 0.156 | 7.00ms | $2.01\times$ |
| ArS（Nucleus） | HumanEval（100-shot） | 45.1% | 14.1ms | $1\times$ |
| SpS（Nucleus） | HumanEval（100-shot） | 47.0% | 5.73ms | $2.46\times$ |

两组数字都值得细看：

- **加速显著且无损** ：HumanEval 加速比达 2.46 倍，而下游指标不降反微微波动（45.1% 对 47.0%），实证了“分布一致”不是纸面承诺。注意由于随机种子处理方式与计算图不同，逐 token 输出不会完全相同，但分布层面一致。
- **突破理论上限** ：自回归采样的速度天花板是“模型大小除以总内存带宽”。HumanEval 和 greedy XSum 上 SpS 的有效生成速度 **超过了这个天花板** ——因为它把多次模型调用合并成了一次。

HumanEval 的加速比明显更高，作者的解释是：代码含有大量常见子序列（如 `for i in range(len(arr)):`），草稿模型很容易猜中；代码 token 也往往更短、更碎；较低的温度同时锐化了两个模型的分布，进一步抬高了接受率。

### $K$ 的权衡：草稿不是越长越好

$K$（草稿长度）是唯一的核心超参数。直觉上 $K$ 越大，大模型打分次数越少，加速应该越多——但实验给出了否定的答案：

![草稿长度 K 的权衡](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/arxiv/Accelerating-Large-Language-Model-Decoding-with-Speculative-Sampling/figures/speculative_sampling_results_2.png)

> 图解：三张子图的横轴均为草稿 token 数 $K$。 **左图** 是生成 128 个 token 的平均耗时（含标准差阴影）：随着 $K$ 增大，耗时先降后平，XSum（黄线）在 $K=3$ 处最优，继续增大 $K$ 反而回升，且方差持续变大。 **中图** 是每轮接受的 token 数占 $K+1$ 的比例，即拒绝采样机制的整体效率：它随 $K$ 单调下降（后面的 token 依赖前面全部接受，“一拒全废”），HumanEval（蓝线）在各 $K$ 下都高于 XSum。 **右图** 是单个 SpS 循环的总耗时，随 $K$ 近似线性增长（斜率略高于草稿模型自身的采样速度，多出的部分来自 nucleus 解码的额外开销）。

结论很清晰： $K$ 增大带来“更少的打分调用”，但代价是“更长的起草时间”加“更低的整体接受效率”，两相抵消后收益见顶甚至倒退。更大的 $K$ 还会推高整段生成时间的方差——对关心 P90、P99 延迟的线上服务来说，这比平均耗时更要命。

## 六、总结与展望

- **核心思想** ：小模型起草 $K$ 个 token，大模型一次并行打分，用改进的拒绝采样从左到右验收，一次大模型调用最多产出 $K+1$ 个 token。
- **理论保证** ：输出分布与目标模型在硬件数值精度内严格一致，加速完全无损，且与 nucleus、top-k、温度等解码策略兼容。
- **实测效果** ：Chinchilla 70B 上 XSum 加速约 2 倍、HumanEval 加速 2.46 倍，有效速度突破内存带宽理论上限。
- **工程要点** ：草稿模型要按目标硬件定制（宽而浅的 4B、8 层模型跑满同样的 16 张 TPU v4），$K$ 存在任务相关的最优点且不宜过大。
- **正交性好** ：不改动目标模型的参数与架构，可与量化、Multi-Query Attention 等现有优化叠加。

这项工作的局限在于需要额外训练和维护一个草稿模型，且加速比依赖草稿与目标模型的分布契合度；它开启的方向——自投机（self-speculative）、树形草稿、无草稿模型等变体——此后几年已成为大模型推理加速最活跃的领域之一。
