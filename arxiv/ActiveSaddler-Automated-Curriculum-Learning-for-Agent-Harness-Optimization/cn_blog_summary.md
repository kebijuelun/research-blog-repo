# ActiveSaddler 精华总结：给 Agent 的"外挂骨架"上一张活的课程表

自动 Harness 优化（AHO）方法大多只回答"怎么改 Prompt/工具/控制逻辑"，却把"用哪些训练任务驱动修改"在优化开始前就定死。本文首次把这一维度形式化为**自动课程学习**问题，提出 ActiveSaddler：将课程决策建模为臂集合动态扩张的非平稳 Bandit，让训练课程与 Harness 共同进化。结果相当硬：同一优化器下，GAIA2 测试 Pass@1 提升 **+4.4 pp（59.8%）**，Terminal-Bench 2.0 提升 **+7.5 pp（80.0%）**，后者超过人工精调的 Terminus-KIRA 10.8 个点。

## 问题：固定课程表的两大盲区

- **无法响应修复进度**：已修复的失败没有剩余价值，未解决的弱点却可能被过早放弃——固定顺序下，很多训练中暴露的失败到最终 Harness 仍未解决。
- **无法平衡温故与知新**：何时回头修已知弱点（exploit）、何时探索未见任务发现新弱点（explore），其相对价值随优化进程不断变化。

由于每次 rollout 都是真金白银的 LLM 调用，预算有限时，"练什么"与"怎么改"的影响是同等量级的。

## 方法：从失败中在线构建的 Bandit

沿用 AutoSaddler 的离线学习式设定：每轮优化器拿到任务批次的执行记录来打补丁。关键分工是——任务批次 $X_t$ 决定"收集什么证据"，优化器决定"证据怎么变成更新"，ActiveSaddler 专攻前者，且是**即插即用的外壳，底层优化器零改动**。三个核心组件：

- **Failure-Pattern Extractor**：对每条失败先做独立的"症状抽取"（不看现有臂集合，避免锚定偏差），再做三路归一化判定（Same / Composition / New），把失败抽象为"失败模式臂"。臂要求原子性（一个补丁修一个模式）与适度抽象，通过 `pattern` CLI 按需访问注册表。
- **Arm Prioritizer**：LLM 沿四轴给每个臂打学习进度分——严重性、可修复性、广度、副作用风险（取反），四轴均值经 softmax（$\tau=0.15$）随机采样。刻意不贪心，让低分臂在价值变化时仍有机会；且"任务通过 ≠ 模式解决"，防掉 dev 准确率的补丁回滚后仍给高分。
- **Exploration Controller**：LLM 每轮做 Pull/Draw 二分类决策，无固定公式，综合权衡"已知臂是否还有可修目标"与"失败面覆盖度"。另有回归再发现机制：全部任务探索过后，曾通过的任务重新入池，无需全量复测即可捕捉回归。

## 实验：一致、稳健、更省钱

- **设置**：GAIA2 按 Universe 切分考察 OOD 泛化（训练 75 题，测试 300 题全未见环境）；TB2 随机划分 30/19/40。共享 rollout 预算 $K = 10\times(|D_{train}|+|D_{dev}|)$，模型为 gpt-5.5。
- **主结果**：ActiveSaddler 以 59.8% / 80.0% 全面领先 GEPA（54.2/65.8）、Meta-Harness（54.2/66.7）、AutoSaddler 固定顺序（55.4/72.5）及两种"由易到难"课程基线。
- **稳健性**：GAIA2 第二次独立优化达 61.6%，两次均在每个 held-out Universe 上超所有基线；迁移到 GEPA 再涨 +3.0 pp（57.2%），收益不绑定特定优化器。
- **对比机械规则**：TSCL 风格失败残留追踪 56.7%、UCB-AIR 风格计数规则 55.6%，均明显落后——LLM 基于完整优化状态的整体判断优于机械规则。
- **成本效率**：GAIA2 上花 **\$298** 即达 58.5% 开发准确率，AutoSaddler 需 **\$1,360** 才到同一水平——课程层的额外优化器开销被更聪明的 rollout 分配远远赚回，省钱 4 倍以上。

## 消融：三个组件缺一不可

- **臂粒度**：换成类别臂/任务臂，GAIA2 掉 3.0/3.6 pp，TB2 掉 10.8/6.7 pp。失败模式臂的失败命中率 52.9%（GAIA2），远高于类别臂 36.4% 和任务臂 17.6%——粒度选错，不相干任务的成功会掩盖未解决的弱点。
- **臂评分**：去掉后 GAIA2 掉 4.5 pp、TB2 掉 7.5 pp。已解决臂被正确降权（24 个全通过臂只占 26.2% 概率质量），暂时性成功不被当作解决证据，优先级随证据双向流动。
- **探索控制**：换成固定调度掉 4.5/8.3 pp。Draw 率从前半程 44% 自然降到后半程 20%；Pull 时的未解决臂数与 Draw 时之比达 2.0–6.9 倍，而固定调度接近 1。

## 结语

本文的贡献不只是一个方法，更是一个新维度：凡是"预算受限、目标随学习进程漂移"的迭代式优化（prompt 优化、评测任务选择、RL 环境调度），都值得问一句——我的课程表，是死的还是活的？作者同时强调这是研究方法而非生产系统，部署前需补齐安全过滤、权限控制与人工审批。
