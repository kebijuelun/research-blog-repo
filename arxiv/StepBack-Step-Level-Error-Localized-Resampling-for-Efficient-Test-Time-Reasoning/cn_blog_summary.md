# StepBack：推理Token最多省下41%

Self-Consistency 靠反复生成完整推理链投票，却连早已正确的步骤也一遍遍重写；StepBack 把额外计算精确投向“可能出错的那一步”，在相同 32 票预算下保持平均准确率，单个模型—数据集组合最多减少 **41.26%** Token，与 DSC 结合后更在 GSM8K 上用 **5.2 倍更少**的 Token 提高 0.9 个百分点。

## 核心思路：保留前缀，只修后缀

推理错误往往从某个中间步骤开始向后传播，此前的题意理解、已知量整理和计算仍可复用。Oracle 诊断实验验证了这一点：准确知道首个错误时，GSM8K 的 $8\times4$ 配置节省 **64.0%** Token，准确率由 91.21% 升至 91.89%；MATH500 同配置节省 **46.5%**，准确率基本持平。

StepBack 将这一发现变成无需训练的解码算法：

- 先生成多条带步骤的草稿，用空行或编号直接解析步骤。
- 每条草稿只预测一个回退点，保留此前缀，重采样该步骤及其后缀；没有明确错误时，仅重采样最终答案。
- 保留草稿原答案，默认采用 $16\times2$：16 条草稿各贡献原答案和一个修复答案，仍凑齐 32 票做多数投票。各后缀可并行生成，无需多轮回溯。

## 两种轻量定位信号

- **NLL-signal**：计算每步平均 Token 负对数似然，选择第一个相对前一步突增超过阈值的位置。它只使用生成模型已有概率，额外成本低，但“不自信”不必然等于“错误”。
- **PRM-signal**：用过程奖励模型给推理前缀评分，选择第一个分数下降超过阈值的位置。默认使用 Qwen2.5-Math-PRM-7B，阈值 0.05；NLL 默认阈值 0.1，均不逐数据集调优。

定位器只决定“从哪里续写”，不反复判断修复是否成功，因此容易接入现有 SC 流程。

## 实验结论：全面省 Token，但并非精准定位包打天下

实验覆盖 3 个模型、5 个数学与 2 个多跳 QA benchmark，共 4,166 题。PRM-signal 在全部 **21 个**模型—数据集组合上节省 **7.66%–41.26%** Token，其中 14 个准确率提高、1 个持平、6 个下降；NLL 通常回退更晚，在 17 个组合上节省更多，却可能漏掉更早的错误。困难竞赛题上的增益仍不稳定。

消融也给出了克制结论：大部分基础节省来自**前缀复用**，而非完美的首错定位。PRM 的首错 Exact 仅 22.3%，允许提前一步为 32.8%；Final-step 甚至能节省 44.07% Token。定位信号主要提升池化准确率，并在重写票占主导时更有价值。

StepBack 还可与 AC、ESC、DSC 叠加，同时减少候选数量和单候选成本；九种组合的单位 Token 收益全部提高。它真正的启发，是把测试时计算的分配粒度从整条轨迹推进到轨迹内部，同时提醒我们：晚回退是强基线，更可靠、更便宜且能识别“何时该换整条路线”的定位信号仍是下一步。
