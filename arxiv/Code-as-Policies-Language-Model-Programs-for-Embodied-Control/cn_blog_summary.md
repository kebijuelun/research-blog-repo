# Code as Policies：让大模型直接编写机器人控制代码

让机器人执行“向右移一点”“直到看见苹果再停下”，不该意味着为每条新指令重新采数据、训策略。Code as Policies（CaP）让代码大模型直接生成连接感知与控制的 Python 策略：在空间几何任务上，代码推理总体成功率达 **98%**，远高于自然语言 Chain-of-Thought 的 **58%**；在 HumanEval 上，层级生成的 P@1 也从 **34.9%** 提升至 **39.8%**。

## 核心创新：从“排技能”到“写策略”

SayCan 等方法虽能用 LLM 规划，却仍依赖预训练技能。CaP 则生成可执行的 **Language Model Program（LMP）**，统一处理三类工作：

- 接收目标位置、分割 mask 等感知结果；
- 调用机器人控制 API，计算位置、轨迹和速度；
- 用 `if`、`while` 等控制流实现反馈闭环，而非只输出固定技能序列。

Prompt 主要由 **Hints** 和 **Examples** 组成：前者用 import、函数签名说明可用 API，后者提供“指令注释—对应代码”的 few-shot 示例。模型还能复用 NumPy、SciPy 等第三方库，把“最左”“最近”“中心”转成数值运算；历史指令和变量保留在同一会话中，形成短期记忆。

## 层级生成：把未定义函数变成分解接口

复杂策略不必一次写完。CaP 先生成高层代码，再通过 Python 抽象语法树找出未定义函数，调用专门的 LMP 补全，并按深度优先方式递归展开。由此，未定义函数不再是错误，而是继续拆解任务的接口，生成函数还可被后续程序复用。

这一设计收益明确：在包含 37 道题的 RoboCodeGen 上，层级生成在四种模型中全部优于扁平生成，Codex davinci 的通过率从 **81%** 提至 **95%**。在 HumanEval 上，Greedy 从 **45.7%** 提至 **53.0%**，P@100 从 **90.9%** 提至 **95.7%**。不过仅 **6.5%** 的题目触发层级生成；在这部分题目上，成功率为 **56%**，两种扁平方法均为 **44%**，说明收益主要来自更长、更深的代码，且依赖底层模型能力。

## 实验结论：优势集中在精确计算与新指令泛化

- **空间推理**：51 道题中，对象选择成功率为 **96%**，位置选择达 **100%**；位置答案要求所有坐标误差不超过 1 cm。优势来自把多步计算交给 Python，而非让模型心算。
- **仿真操作**：在未见属性、未见指令下，CaP 的 Long-Horizon 成功率为 **80%**，高于 CLIPort 的 **0%** 和自然语言规划器的 **64%**；空间几何任务为 **62%**。CaP 每个任务只需一个示例 rollout，CLIPort 则使用 30k 条示范。
- **并非全面领先**：已见空间几何任务上，CaP 为 **89.3%**，低于 CLIPort 的 **97.33%**；部分堆叠、颜色关系任务也存在更强基线。
- **真实系统**：白板绘画、桌面抓取和厨房移动操作展示了跨任务、跨 API 适配，还能生成简化 PD 与阻抗控制器，但这些开放演示缺少统一量化评估。

## 价值与边界

CaP 不是取消机器人工程，而是把投入从“逐条训练新技能”转向“提供可靠感知、清晰 API 和高质量示例”。它仍受检测误差、已有控制原语、Prompt 质量和代码正确性约束；跨 embodiment 迁移仍脆弱，也不能依据执行反馈在线修代码或调参。下一步的关键，是把真实执行结果纳入生成闭环，让机器人会写策略，也会调试策略。
