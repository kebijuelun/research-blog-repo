# EmbodiedSmith：用"递归自改进飞轮"在仿真中规模化生产具身数据

训练机器人基础模型最缺的是什么？数据和可靠的评估环境。真机数据太贵太少，而现有仿真数据生成流水线又受困于预定义资产、场景生成与任务生成脱节、复杂构型（人形、灵巧手）支持不足、柔体流体物理缺失这四大短板。EmbodiedSmith 提出的核心思路是： **把场景生成和任务生成耦合进一个递归自改进（Recursive Self-Improvement, RSI）的智能体回路** ——场景生成时预先考虑下游任务需求，任务生成失败时反过来编辑场景，二者像飞轮一样互相打磨。效果相当硬核：示范生成的平均成功率（ASR）达到 **67%** ，而最强基线只有 17%–21%；消融实验显示去掉执行反馈后成功率几乎归零；用它生成的多样化数据训练 $\pi_{0.5}$，在随机化场景下的成功率从 7.2% 跃升至 40.2%。

## 一、为什么需要 EmbodiedSmith：仿真数据的"理想与现实"

先建立直觉。机器人数据来源大致有三种：

- **真机遥操作数据** ：与目标硬件最贴合（hardware proximity 高），但采集贵、慢、多样性差；
- **第一人称（egocentric）/ UMI 手持数据** ：便宜且多样，但和机器人的本体、接口对不上；
- **仿真数据** ：理论上三者兼得——可扩展、多样、且能精确对齐目标机器人硬件。

除了当数据源，仿真还天然是低成本、可复现的大规模 **评估环境** 。随着 RSI（递归自改进）技术的发展，仿真环境正在变成机器人基础设施的核心组件。

但现有的仿真生成流水线有四个明显瓶颈：

1. **多样性受限** ：场景和资产来自现成数据集，技能是预定义或规则生成的，无法自定义；
2. **物理不真实** ：对柔体（deformable）和流体支持差，而它们是真实物理世界的重要组成部分；
3. **任务成功率低** ：场景生成和机器人任务规划是 **解耦** 的——场景生成时不知道机器人能不能够得着，规划好的动作是否可行无人验证，任务越复杂、越长程，这个问题越致命；
4. **复杂构型缺失** ：移动操作臂、灵巧手、人形机器人的任务规划很难做，缺了它们，机器人就学不到人类级别的灵巧行为。

EmbodiedSmith 的应对可以概括为四个特性： **高数据多样性** （从物体到布局到场景到任务全部可生成、可用语言驱动）、 **丰富物理仿真** （柔体、流体）、 **RSI 数据生成** （场景与任务互相改进，长程任务也保持高成功率）、 **人类级灵巧性** （支持移动操作臂、人形、灵巧手）。

> 图解：EmbodiedSmith 的整体流程。给定任务描述和机器人本体配置，系统将场景生成与任务生成、执行耦合在一起：(a) 展示了不同数据源在硬件贴合度、多样性、可扩展性三个维度上的权衡——仿真数据是三者兼备的选择；(b)–(d) 则展示了"生成 → 执行 → 反馈 → 修订"的闭环，反馈被用来迭代地修改场景和重新规划任务。

## 二、方法总览：一条贯穿"资产—场景—任务"的生成流水线

给定一个任务规范和目标机器人本体，EmbodiedSmith 通过三个层次产出经过验证的机器人示范数据：

- **环境构建** ：资产生成 → 场景生成 → 场景编辑，产出"为任务而生"的仿真场景；
- **机器人轨迹生成** ：把任务落地为可执行的 Skill DAG（技能有向无环图），并在执行反馈中反复修订；
- **本体扩展** ：通过适配器把同一套规划、验证接口延伸到人形机器人和灵巧手上。

## 三、环境构建：场景是"为任务而生"的

![场景生成流程](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/arxiv/EmbodiedSmith-Scaling-Embodied-Data-through-Recursive-Self-Improvement-Flywheel-in-Simulation/fig/scene_Gen.png)

> 图解：场景生成模块把场景描述、任务指令和机器人配置转换为可直接仿真的 3D 场景。流程包含功能区规划、视觉落地、资产检索与生成、以及经过物理验证的场景与桌面布局优化。

### 3.1 资产生成：一个可持续扩展的"验证过"资产池

现成资产库覆盖面广，但语义标签、坐标约定、度量尺度、几何质量参差不齐；按需 3D 生成能覆盖开放类别，却又常有碰撞几何和物理行为不可靠的问题。

EmbodiedSmith 的做法是维护一个 **可持续扩展的资产池** ，统一管理两类资产：

- **已有资产** ：内置 VLM 根据多视角渲染和元数据，对齐语义类别、规范朝向、坐标系和真实尺度，再做语义正确性、几何完整性、尺度合理性和场景兼容性检查；
- **生成资产** ：检索不到合适资产时，先生成一张与场景风格一致的参考图，经图像编辑控制尺寸、材质和粗结构，再用 SAM3D 重建为带纹理的 3D 资产。随后等比缩放、修复几何缺陷、用自适应凸分解构建碰撞几何，并由 VLM 在类别约束下赋予质量、摩擦系数、杨氏模量等物理参数。

两类资产走 **同一条验证流水线** ：静置、接触、扰动测试一个不通过就修复或重新生成，通过的进入持久资产池跨场景复用。这个设计的聪明之处在于——资产生成不是一次性消耗品，而是越用越丰富的公共库存，既保证质量一致，又摊薄了生成成本。

### 3.2 物理资产生成：关节、柔体、流体三件套

物理资产生成在通用资产流水线之上扩展为三个阶段：

- **构建阶段** ：关节资产走 Articraft 式循环——LLM 迭代编写和修改构建程序，靠编译器和验证反馈收敛，并提前注入下游机器人约束（度量尺度、坐标系、夹爪兼容性、运动范围）。柔体支持分区材质的体素表示（论文实现中采用简化程序表示并做交互稳定性校准），流体资产则把几何与求解器参数绑定，支持倒水等交互；
- **物理验证阶段** ：关节资产检查惯性一致性、关节功能运动、抓取关键点和包容几何；柔体、流体资产接受对应的形变和流动探针测试。未通过的检查触发定向修订，无改善的修改直接回滚；
- **任务验证阶段** ：先用 CuRobo 评估无碰撞运动可行性，再进仿真执行。操作失败时，由一个 **独立于执行者的 agent 角色** 分析遥测数据，判断是任务配置、技能还是资产出了问题，修复后重新验证。

值得注意的是作者的坦诚：柔体资产"释放后恢复不完全"被记录为已知局限而非验收标准。只有同时通过场景检查、运动规划和数据导出的 episode 才会被保留。

### 3.3 场景生成：语义构图与几何求解解耦

给定自然语言描述 $\mathcal{T}$、任务上下文和机器人本体配置 $\mathcal{E}$，场景生成器输出初始场景假设：

$$
\mathcal{S}_0 = (\mathcal{G}, \mathcal{O}, \mathcal{X}, \mathcal{Q})
$$

其中 $\mathcal{G}$ 表示房间边界与建筑开口，$\mathcal{O}$ 是独立物体实例，$\mathcal{X}$ 是它们的六自由度位姿，$\mathcal{Q}$ 是支撑区域与机器人交互约束。

核心设计是 **把开放式的语义构图和确定性的几何求解解耦** ：

1. VLM 先把输入解析为一张 **带类型的关系图** ，显式编码功能分区、静态设施、邻接朝向关系、可用支撑面和机器人接近方向——不直接生成容易冲突的绝对坐标；
2. 资产模块实例化各节点后，按 **"静态环境优先、任务物体随后"** 的层级求解布局：地面设施先组织成局部组合，用 Beam-DFS 搜索联合优化位姿；墙面设施分配到避开门窗的有效墙面；任务物体在父级支撑面的局部坐标系中放置；
3. 整个求解显式约束房间边界、物体非穿插、开口净空、墙面容量、通道连通性和机器人操作空间，并用 CuRobo 验证任务物体对当前本体的 **可达性** 。

这里有个关键的态度转变：$\mathcal{S}_0$ 只是一个 **几何和可达性验证过的初始候选** ，而不是保证可执行的环境。真正的可执行性要交给下游机器人规划与执行来检验，失败反馈回流到 RSI 回路——这正是与传统"场景生成即终点"流水线的本质区别。

### 3.4 场景编辑：低成本的任务适配

许多具身任务共享同一个功能环境，只在任务相关物体上有差异。场景编辑模块在 RSI 回路里复用已验证的环境，避免重复的场景合成开销。

支持的操作包括：任务物体的新增、替换、缩放，支撑面内或跨支撑面的移动，以及面向机器人可达性的放置优化。每项编辑都 **可预览、可追溯** ，并明确标记出哪些物理、可达性和导出检查需要重新验证。

## 四、机器人轨迹生成：五工具智能体的闭环审议

![闭环任务生成与验证](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/arxiv/EmbodiedSmith-Scaling-Embodied-Data-through-Recursive-Self-Improvement-Flywheel-in-Simulation/fig/data_scaling/image.png)

> 图解：机器人任务生成与验证的闭环。(a) 任务指令被落地到场景、机器人配置和可用技能上；(b) Agent 提出技能序列和成功条件，构建并编译候选任务配置；(c) 候选在仿真中执行，通过程序化验收检查评估；(d) 独立 VLM 评审作为补充，失败则触发诊断、修订和再验证；(e) 最终验收后交付可执行配置。

系统由三个角色组成，职责划分非常干净：

- **Task Plan Agent** ：理解任务、做核心决策、提出修复（VLM 驱动）；
- **Harness** ：流程管控者，负责检查一致性、冻结配置、发起独立审查，是整个框架的调度核心；
- **simengine** ：负责真实的仿真解析、执行和记录。

### 4.1 任务落地与规划

规划时可用的原始输入包括：任务 prompt、场景配置文件、本体配置、可用原子技能列表和一张全局视角的场景图。Harness 先对输入做一致性检查并冻结为快照——保证后续规划和验证的依据始终一致。

Agent 据此把任务引用映射到场景实体，绑定原子技能，决定机器人站位、控制器、动作参数和依赖顺序，形成紧凑的 **Skill DAG** 。同时把任务要求翻译成可检查的成功条件，建立"任务要求—动作节点—验证证据"的对应关系。例如"把方块放到托盘上"，既需要 `Place` 动作，也需要最终方块与托盘空间关系的检查。

### 4.2 五个工具撑起整个决策循环

Agent 的一切操作都通过五个高层工具完成，按任务生命周期划分接口：

| 工具 | 职责 |
| --- | --- |
| `inspect` | 提供物体身份、位姿、支撑关系、交互区域和视觉观测，帮助 Agent 定位目标和选择初始站位；执行后启动独立 VLM 评审并返回反馈 |
| `build` | 把落地后的交互组织为 Skill DAG，定义终态、必需事件、安全约束和禁止事件；Harness 检查实体引用、参数、机器人绑定和任务要求覆盖后，编译冻结为 Candidate |
| `run` | 在物理仿真中执行技能 DAG，返回技能结果、物体与附着状态、安全事件和任务检查 |
| `revise` | 依据失败证据修订物体绑定、依赖关系、站位、抓取位姿或运动参数；任务成功判据保持不变 |
| `finish` | 提交成功回合做终态、必需事件、运行时安全和数据完整性的最终检查，通过后保留为示范 |

整个流程是一套颇有"制度设计"味道的审议流程：

- `build` 之后调用 `run` 发起真实仿真，同步记录物体与机器人状态、技能事件、观测、动作和视频；
- 即使第一次 `run` 就通过，Agent 也 **不能直接 finish** ——必须至少调用一次 `inspect`，由独立的 VLM reviewer 复核。这种"复核审议制"大幅提高判断准确性；
- 未通过则调用 `revise`，新草稿必须重新 `build`、重新验证， **新版本不能继承旧版本的通过结论** ；
- 最关键的是：如果 Agent 判断问题出在场景层面（比如核心物体不可达、桌面资产遮挡轨迹），它会反过来调用场景编辑能力修改场景—— **这正是 RSI 飞轮的咬合点** ：场景生成预见任务需求，任务生成反馈场景修订。

## 五、本体扩展：同一套技能接口，适配人形与灵巧手

任务级技能表示、验证流程和执行证据接口在不同本体间共享，本体差异被完全压缩在底层执行适配器里。

**人形机器人（Unitree G1）** 。G1 专属适配器位于共享技能 DAG 之下：移动目标被转换为平面速度与航向参考，交给学习到的平衡行走策略；操作目标保留关节空间/末端执行器表示，由 G1 运动学模型和 CuRobo 求解。在 50 Hz 控制周期下，适配器把 15 自由度下半身和 14 自由度手臂指令合成为 29 自由度全身动作，在四个 200 Hz 仿真步内保持，手部单独下发。所有 G1 特有的映射都锁在适配层，上层技能跨本体完全复用。

**灵巧手（Sharpa Wave + Split ALOHA 移动平台）** 。单侧配置为 6 关节机械臂 + 22 自由度灵巧手。任务专用的接触求解器把物体级交互契约转换为经过碰撞检查的手部姿态与指关节构型；执行时 CuRobo 规划手臂航点、手指关节显式控制，PhysX **逐连杆** 记录接触遥测而非夹爪聚合数据。任务验收采用故障即闭（fail-closed）契约：例如指定的食指指腹必须是首个接触部位，只有明确允许的连杆才能承力，释放、撤回、归位各阶段都有力与位姿门禁。

两个本体的执行都接入同一个五工具智能体循环，全程 **不需要任何人类示范** 即可生成高精度的接触丰富型轨迹。

## 六、实验一（Q1）：生成的场景又好看又"能用"

实验对比五个代表性场景生成基线：Holodeck、LayoutVLM、SAGE、EmbodiedGen V2、SceneSmith。所有方法在相同 20 个室内场景规格上各生成 3 次。感知维度由 GPT-5.5 根据四个渲染视角打 1–10 分（CF 内容功能、SL 空间布局、PP 物理合理性、TF 文本一致性、VQ 视觉质量）；几何维度报告四个指标（COL 碰撞数、NAV 可导航性、OOB 越界数、OPN 开口净空）。

| 方法 | CF↑ | SL↑ | PP↑ | TF↑ | VQ↑ | COL↓ | NAV↑ | OOB↓ | OPN↑ |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Holodeck | 5.56±1.72 | 5.47±1.50 | 6.02±1.09 | 7.32±3.15 | 5.64±0.98 | 0.62±6.24 | 0.9967±0.0073 | 0.37±0.84 | 0.5997±0.2951 |
| LayoutVLM | 5.27±1.84 | 5.32±1.78 | 6.00±1.19 | 7.05±3.66 | 5.50±0.79 | 0.43±0.89 | 0.9954±0.0135 | 0.52±0.70 | 0.5417±0.4147 |
| SAGE | 5.20±1.98 | 5.13±1.60 | 5.92±1.08 | 7.07±3.31 | 5.15±0.78 | 0.35±1.09 | 0.9976±0.0081 | 0.03±0.18 | 0.8500±0.2311 |
| EmbodiedGen V2 | 5.57±1.68 | 5.87±1.65 | 5.43±1.39 | 6.75±3.80 | 5.95±0.98 | 2.37±1.45 | **0.9988** ±0.0052 | 0.19±0.48 | 0.9145±0.1363 |
| SceneSmith | 5.34±1.44 | 6.18±1.38 | 6.59±1.01 | **8.92** ±2.33 | 5.52±0.96 | 2.05±1.87 | 0.9916±0.0217 | **0.00** ±0.00 | 0.9621±0.0742 |

几个值得注意的点：

- CF（7.13 vs 最强基线 5.57）相对提升 **28.0%** ，SL、PP、VQ 分别提升 17.6%、16.5%、23.0%；
- 更关键的是 **功能丰富不以几何可用性为代价** ：碰撞数最低（0.29）、零越界、可导航性持平最优、开口净空最高。一般来说场景越丰富越容易碰撞、堵门、碎片化通行空间，EmbodiedSmith 做到了"内容更满、空间依然可用"——这对具身应用至关重要；
- 定性对比上，Holodeck/SAGE 场景偏稀疏，LayoutVLM 留有大片未利用区域，EmbodiedGen V2/SceneSmith 更丰富但局部布局不一致；本文方法产出的环境致密而结构清晰，功能分区明确、通行空间保留。

## 七、实验二（Q2）：RSI 让困难任务的示范生成成功率翻倍再翻倍

### 7.1 设置与指标

主评测包含 16 个任务：10 个固定底座操作 + 6 个移动操作，各半为短程和长程任务（长程任务多为记忆类任务，如记住杯子—方块配对再复原）。每个任务在相同初始场景上跑 10 次独立 agent 会话（最多 30 轮反馈修订预算），产出的候选计划在 10 个留出的仿真种子上评估。指标为 ASR（平均成功率）、Top-5 ASR（每任务最好五个候选的平均）和 Token（每会话 VLM 输出 token 数）。

### 7.2 与基线的对比

| 类别 | 任务 | SceneSmith+Planner ASR | EmbodiedGen V2+Planner ASR | **EmbodiedSmith ASR** |
| --- | --- | --- | --- | --- |
| 固定-短程 | Open Drawer | 32% | ✗（不支持关节资产） | **78%** |

一个有趣的细节：移动设定下 Cup to Tray 表现更好（导航改善可达性），但 Open Drawer 更差——可抓取的站位未必适合关节约束的开合运动，导航不是万能解药。

### 7.3 消融：执行反馈是命门

| 方法 | Fixed-Short ASR | Fixed-Long ASR | Mobile-Short ASR | Mobile-Long ASR |
| --- | --- | --- | --- | --- |
| w/o Feedback | 4.0% | 0.0% | 0.0% | 0.0% |
| w/o Placement Validation | 48.6% | 13.2% | 67.3% | 47.6% |
| **Ours（完整版）** | **69.4%** | **71.6%** | **70.0%** | **54.0%** |

- **去掉执行反馈，ASR 几乎归零** ——尽管 token 消耗大幅下降。这直接证明了 RSI 闭环是整个系统的命门：一次性生成的计划在真实物理执行中几乎注定失败；
- 去掉站位验证主要打击固定底座长程任务（71.6% → 13.2%），移动任务掉得较少，因为导航可以部分补偿糟糕的初始站位。

### 7.4 跨本体示范

除定量评测外，论文展示了单臂、双臂、人形和灵巧手构型下的专家示范：灵巧手成功完成对抽屉把手的手内抓握并打开抽屉；人形机器人先移动到桌边再操作目标。执行中平台同步记录视觉观测、机器人状态和控制动作，把成功轨迹直接转化为策略学习数据。

## 八、实验三（Q3）：多样性数据真的让模型更泛化

最后一个问题：这些数据能不能用来训模型？

### 8.1 数据构成

作者在书房和厨房两个场景从零规划，各设计 5 个任务（覆盖 pick、place、open 等原子技能，长度 3–6 个原子动作），任务计划全部由 prompt 直接生成、 **零人工调试** 。收集两批数据并构成两个等长数据集：

- **clean** ：20 小时固定布局、不开随机化的数据；
- **mixed** ：10 小时固定布局 + 10 小时开启随机化、桌面布局变化的数据。

随机化机制分三层：资产组合（干扰物类别/实例/数量采样）、空间布局（受净空、支撑区和操作保留区约束的位姿采样）、观测与初始条件（光照、背景纹理、相机位姿、机器人基座扰动）。组织方式为 "big group（资产组合）— small group（布局）— episode" 三级结构，配合执行反馈驱动的逐级重采样：单条失败重采 episode 条件，连续失败换布局，整组失败换资产组合——保证随机化开启后仍能达到采集配额。

![随机化数据采集](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/arxiv/EmbodiedSmith-Scaling-Embodied-Data-through-Recursive-Self-Improvement-Flywheel-in-Simulation/fig/random.png)

> 图解：开启桌面干扰物随机化和光照/纹理随机化后的积木堆叠任务数据采集示例。同一任务在不同资产组合、布局和观测条件下产出多样化轨迹。

### 8.2 结果：clean 数据"死记硬背"，mixed 数据真正泛化

用两个代表性模型 $\pi_{0.5}$（VLA）和 FastWAM（WAM）分别在两个数据集上微调，在两种设定下评估： **simple** （与 clean 采集时相同的布局）和 **random** （随机种子控制的环境泛化，所有种子预先经专家执行器验证可行后固定）。

| 模型/数据 | Simple | Random | 平均 |
| --- | --- | --- | --- |
| $\pi_{0.5}$ (Clean) | 61.2% | 7.2% | 34.2% |
| $\pi_{0.5}$ (Mixed) | 50.8% | 40.2% | **45.5%** |
| FastWAM (Clean) | 25.5% | 1.0% | 13.3% |
| FastWAM (Mixed) | 20.4% | 10.2% | **15.3%** |

结论非常清晰：

- clean 数据训练的模型在 simple 环境表现不错，但到 random 环境成功率 **暴跌** （61.2% → 7.2%）——某种程度上说明模型学到的是"图像与轨迹的对应"而非真正的操作策略；
- mixed 数据在 simple 上略有损失，但在 random 上 **大幅提升** （7.2% → 40.2%），平均成功率全面反超。数据多样性对泛化的助益是实实在在的，这套引擎具备作为大规模预训练数据源的潜力。

## 九、附录要点速览

**数据采集统计** （10 个策略训练任务）：原子动作数 3–6 个，单条平均时长 13.4–49.8 秒，收集成功率 70.6%–97.3%。其中海绵擦拭（Sponge Wiping）最难（75.54%，平均 49.8 秒），方块放置（Cuboid Placement）最高（97.32%）。

**训练超参数** ：$\pi_{0.5}$ 用 batch 256、学习率 $5 \times 10^{-5}$、恒定调度（10k warmup）、最多 20k 步；FastWAM 用 batch 64、学习率 $1 \times 10^{-4}$、余弦衰减（5k warmup，100k 调度）、最多 70k 步。

**原子技能库** （仿真执行层支持 23 个参数化技能，节选）：`navigate`（底盘移动）、`pick`/`manualpick`/`dexpick`/`dynamicpick`（多种抓取，含运动目标抓取）、`place`/`dexplace`（放置）、`open`/`close`/`rotate`（关节物体操作）、`press`（按压按钮）、`move`（平面推移/擦拭）、`flip`（翻转）、`pour_water`（倒水并验证结果）等。可以看到技能库本身就为柔体流体和复杂交互预留了接口。

**十个策略评估任务** ：书房侧包括空间指引放置、长方体定向放置（朝向误差 ≤ 15°）、积木堆叠（释放后稳定 1 秒以上才算）、拆堆再放（必须保留"先移走上层"的顺序证据）、开抽屉（沿真实滑轨拉约 7 cm）；厨房侧包括顺序放置、扶正调料瓶、套碗、关微波炉门（关至距零位 5° 内）、海绵擦拭（必须保留接触与路径覆盖证据）。

## 十、总结

- EmbodiedSmith 把 **资产、场景、任务三级生成** 统一进一条流水线，支持全自主生成和语言驱动自定义；
- 核心创新是 **RSI 飞轮** ：场景生成预见任务需求，任务生成反向编辑场景，消融证明去掉执行反馈成功率几乎归零；
- 场景质量在 7/9 项指标上 SOTA（CF 相对提升 28%），且功能丰富不以几何可用性为代价；
- 示范生成平均 ASR **67%** ，是基线的 3 倍以上，长程记忆类任务上差距尤为悬殊，token 消耗反而更低；
- 支持移动操作臂、人形（G1）、灵巧手（Sharpa Wave）及柔体流体交互，无需人类示范即可产出接触丰富型轨迹；
- 下游策略实验证明：混合多样化数据训练的模型在随机场景下成功率从 7.2% 提升到 40.2%，多样性数据确实买来泛化能力。

一句话展望：EmbodiedSmith 展示了"场景与任务联合迭代精炼"这条路径的潜力，但柔体交互的物理保真度、灵巧操作的双臂协调与跨场景泛化仍未完全解决——把这套 RSI 引擎接入真实机器人的预训练闭环，或许才是这个飞轮真正开始加速的时刻。
