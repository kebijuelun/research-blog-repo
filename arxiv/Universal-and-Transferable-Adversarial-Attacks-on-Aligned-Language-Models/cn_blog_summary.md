# GCG：搜索通用对抗后缀，跨模型攻击对齐语言模型

这篇工作解决了一个关键安全问题：经过对齐训练、本应拒绝有害请求的语言模型，能否被自动生成的输入稳定绕过？GCG 让攻击摆脱人工“越狱话术”，实现批量搜索与跨模型迁移；它在 Vicuna-7B 上对单条 Harmful String 的精确诱导成功率达 **88%**，后缀集成在黑盒 GPT-3.5、GPT-4 上分别取得 **86.6%** 和 **46.9%** 的攻击成功率。

## 核心方法：梯度筛选，前向传播决策

- **优化肯定回答的开头**：攻击者不修改原始请求，只在其后附加可优化的离散 Token。目标不是生成唯一的完整有害答案，而是让模型先输出“肯定并复述原请求”的短语，如“Sure, here is …”。这既扩大可行解空间，也避免模型仅靠改变话题获得“Sure”。损失定义为该目标开头的负对数概率。
- **高效搜索离散后缀**：穷举每个位置的整个词表计算量过大。GCG 用当前 Token 的 One-hot 梯度，为所有可修改位置分别选出 Top-$k$ 个候选，再随机采样 $B$ 个单点替换，通过真实前向传播计算损失，采用最佳候选。简言之，梯度负责缩小范围，模型本身负责最终裁判。
- **让所有位置竞争更新**：AutoPrompt 预先选定位置，GCG 则在相近计算预算下同时考虑所有坐标。默认对比中，各方法优化 20 个 Token、运行 500 步；AutoPrompt 与 GCG 的 Batch Size 为 512，Top-$k$ 为 256。

## 从单条请求到通用、可迁移攻击

同一后缀被拼接到多个训练请求后，GCG 聚合各请求梯度并最小化总损失。梯度聚合前分别裁剪为单位范数，避免单个请求主导搜索；请求则逐步加入，当前后缀能攻击已加入请求后才扩展，形成课程式优化。多个共享 Tokenizer 的模型也可联合训练，例如 Vicuna-7B 与 Vicuna-13B。

这里要区分两种能力：**多请求通用**是同一后缀覆盖不同行为，**跨模型迁移**是后缀对未参与优化的模型仍有效。

## AdvBench 与白盒结果

作者构建 AdvBench，包含两类各 500 条的数据：

- **Harmful Strings**：要求模型输出与目标完全一致的字符串；使用 LLaMA Tokenizer 后长度为 3～44 Token，平均 16 Token。
- **Harmful Behaviors**：不要求逐字匹配，只要模型实际遵从有害指令而非拒绝或回避即算成功；通用攻击另报告留出请求结果。

白盒实验中，GCG 对 Vicuna-7B、LLaMA-2-7B-Chat 的单字符串精确诱导 ASR 分别为 **88%**、**57%**，AutoPrompt 仅为 25%、3%，PEZ 和 GBDA 均为 0。对 LLaMA-2 的留出 Behaviors，GCG 通用后缀测试 ASR 为 **84%**，AutoPrompt 为 35%。不过 AutoPrompt 在 Vicuna 开放行为任务上并不弱，通用后缀测试 ASR 与 GCG 同为 98%，因此 GCG 并非所有设置都数量级领先。

## 黑盒迁移：广泛，但不均匀

研究者用 Vicuna，进一步加入 Guanaco 模型，在 25 个请求上联合优化后缀，再测试未参与训练的商业模型。集成依次尝试三个短后缀及连接版本，任一成功即停止，最终 ASR 为：GPT-3.5 **86.6%**、GPT-4 **46.9%**、Claude-1 **47.9%**、Claude-2 **2.1%**、PaLM-2 **66.0%**。其中 PaLM-2 每次检查 8 个候选回答，口径与确定性解码不同。

多模型训练并非单调增益：加入 Guanaco 后，Claude-1 单后缀 ASR 从 2.6% 升至 37.6%，GPT-4 却从 34.5% 降至 29.1%。继续降低源模型损失也不必然增强迁移，训练过长可能过拟合；源模型与目标模型的数据或蒸馏关系同样可能影响结果。

## 结论与防御启示

GCG 表明，对齐评估不能只防自然语言越狱，还要持续抵抗自动搜索。部分后缀含有可解释结构，但并非都能被人类理解；迁移效果也依赖模型版本、输入形式和解码设置，不能外推为当前系统的表现。防御可探索对抗训练、输入检测和更多对齐训练，但计算成本、正常能力与适用威胁模型之间的平衡仍未解决。
