# Qwen：3T Token 训练通用与专长模型

通用大模型要进入真实开发流程，必须兼顾语言、推理、代码、对话与工具调用；Qwen 以“统一底座＋分层训练”回应这一挑战，Qwen-14B 取得 MMLU 66.3、C-Eval 72.1，Code-Qwen-Chat-14B 的 HumanEval pass@1 更达到 66.4。

## 预训练：质量、多语言与架构协同

- **统一模型谱系**：以最多 3T Token 训练 1.8B、7B、14B 基础模型，再通过 SFT、RLHF 和领域继续训练派生对话、代码、数学及视觉语言模型，复用底座并分配后续训练成本。
- **系统清洗数据**：覆盖网页、百科、书籍和代码，经过正文抽取、语言识别、精确与模糊两级去重、质量安全过滤、优质来源上采样，并混入指令数据；所报告评测的指令样本移除与测试集存在 13-gram 重叠的数据。
- **多语言 Tokenizer**：BPE 词表扩至约 152K，加入中文及多语言字符并拆分数字位，以更高 Embedding 开销换取更好的多语言压缩率，初步实验未发现下游表现受损。
- **LLaMA 式改造**：采用不共享的 Embedding 与输出投影、FP32 RoPE、QKV Bias、Pre-Norm/RMSNorm 和 SwiGLU；训练使用 Flash Attention、AdamW 与 BF16 混合精度。

## 长上下文：免训练扩展至 16384

Qwen 组合动态 NTK-aware interpolation、LogN-Scaling 与分层 Window Attention，分别处理位置插值、注意力熵和不同层的长度敏感性，将 2048 训练上下文扩展到 16384。原始 Qwen-7B 在 4096 长度时 PPL 已达 39.35，组合方法在 16384 长度仍为 4.32；Qwen-14B 则为 3.42。不过，PPL 稳定并不自动等于长文检索和推理可靠。

## 基础能力与对齐：领先有边界

Qwen-14B 在 MMLU、C-Eval、GSM8K、MATH、HumanEval、MBPP、BBH 七项基准上全部超过此前 13B 开源模型，并在 C-Eval、MATH、HumanEval 上超过 LLaMA2-70B，但整体仍落后 GPT-3.5 和 GPT-4，也并非每个细分任务都领先。

对齐阶段，SFT 使用多风格对话、安全数据和 ChatML，屏蔽 system/user 损失；RLHF 先经偏好预训练与高质量偏好微调构建 Reward Model，再用 PPO 优化，并以约 6600 个细粒度标签覆盖复杂需求。加入预训练梯度用于缓解“对齐税”，在人类偏好与基础能力间保持平衡。

## 工具与 Agent：从回答走向执行

团队用 self-instruct 构造约 2000 条 ReAct 工具样本，直接与通用 SFT 数据混合。面对训练中未出现的工具，Qwen-14B-Chat 的选择准确率达 98%、输入 Rouge-L 达 93%，错误调用率降至 2.4%。代码解释器任务中，其总体可执行率为 81.7%，数学与可视化正确率分别为 58.4% 和 56.4%，优势不仅是写代码，更是“规划—调用—观察—调整”。

## 领域专训：代码与数学各走一路

- **Code-Qwen**：在通用底座上追加约 90B 代码 Token，并将上下文扩至 8192。14B-Chat 的 HumanEval 从 43.9 升至 66.4，MBPP 从 46.4 升至 52.4，六种语言平均 pass@1 为 51.9。
- **Math-Qwen**：以增强数学指令做 SFT，仅对回答计算损失。14B 的 GSM8K、MATH 分别达 69.8、24.2，Math401、Math23K 达 85.0、78.4；后两项超过表中 GPT-4，但前两项仍明显落后。

Qwen 的核心贡献不是发明单个组件，而是整合数据清洗、多语言预训练、免训练长上下文、偏好对齐、工具学习与领域专训。函数级代码测试、复杂数学和偏好评测仍不能代表完整工程能力，推理可靠性与真实任务完成率仍是后续关键。
