# GoalScope：定位并干预大模型的子目标编码

这项研究要回答的是：多步任务中，大模型内部是否存在可定位、读出并因果干预的“下一步目标”，而非仅仅表现得有计划。最亮眼的结果是，子目标编码跨 Python/C++ 移植后，在 `indent` 位置以 **96%** 的成功率触发同一操作；替换 250 个 goal heads 读取的任务信息，则以约 **94%** 的成功率改写接下来执行的子目标。

## 从目标定义到 GoalScope

论文用三个可检验属性界定功能性目标：**预承诺**，动作前已形成表示；**可塑性**，同一目标能由不同路径实现；**持续性**，执行中持续引导行为，完成后释放。

- 作者将代码任务拆成 2–4 个有序子目标，在实现前的 `prev_end`、`indent`、`var`、`eq` 四个位置测量内部状态。主评测包含 253 个 Python 规格、四种数据类型，每种配置有 1012 个观测。
- 通过跨语言激活移植学习稀疏 mask，在 64 层 `Qwen2.5-Coder-32B-Instruct` 的第 28–55 层定位出 **122 个 goal heads**，尽量洗去具体代码 token 的表面特征。
- **GoalScope** 聚合这些 heads 的输出，再注入没有原始任务上下文的独立运行，让模型用自然语言说出下一步操作。同一向量还被用于跨语言干预，因此同时检验读出的忠实性与因果性。

## 目标可读、可移植，也构成因果瓶颈

GoalScope 在最早的操作前位置已有约 **60%** 的忠实读出率，到提前三个 token 的 `indent` 超过 **0.90**，说明目标并非开始写代码时才临时形成。跨语言移植四个位置的平均因果成功率约 **87%**，支持该编码表达的是抽象“做什么”。

消融进一步显示：

- 只让 122 个 goal heads 读取任务与进度，成功率仍为 **80.6%**；扩大到 250 个后达 **91.3%**，接近 92.5% 的干净基线，随机 heads 则无法维持任务。
- 盲化 250 个 goal heads，成功率从 **0.925 降至 0.158**；盲化随机 heads 不影响基线。这是一个稀疏但存在冗余、可补偿的因果瓶颈。
- 目标编码在执行中逐渐衰减并转向下一子目标，但抗干扰能力弱：困难错误前缀下，各模型成功率仅 **0.09–0.21**。因此，持续可用不等于遇到障碍仍能坚持目标。

## NRGS：反复重算，而非一直携带

普通 Transformer 没有递归连接，而目标常持续超过 30 个 token、约到第 40 层后才清晰可读，单靠逐层传递同一状态难以解释。作者提出**非递归目标追寻（NRGS）**：模型反复读取任务说明、从已有代码估计进度，再比较二者，选出尚未完成的操作。

因果实验支持这一机制：只移植任务区间，**89%** 的案例转向 source 子目标；只移植代码进度区间仅 **6%**，两者同时移植达 **98%**。250 个 goal heads 的任务区间 KV transfer 带来约 **94%** 的行为改变和约 **90%** 的读出改变，随机控制仅 **0.2%**。同一干预在子子目标和未列明步骤的总目标上分别取得约 **79%** 与 **77%** 的重定向率。

进度 query 也有作用，但更弱且并非唯一信号：order-diff 配置下重定向率约 **57%**，模型还混合使用任务顺序、完成数量和归纳等线索。NRGS 因而获得有力但不完整的支持。

## 价值与边界

GoalScope 还能读出未明确列步的算法子目标及部分 few-shot 隐式规则，但 39 个单关系 ICL 任务平均准确率仅 **36.2% ± 5.6%**；失准模型实验也只是定性案例，不能视为稳定的恶意意图检测器。主证据来自步骤明确、无思维链的简单代码任务，对开放 agent、其他架构和更大模型是否普遍成立，仍需验证。
