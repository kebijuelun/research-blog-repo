# Olifant：用 CPU 记忆起草，让文本生成提速降耗

本地大模型需要兼顾速度与能耗，而传统投机解码的神经草稿模型自身成本不菲；Olifant 用驻留 CPU 内存的记忆式分类器替代它，让医疗、法律等不便上云的私密文本也能在消费级设备上高效生成。在领域匹配的法律文本上，它为无 KV cache 的 Mistral-7B 带来 **2.43 倍吞吐量**和 **2.51 倍能耗改善**。

## 核心方法：把语料编译成预测器

Olifant 使用 TiMBL 的 IGTree 算法，将语料编译成前缀 trie，无需 GPU、反向传播或加速器显存：

- 采用与验证器一致的 SentencePiece tokenizer，以连续四个 token 预测下一个 token，即 $(t_1,t_2,t_3,t_4)\rightarrow t_5$。
- 按信息增益排列上下文位置；查询时匹配最深节点，以多数标签给出预测。完整窗口未出现时，可回退到已匹配前缀，而非只能精确复用原文。
- 若节点多数标签与父节点一致便剪枝，通常可将 trie 缩小约 **95%**，且不改变已存储上下文的查询结果。
- 单 token 查询仅需 **0.16–0.25 ms**，实例库占用 **145 MB–4.6 GB** CPU RAM；相比之下，TinyLlama-1.1B 的 CPU 草稿延迟为 254 ms。

## 关键结果：验证器越快，草稿越要便宜

实验统一采用 Mistral-7B-v0.1、Apple M1 Max 和 batch size 1，覆盖 WikiText、PubMed、EurLex 三类文本，并比较 plain、4-gram、TinyLlama 与四个领域实例库。

- **无 KV cache**：领域匹配的 EurLex 模型在法律文本上于 $k=8$ 达到 5.55 tokens/s，能耗从 1326 降至 **529 J/100 tokens**。接受率虽从 $k=3$ 的 38.1% 降至 $k=8$ 的 19.9%，平均接受长度却从 1.13 增至 1.53，因此吞吐反而提高。
- **有 KV cache**：plain 基线已提升至 16.3–16.9 tokens/s，收益明显收窄。法律文本在 $k=3$ 时仍有 **1.25 倍速度**和 **1.09 倍能耗改善**，达到全研究最低的 **93 J/100 tokens**。
- **神经草稿反转**：TinyLlama 在无缓存时可加速 1.15–1.20 倍，有缓存后却只剩 0.47–0.29 倍，因为顺序生成草稿已比 cached verifier 验证更昂贵。
- **速度最优不等于能耗最优**：无缓存速度偏好 $k=8$，有缓存速度偏好 $k=3$–5，而有缓存能耗偏好 $k=3$；更长草稿会提高加速器功率。

## 为什么有效，以及边界在哪里

法律文本的优势来自**跨文档公式化**，而非单篇重复：其文内重复率仅 12.1%，但 **73.6%** 的不同 4-gram 也出现在其他法律文本中，离线领域训练正好捕捉这种可复用结构。首 token 拒绝快速路径则降低失败成本，使 cached 机制的实际盈亏平衡点降至约 20%–25% 的首 token 接受率。

Olifant 证明了接近零成本、可按语料适配的 CPU 草稿能同时提速降耗，但 **KV cache 仍是第一优先级**：它本身即可提速 6–7 倍、将能耗降至约十分之一。当前结论仍限于单一 M1 Max、Mistral-7B、greedy decoding 及同源领域测试，其他硬件、采样与跨领域泛化仍待验证。
