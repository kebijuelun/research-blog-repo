# DistillSpec：蒸馏对齐加速投机解码

大模型逐 Token 解码拖慢推理，投机解码（SD）虽能由小模型起草、大模型并行验收，却常因两者分布不一致而频繁拒绝草稿，卡住无损加速上限。DistillSpec 用白盒知识蒸馏（KD）让草稿模型在真实生成轨迹上对齐目标模型：相较标准 SD 再提速 **10%–46%**；与模型级联组合时，XSum、GSM8K 的相对延迟分别降低约 **6.4×、10.7×**，任务表现几乎不变。

## 为什么有效：SD 不只拼草稿速度

- 小模型先采样 $\gamma$ 个 Token，大模型一次性并行打分，再按接受率逐个验收；被拒绝后的草稿丢弃并重采样。
- 这套 rejection sampling 保持最终输出服从目标分布，因此是**无损**加速；但草稿越不像目标，接受率越低。
- 单 Token 接受率满足 $\beta=1-\mathrm{TVD}(p,q)$。真正的系统收益还取决于块效率 $\tau$ 和草稿/目标延迟比：只把小模型做快不够，还要让它“更会配合”。

## 核心方法：把分布对齐变成训练目标

- **白盒监督**：在每个生成上下文上，用教师完整 logits 缩小目标分布 $p$ 与学生分布 $q^\theta$ 的散度，而非只学 one-hot 答案；采样解码时，词表概率信息尤其重要。
- **散度可调**：比较 FKL、RKL、JSD、TVD。TVD 直接对应接受率，却不是所有任务的最佳 Loss，应随任务和解码策略选择。
- **优先 on-policy 数据**：用当前学生生成的轨迹接受教师监督，避免持续调用昂贵教师。理论分析表明，学生轨迹上的小 TVD 能约束教师轨迹上的接受率；固定标准答案则容易与当前模型分布错位。

## 实验与配方：收益真实，但没有万能组合

在 T5-XL（3B）/T5-Small（77M）等模型和摘要、翻译、数学推理、语言建模任务上，36 组设置全部取得正收益，模型生成数据整体优于固定答案，$f$-Distill 与 GKD 通常最强。GKD 在 XSum 上约 24 小时达到接近 $f$-Distill 的接受率，而后者约需 50 小时。

- **迁移仍有效**：GSM8K 蒸馏草稿用于 23 个未见 BBH 任务，greedy/non-greedy 平均加速由 1.93×/1.78× 提至 **2.21×/2.02×**；未经重新蒸馏迁移到 T5-XXL，仍有 **7%–37%** 增益。
- **配方随任务变**：XSum greedy 最佳是学生+教师数据配 JSD（$\tau$ 增量 0.53）；GSM8K greedy 是学生数据配 FKL（0.61），改为温度采样后则变成教师数据配 RKL（0.49）。学生任务分数高，也不等于草稿块效率高。

## 结论与边界

- DistillSpec 不改 SD 验收协议，可与验证、并行等系统优化叠加；模型级联组合进一步实现 6.4×–10.7× 延迟缩减。
- 加入 lenience 可主动交换质量与延迟，但不再具备标准 SD 的分布无损保证。
- 方法需要教师白盒 logits，且收益依赖硬件、输出长度、草稿/目标延迟比和解码策略；后续重点是降低白盒与逐任务调参成本。
