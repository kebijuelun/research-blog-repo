# PTP：反向预测前一 Token，近乎还原提示词

只看到 LLM 的回答，能否在黑盒条件下反推出原始提示词？这关系到隐藏提示词泄露、模型行为分析与不良响应溯源。PTP 将目标模型的输出按 Token 倒序，从头训练反向语言模型，在 Qwen3-0.6B Chat 的 ShareGPT 100 条测试样本上，提示词 Exact Match（EM）达到 **64.77**，重构响应的 EM 达到 **61.79**。

## 核心创新：恢复的不只是原话，更是模型行为

- **Previous-Token Prediction**：正向模型按 NTP 预测下一 Token；PTP 先 Tokenize、再反转序列，让标准自回归模型根据右侧的未来上下文预测前一个 Token。无需特殊训练器，改变的是数据方向与来源。
- **从单点恢复到原像集合**：不同提示词可能触发相似回答，因此目标既可逐字恢复原输入，也可找到能引发相似行为的替代提示词。随机采样还能生成多个候选。

## 方法：五步完成反向闭环

1. **全词表探测**：将每个 Token 分别作为开头，让目标模型随机续写固定长度文本，并跨 Epoch 实时重采样，以覆盖模型自身的 Token 转移规律，而非模仿自然问题分布。
2. **Token 级反转**：严格在 Tokenize 后倒序，避免倒排字符或单词破坏 Token 清单。
3. **从零逆向预训练**：在反转语料上使用标准 NLL，学习 $P(y_{t-1}\mid y_{\geq t})$，不依赖现成模型的正向语言先验。
4. **轻量微调**：使用 400 条真实提示词，响应仍由冻结的目标模型生成，主要校准自然提示词的格式与语义。
5. **反向解码与验证**：从响应生成提示词，可 Greedy 或采样多候选；再把提示词交给目标模型，形成“响应 → 提示词 → 再生成响应”的闭环检验。

## 结果：精确恢复突出，但不等于全面领先

- 同一测试集上，最强 O2P 配置的提示词与响应 EM 仅为 **25.44** 和 **24.17**。PTP 的提示词 EM、BLEU、Token F1 分别为 64.77、63.08、63.64，优势集中在严格 Token 指标。
- O2P-1 的提示词 ROUGE-L、CS、BERT F1 更高；响应闭环中 RPEGA 的 CS 也略高。因此准确结论是：**PTP 更擅长精确恢复，O2P 更容易生成语义合理的改写**。
- Qwen Chat 的提示词 EM 为 64.77，Base 仅为 **35.14**。本文设置中，指令微调与 Alignment 反而让响应保留了更可逆的结构。
- 跨模型直接迁移到 GPT-4o 时，提示词 EM 降至 **11.36**，但闭环响应 CS、BERT F1 仍有 **81.57** 和 **84.53**：迁移主要保留语义与行为，而非精确 Token。

消融显示，核心能力来自“合成预训练＋反向目标”的组合；只用同样 400 条真实提示词难以学出可靠逆映射，256 Token 序列与实时重采样也优于更短序列和固定语料。

## 必须看清的边界

- “data-free”仅指合成预训练，完整流程仍需 400 条真实提示词微调。
- Token 级精确恢复需要目标 Tokenizer，严格说属于半黑盒假设；跨架构、跨词表时精确指标会显著下降。
- 约 15 万词表、每条 256 Token 时，一个预训练 Epoch 约生成 **38M Tokens**，单张 A100 约需 **1 小时**，商业 API 的查询成本不可忽略。
- 功能等价是统计结论，不保证每个案例意图无损；多候选反演也可能扩大敏感提示词的暴露面。
