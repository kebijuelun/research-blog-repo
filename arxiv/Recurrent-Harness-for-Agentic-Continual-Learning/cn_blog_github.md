# ReHarness：给 Agent 记忆系统装上"反向传播"

LLM Agent 越来越需要在一条源源不断的数据流上边干活边学习（Continual Learning），但现有的 Agent 记忆框架（Harness）大多只会"往前写、往前读"：经验一旦写进记忆库，就很少再根据后续使用效果回头修正，于是过度泛化或过时的"经验总结"会留在库里反复误导后面的决策。这篇来自 MIT、Meta MRS Research 和 Yale 的工作提出 **ReHarness**：在前向读写之外，增加一条 **反向修订（Backward Revision）** 通路——每次用完某条经验后，根据它这次的实际表现回头改写它，相当于给纯文本的记忆系统装上了"反向传播"。结果相当硬：在 3 个持续学习 Benchmark × 3 个前沿 Backbone（Claude Opus 4.8、GPT-5.5、Gemini 3.7 Flash）共 9 个组合中，ReHarness 拿下 8 个第一，平均 normalized gain 达到 **0.240**，比最强的全历史基线 Full Raw（0.164）高出约 46%，而 token 消耗只有后者的 **三分之一左右**。

## 一、提出问题：Agent 的"错题本"为什么会越记越错

先铺垫一下背景设定。所谓 **Agent Harness**（智能体支架），可以理解为套在一个参数固定的 LLM 外面的"运行时脚手架"：它负责记忆读写、检索、Prompt 组装等，让模型在不更新参数的情况下，通过在长任务流中积累经验来越做越好。这就像是给模型配了一本不断更新的"错题本 + 经验手册"。

在这个设定下，一个典型的持续学习循环长这样：

- 决策 Agent $\pi_D$ 处理完第 $t-1$ 个实例，留下轨迹 $\tau_{t-1} = (x_{t-1}, y_{t-1}, r_{t-1})$（输入、输出、环境奖励）；
- 记忆 Agent $\pi_M$ 对轨迹做反思，生成一条文本反思 $R_{t-1}$，写入 Harness 状态 $h_t$（**前向写**）；
- 下一个实例到来时，从 $h_t$ 检索相关反思辅助 $\pi_D$ 决策（**前向读**）。

问题出在哪？论文用一个极简的排序例子把缺陷暴露得很清楚：

![Figure 1：从有状态 Harness 到 ReHarness](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/arxiv/Recurrent-Harness-for-Agentic-Continual-Learning/images/png/pipeline.png)

> 图解：左图 (a) 是传统有状态 Harness 的纯前向信息流。$\tau_{t-1}$ 要求把 $\{3,7,4\}$ **降序** 排列，Agent 做对了，于是 $\pi_M$ 写下反思"把大数放前面"（$R_{t-1}$）。到了 $\tau_t$，查询变成 **升序**，检索到的 $R_{t-1}$ 直接误导 $\pi_D$ 答错；虽然 $\pi_M$ 随后又写了一条"把小数放前面"，但旧的错误反思 **仍然留在** $h_{t+1}$ 里，并在 $\tau_{t+1}$ 因数字重叠再次被检索到，又一次误导决策。右图 (b) 是 ReHarness：新增的修订 Agent $\pi_R$ 利用 $\tau_t$ 的失败反馈，把 $R_{t-1}$ 改写成"仅降序时大数在前"（$R'_{t-1}$），错误经验被就地修复，$\tau_{t+1}$ 顺利答对。

这个例子的要害在于：**纯前向的记忆演化只关心"写了什么"，从不关心"写的东西后来好不好用"**。在分布持续漂移（Distribution Shift）的流式场景下，过度泛化的反思一旦入库就没有机制被纠正，会沿着检索链路反复传播错误。现有方法要么只做 add/delete 式的记忆管理（维护一致性，但不吸收下游反馈），要么依赖额外的训练集/验证集做离线优化——这在严格的在线流式协议下根本不存在。

## 二、核心方法：ReHarness 的三步循环

找到了病因——只有前向通路、缺少反向反馈——接下来的问题是：反向反馈在 Agent 场景下该怎么实现？这里有三个现实约束：

1. **实例只过一次**：流式设定下不能回头重放历史实例收集反事实结果；
2. **没有验证集**：无法在多个候选更新之间做挑选；
3. **模型是黑盒 API**：拿不到参数，梯度反传无从谈起。

作者的解法很优雅：**既然模型参数动不了，那就在纯文本的 Harness 状态里做"反向传播"**。自然语言反馈本身已被证明是有效的学习信号（如 Reflexion、TextGrad 等前人工作），于是反向反馈被实现为对文本反思的 **修订（Revision）**。笔者认为这个设计的聪明之处在于：它把"学习"完全锁定在文本空间，既不碰模型权重，也不需要任何额外数据，天然适配黑盒 API + 严格流式这两个最苛刻的条件。

具体来说，ReHarness 的每个时间步由三步组成：

### Step 1：前向读（Forward Read）

设当前 Harness 状态为 $h_t = \{R_i\}_{i<t}$。给定查询 $x_t$，检索 top-$k$ 条相关反思交给决策 Agent：

$$
\mathcal{I}_t = \{i_1,\dots,i_k\} = \operatorname{Retrieval}(x_t, h_t, k), \qquad y_t = \pi_D\!\left(x_t, \{R_i\}_{i\in\mathcal{I}_t}\right)
$$

环境返回奖励 $r_t$，构成当前实例轨迹 $\tau_t = (x_t, y_t, r_t)$。

### Step 2：反向修订（Backward Revision）

这是全文的核心创新。观察完 $\tau_t$ 之后，修订 Agent $\pi_R$ 逐条回访本次被检索到的反思，结合该反思的 **源轨迹** $\tau_i$ 和它在当前实例上的 **实际效果** 进行改写：

$$
R'_i = \pi_R\!\left(R_i, \tau_i; \tau_t\right), \qquad \forall i \in \mathcal{I}_t
$$

这里有一条关键约束必须划重点：$\tau_t$ 只能作为 **反馈信号** 使用，$R'_i$ 中的任何新内容都必须 **有据可溯地来自源轨迹 $\tau_i$**，防止信息泄漏（Information Leakage）。换句话说，修订只能做三件事：补入 $\tau_i$ 中当时被忽略的证据、纠正 $R_i$ 中缺乏支撑的假设、收紧反思的适用条件。用排序的例子说，就是把"大数放前面"加上限定条件改成"仅降序时大数放前面"。

用修订后的反思替换库中对应条目（未被检索的保持不动），得到中间状态 $h'_t$，这就建立了反向通路 $\tau_t \rightarrow R'_{t-1} \rightarrow h'_t$。

### Step 3：前向写（Forward Write）

最后，记忆 Agent $\pi_M$ 照常对 $\tau_t$ 反思生成新条目，但有一个细节：它会把刚修订好的 $\{R'_i\}$ 当作 **示范（Demonstration）** 来学习"什么样的反思才是好的反思"：

$$
R_t = \pi_M\!\left(\tau_t; \{R'_i\}_{i\in\mathcal{I}_t}\right), \qquad h_{t+1} = h'_t \oplus R_t
$$

Prompt 会引导 $\pi_M$ 只保留有证据支撑的解释，并鼓励 $R_t$ 覆盖示范中没有的互补视角（比如顺着 $R'_{t-1}$ 的格式写出"仅升序时小数在前"）。

三步合起来，前向读、前向写、反向修订构成一个完整的 **循环（Recurrent）** 结构——这也是论文标题中 Recurrent Harness 的由来：信息不仅沿时间向前流动，还会以反馈的形式向后回流，形成闭环。

## 三、实验设置：严格流式协议下的全面评测

方法讲完，自然要问：这套闭环在真实任务流上管不管用？先看实验怎么搭。

### 评测协议与指标

所有方法在 **严格在线流式协议** 下评测：没有训练集、没有验证集、不允许重复尝试，Harness 状态在每条任务流内跨实例累积、在流之间重置。每个实验重复 3 次独立采样的流式 rollout，所有方法共享相同的初始化和随机种子后各自演化。

由于不同任务的原生指标不可比，论文沿用 CL-Bench 的做法报告 **Normalized Gain**（归一化增益）：

$$
\text{Normalized Gain} = \frac{r_{\text{method}} - r_{\text{stateless}}}{r_{\max} - r_{\text{stateless}}}
$$

其中 $r_{\text{stateless}}$ 是不带任何记忆的无状态 Backbone 成绩，$r_{\max}$ 是该任务指标的理论上限。这个指标衡量的就是"从流中经验学习"相对裸模型带来了多少提升。

### Benchmark、基线与 Backbone

三个持续学习 Benchmark 覆盖了相当广的任务谱系：

- **CL-Bench**：6 个任务，涵盖队列研究、代码库适配、数据库探索、销售预测、盲频谱监测、可剥削扑克，每条流含 12-120 个多轮实例，带显式分布漂移；
- **MemoryBench**：长输入长输出写作任务（HelloBench + WritingBench 的 5 个英文任务），覆盖学术、创意、政治写作，每条流 17-47 个单轮实例，由 GPT-5.6-Sol 评分；
- **MemoryArena**：5 个领域（旅行规划、网购、渐进式网络搜索、数学与物理形式推理），每个领域 20-270 个任务，每个任务含 2-16 个相互依赖的多轮实例。

基线共 7 个，分为几派：原子记忆派的 **Mem0**；反思库派的 **RBank**（只追加不修改）、**DoT**（基于检索经验生成多样反思）、**ACE**（维护全局 playbook 并做增删改合并）；Prompt 优化派的 **GEPA-Online**（把 GEPA 改造为纯在线顺序更新）；以及原始上下文派的 **Top-K Raw** 和 **Full Raw**（直接检索/塞入原始轨迹做 In-Context Learning）。所有方法使用同一 Backbone（Claude Opus 4.8 / GPT-5.5 / Gemini 3.7 Flash），检索统一用 Qwen3-Embedding-8B 取 top-5。

几个值得注意的读数：

- ReHarness 平均增益 **0.240**，在 9 个组合中 8 个排名第一或并列第一；
- 原始上下文基线（Top-K Raw / Full Raw）确实是强对手，平均超过大多数结构化记忆方法——这与 CL-Bench 原论文的发现一致；
- 纯反思方法（RBank、DoT、ACE）表现不稳，部分设置甚至出现 **负增益**（学了还不如不学）；
- GEPA-Online 在 MemoryBench × Gemini 上崩塌到 -0.134，说明仅靠 Prompt 优化做持续学习不够鲁棒。

统计显著性方面，作者对每个带种子的任务流做双侧配对 Wilcoxon 符号秩检验（Bonferroni 校正），ReHarness 对 **所有** 基线优势显著（$p_{\mathrm{adj}} < 0.05$），包括对 Top-K Raw（$p_{\mathrm{adj}} = 0.039$）和 Full Raw（$p_{\mathrm{adj}} = 0.043$）。

### 任务级拆解

上面那张图（Figure 2）展示了 16 个任务上各方法的归一化增益（对三个 Backbone 取平均），纵轴为 Normalized Gain，每个任务一组柱子，青绿色为 ReHarness。

> 图解：三组子图分别对应 CL-Bench、MemoryBench、MemoryArena。可以看到各方法在不同任务上波动很大，不少方法在某些任务上掉到零以下（不如无状态 Backbone）；而 ReHarness（每组最右侧的青绿柱）在几乎所有任务上都保持领先或贴近最优。两个例外值得说明：CL-Bench 的 Poker 任务上它只有边际增益；MemoryArena 的 Travel 任务上 Mem0 异常强势。

为什么 Poker 上不灵？论文的解释很坦诚：扑克有隐藏牌和运气成分，单局奖励与策略质量 **弱耦合**，下游奖励对反向修订而言是噪声信号。Raw 类方法把原始牌局轨迹原样保留、把解读推迟给决策时的 Agent，反而不受这个信用分配（Credit Assignment）问题的影响。换句话说，**ReHarness 最受益的场景是反馈具有诊断性（diagnostic）的任务**——失败能明确指向哪条经验错了。

### Token 效率

多了一次反思调用和 $k$ 次修订调用，ReHarness 会不会更贵？恰恰相反。以 CL-Bench × Claude 单次 rollout 为例：

| 方法 | 输入 token | 输出 token | 总 token | 相对倍数 | API 成本（含缓存） |
|---|---|---|---|---|---|
| Top-K Raw | ~52.20M | ~0.46M | ~52.66M | 1.3× | ~\$85 |
| **ReHarness** | ~37.19M | ~4.38M | ~41.57M | 1.0× | ~\$254 |
| Full Raw | ~141.68M | ~0.44M | ~142.12M | 3.4× | ~\$314 |

原因在于：压缩后的反思大幅降低了每次决策时重复读入原始轨迹的上下文成本，对多轮长实例尤其明显。虽然 ReHarness 输出 token 更多（要生成修订），但输入端的节省完全覆盖了这部分开销。对比 Full Raw，ReHarness 便宜约 20% 且增益更高（0.217 vs 0.191）；Top-K Raw 更便宜但增益明显更低（0.165）。

## 五、深入分析：修订到底改了什么、有没有效

主结果之后，论文用四个递进的分析回答了读者最关心的质疑。我们逐个看。

### 分析一：修订会不会"偷看答案"？

反向修订最大的风险是信息泄漏——修订时把当前实例 $\tau_t$ 的内容直接抄进反思，那等于作弊。论文借鉴 FActScore 的思路，用 GPT-5.6-Sol 把每条修订后的反思拆成事实性断言，分类为：grounded（被源轨迹 $\tau_i$ 蕴含）、leaked（不被 $\tau_i$ 蕴含但被 $\tau_t$ 蕴含）、unsupported（两者都不蕴含）。

| LLM | Grounded 率（↑） | 每次修订 Δ | Leakage 率（↓） | 每次修订 Δ | Unsupported 率（↓） | 每次修订 Δ |
|---|---|---|---|---|---|---|
| Claude | 0.953 | -0.003 | 0.021 | 0.006 | 0.026 | 0.002 |
| GPT | 0.987 | -0.002 | 0.008 | 0.003 | 0.005 | 0.001 |
| Gemini | 0.963 | 0.007 | 0.013 | 0.004 | 0.024 | -0.002 |

三个 Backbone 的 grounded 率都在 **95% 以上**，泄漏率仅 0.8%-2.1%，且修订前后这些比率几乎不变（grounding 每次修订最多下降 0.3%）。这说明 Backbone 基本遵守了"只把 $\tau_t$ 当反馈、不当素材"的约束。

### 分析二：修订真的产生了有用的信息吗？

接地性只证明"没作弊"，还要证明"改得对"。论文设计了一个巧妙的 **反事实重放（Counterfactual Replay）** 实验：完成 $\tau_t$ 并得到修订后状态 $h'_t$ 之后，**回到同一个实例** 用 $h'_t$ 重新辅助决策（注意这违反在线协议，仅作诊断）。它回答的问题是："基于过去轨迹中本来就有的信息，早该怎么记才能帮到这个实例？"

| 设置 | 修订依据 | 应用于 | Cohort | Codebase | Database | Sales | Spectrum | Poker | Average |
|---|---|---|---|---|---|---|---|---|---|
| 无修订（仅前向） | -- | -- | -0.053 | 0.359 | 0.279 | 0.258 | 0.033 | -0.012 | 0.144 |
| ReHarness | $\tau_t$ | $\tau_{t+1}$ | -0.019 | 0.378 | 0.361 | 0.408 | 0.162 | 0.009 | 0.217 |
| 反事实重放 | $\tau_t$ | $\tau_t$ | **0.046** | **0.509** | **0.402** | **0.698** | **0.314** | **0.041** | **0.335** |

两个结论：其一，反事实重放（0.335）大幅超过 ReHarness（0.217），说明修订确实从过去轨迹中挖掘出了"本该被记下"的信息，修订是 **有意义的**；其二，即便只用合规的方式把修订结果应用到后续实例，ReHarness 依然在所有任务上超过无修订基线（0.144），在数据库探索、销售预测、盲频谱监测上提升尤其大——反向修订的价值不是纸面富贵。

### 分析三：它到底在改什么？（定性案例）

![Figure 3：ReHarness 修订的定性案例](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/arxiv/Recurrent-Harness-for-Agentic-Continual-Learning/images/png/example.png)

> 图解：(a) 盲频谱监测的早期修订。$\tau_2$ 中 $\pi_D$ 观测到五个发射机峰值（奖励 0.297），但 $\pi_M$ 过度泛化，写下"报告可信的额外信道以填补大的静默空隙"。这条反思被检索后，$\tau_3$ 的 $\pi_D$ 编造了未观测到的发射机，奖励跌到 0.219。$\pi_R$ 以此为反馈，把假设标记为"推测性"，改为"优先保留已确认峰值"，$\tau_4$ 奖励回升到 0.367。(b) 数据库探索的后期修订。早期流中固化的反思"评分值来自 prc 列"在 $\tau_{20}$ 后遭遇 schema 漂移（新增 prc_v2 列）；$\tau_{23}$ 中 $\pi_D$ 只查 prc 而失败（奖励 0），$\pi_R$ 把规则改为"不预设哪列被评分、枚举所有价格类列"，$\tau_{25}$ 中 $\pi_D$ 两次查询即命中正确答案（奖励 0.867）。

这两个案例分别展示了 ReHarness 的两类典型修复：**纠正早期的过度泛化** 和 **在分布漂移后更新过时经验**。

### 分析四：稳定性与可塑性如何兼得？

持续学习的经典矛盾是稳定性（Stability，漂移后旧能力是否保留）与可塑性（Plasticity，漂移后能否快速适应新分布）的权衡。论文沿用 CL-Bench 的分解方式：稳定性测分布漂移后第一个实例的增益（此时还没有漂移后的反馈），可塑性测漂移之后、下一次漂移之前的实例增益。

| Method | Claude Stab. | Claude Plas. | GPT Stab. | GPT Plas. | Gemini Stab. | Gemini Plas. | **Avg Stab.** | **Avg Plas.** |
|---|---|---|---|---|---|---|---|---|
| Mem0 | 0.002 | 0.101 | 0.014 | 0.206 | -0.026 | 0.118 | -0.003 | 0.142 |
| RBank | **0.004** | 0.069 | 0.001 | 0.065 | -0.022 | 0.062 | -0.006 | 0.065 |
| DoT | -0.003 | 0.127 | -0.002 | 0.083 | 0.000 | -0.007 | -0.002 | 0.068 |

## 七、总结与展望

回顾全文要点：

- **问题**：现有 Agent Harness 只做前向读写，过度泛化/过时的反思会在记忆库中持续误导后续决策；
- **方法**：ReHarness 在前向读写之外增加反向修订通路，用当前轨迹作反馈、以源轨迹为接地约束改写被检索的反思，构成完整的循环结构，无需参数更新、无需重放、无需验证集；
- **结果**：3 个 Benchmark × 3 个 Backbone 平均 normalized gain 0.240，9 个组合中 8 个第一，对所有基线统计显著，token 仅为 Full Raw 的约 1/3；
- **分析**：修订 95%+ 接地、泄漏率 <2.1%；反事实重放证明修订信息有效；稳定性与可塑性双第一；$k=5$ 即为甜点；
- **局限**：在奖励噪声大的任务（如扑克）上反向修订信号弱，效果打折；且仍需存储原始轨迹以备修订，有额外存储开销。

笔者认为，这篇工作更大的价值在于把一个经典思想——"用下游反馈修正上游表示"——干净地移植到了纯文本的 Agent 记忆空间：当模型权重越来越封藏在 API 之后，**Harness 层的循环适配** 很可能成为 Agent 持续学习的主战场。下一步值得关注的方向，是如何在弱反馈/噪声奖励场景下让修订信号更鲁棒，以及如何降低保留原始轨迹的存储成本。
