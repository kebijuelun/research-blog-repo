# HASS：训练对齐带来 4.05 倍解码提速

大模型逐 Token 解码的串行瓶颈限制了低时延应用，而推测采样常因草稿模型的训练目标、上下文与真实解码不一致，损失加速收益。HASS 通过 Top-K 目标蒸馏和多步上下文对齐解决这两处错位：在单张 NVIDIA H800、batch size 为 1 的设置下，四个 LLaMA 模型、三类任务的平均加速达 **2.81x–4.05x**，比 EAGLE-2 快 **8%–20%**。

## 问题：草稿模型为何越猜越不准

推测采样让小模型先连续生成候选，再由目标模型并行验收；每轮平均生成的 Token 数称为接受长度 $\tau$，它越大，目标模型的串行调用越少。EAGLE 系列虽利用目标模型特征提高草稿质量，训练与解码仍有两处错位：

- **目标错位**：常规蒸馏拟合完整词表，但 Top-K、Nucleus Sampling 乃至贪心解码主要依赖高概率候选，长尾 Token 的精确排序并非重点。
- **上下文错位**：训练时每个位置都有目标模型的真实特征；多步解码时，未验证位置只能使用草稿模型自身特征，误差会沿草稿链累积。

## 方法：同时校准“学什么”和“在哪学”

HASS 只改变草稿模型的训练过程，由两个互补模块组成：

- **Top-K 目标蒸馏**：仅在目标分布概率最高的 $K$ 个 Token 上计算加权交叉熵，让草稿模型优先学习最可能被接受的候选，而非平均照顾整个词表。目标特征原本就经过 LM Head，因此无需额外运行目标模型。
- **多步上下文对齐**：第 1 步沿用 EAGLE 的训练条件，后续步骤逐步用前序草稿前向产生的特征构造 query、key 和 value，并通过定制 Attention Mask 模拟不同解码深度，让模型适应自身误差。它只替换特征上下文，不替换训练 Token。

训练结束仍只保留一个草稿模型，继续使用 EAGLE-2 的动态草稿树；目标模型权重、接受条件和输出分布均不变，推理也没有新增开销。

## 结果：接受更长草稿，收益可以迁移

- **主实验全面领先**：在 MT-bench、HumanEval、GSM8K 上，HASS 相对 EAGLE-2 的接受长度提高 **8%–16%**，并转化为 **8%–20%** 的实际速度优势；最高平均加速 **4.05x** 出现在 LLaMA3-Instruct 70B、$T=0$。
- **对齐步数并非越多越好**：3–4 步总体最好，5 步开始回落；仅做特征对齐优于同时替换训练 Token，说明关键是适应特征误差。
- **数据效率更高**：仅使用 $1/4$ ShareGPT 数据的 HASS，接受长度就能达到或超过使用全量数据的 EAGLE-2。
- **跨任务仍有效**：草稿模型未经翻译适配，直接用于五个翻译方向时，平均加速为 **2.44x–3.28x**，比 EAGLE-2 快 **17%–24%**。

代价全部留在训练端：标准 Align-3 的训练时间平均增加 **66.34%**，总计算量约为 EAGLE-2 的 **3 倍**。因此，HASS 的核心价值是用一次性的额外训练成本，换取可反复复用、无损且零推理增量的解码加速。
