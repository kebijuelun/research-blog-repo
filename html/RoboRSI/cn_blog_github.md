# RoboRSI：让机器人在真实世界里自我进化

机器人 Demo 最大的痛点不是“做不出来”，而是“做出来之后，换个场景就得重写一遍”。Noematrix Lab 推出的 RoboRSI 正是针对这个问题：它是首个部署在真实移动机器人上的多智能体（Multi-Agent）自进化框架，能让机器人在开放真实场景中自主迭代技能，完成目标搜索、移动接近、抓取、运送与放置的长程任务。最硬的数字是：2024 年同类地面清理 Demo 需要两名工程师连续投入约一个月、手写 2,000–3,000 行任务代码；而 RoboRSI 把从需求到可执行能力的迭代压缩到了约一天，并且迭代产出的技能、代码和失败诊断会沉淀在框架中供下一任务复用。仿真侧，经过约一天的并行迭代，LIBERO 上累计任务通过率达到 95/120，RoboTwin 从 9/50 提升至 36/50。

## 提出问题：Agent 直接上机器人，为什么行不通

软件行业已经验证了这条路径：AI Coding 工具接管了代码编写、日志诊断与版本迭代的执行闭环，工程师得以专注于宏观目标、价值判断和安全边界，系统也能从完整的“尝试—反馈”循环中持续改进。

物理世界理应经历同样的进化，但复杂度完全不在一个量级。机器人本体拥有高维、连续且受动力学约束的动作空间；真实场景开放、非结构化，随人、物和外部条件不断变化。直接把 Agent 部署到机器人上，长程任务很难跑通；执行中遇到的各类问题与不完整反馈，极易让 Agent 陷入混乱。

更现实的对比是工程成本。2024 年做一个纯地面清理 Demo，需要两名工程师约一个月，手写 2,000–3,000 行任务代码；一旦要适配新场景、新物体或出现新的失败模式，往往意味着同等量级的返工。RoboRSI 要回答的核心问题就是： **能否让机器人系统自己完成“任务拆解—技能实现—真机执行—诊断—修订”这条闭环，并且让每次迭代的成果可复用？**

## 分析问题：成本与混乱到底从哪来

### Context 管理是新时代的代码管理

把 Code Agent 接上 MCP 之后，机器人其实已经能看图、调工具、执行动作，偶尔还能在陌生任务上撞出一次成功。但连续运行会很快暴露两个真问题：

- **谁来干杂活？** 环境复位、成功判断、异常恢复、安全决策，过去都要机器人工程师逐项跟进；
- **经验怎么复用？** 这次执行留下的轨迹、视频和代码，下一轮如何被真正用上，而不是让上下文不断堆积冗余信息，最终把系统拖入混乱。

RoboRSI 因此把目标收敛为两件事： **尽可能减少人类介入** ，以及 **让 Agent 用更少的 Token 从有价值的历史经验中完成更稳定、更快的迭代** 。

### 人工成本出在哪里

机器人报错停机、抓空或走偏之后，复位环境、检查结果、读日志、诊断代码——这些执行细节过去全靠工程师持续理解和跟进。RoboRSI 的思路是让 Manager、Planner、Engineer、Reviewer 四个角色接管这些细节，再通过 **面向人类的高层引导（Human-Friendly Steering）** ，让人把注意力放回目标、方向、价值判断、专业知识和安全边界上。真机上人仍负责安全监管和必要的方向调整，但不必跟进每一次底层执行；仿真中则可以自动完成更多检查与复位。

### 历史经验出在哪里

如果每轮都让 Agent 参考过去的完整 rollout，Token 会失控膨胀；如果每次局部失败都重写整套流程，系统又难以收敛。这里的关键观察是：Coding 模型擅长处理局部细节，却容易在连续修改中丢失全局目标。RoboRSI 用一棵任务—技能树（TSR）提供 **面向智能体的结构（Agent-Friendly Structure）** ：固定高层任务骨架，把具体能力放进职责明确、归属清晰的技能节点，让每次局部修订都不偏离总体目标。笔者认为这个设计的聪明之处在于：它没有试图让模型“变得更聪明”，而是用工程结构把模型的短板（全局漂移）绕开了。

## 解决问题：RoboRSI 的两种互补抽象

### 总体框架：执行、诊断、更新、复用一体化

OpenETA、Voyager、Code as Policies 等前作分别从具身交互闭环、可执行技能库、语言模型生成机器人策略等方向推进了 Agent 与环境的持续交互。但对持续运行的机器人来说，仅有单次技能执行和交互闭环并不够：任务管理、失败诊断、技能版本维护、跨轮经验压缩复用，都应作为独立模块由不同 Agent 分管。

RoboRSI 的设计哲学由此概括为两种互补抽象： **Human-Friendly Steering** 把人类输入集中在目标、方向、价值和安全判断上； **Agent-Friendly Structure** 用层级化技能树约束局部实现，使多智能体运维、验证通过后的能力固化、下一轮复用在同一流程中持续推进。

### 四个角色接力：Manager、Planner、Engineer、Reviewer

RoboRSI 的多智能体集群包含四个 sub-agent，围绕同一任务和反馈闭环持续协作：

| 角色 | 职责 | 类比 |
| --- | --- | --- |
| Manager | 把任务指令变成任务队列，管理并发 worker、断点和技能版本 | 项目经理 |
| Planner | 结合当前观察与已有技能形成可执行计划 | 架构师 |
| Engineer | 调用工具、执行动作、实现候选代码策略 | 一线工程师 |
| Reviewer | 根据结果定位问题，把修订建议送回 Manager | Code Reviewer |

真机保留必要的安全监管和方向调整，仿真则可以自动完成复位与结果判断。整个工作流像一条六步流水线：

1. **REQUEST** ：人类给出目标、约束、专业知识与操作建议；
2. **MANAGER** ：分解任务，定义原子任务（Atomic Task）并定位所需基础技能（Base Skill）；
3. **PLANNER** ：为每个原子任务生成边界明确的执行方案；
4. **ENGINEER** ：为相关技能编写并测试基于代码的策略；
5. **ROBOT** ：真实执行，返回观测、动作、日志与物理结果；
6. **REVIEWER** ：形成任务总结，把修订建议路由回责任分支，开启下一轮。

### TSR：自顶向下的技能细化

TSR（Top-down Skill Refinement）是 RoboRSI 面向 Coding 模型的关键结构抽象。技能按四个层级组织：

- **任务族（Task Family）** ：定义一类任务的总体目标和约束；
- **复合技能（Compound Skill）** ：组合可复用的多步能力；
- **原子任务（Atomic Task）** ：职责明确、结果可验证的最小任务单元；
- **基础技能（Base Skill）** ：封装感知、移动、抓取、放置等与机器人直接交互的能力。

通过固定全局骨架、限定技能边界、明确节点所有权，TSR 保证细节导向的 Coding 模型不偏离总体目标。执行结果沿实际调用路径返回：稳定节点继续组合复用，出错节点在原分支内修订；成熟路径固化为代码，轨迹数据用于训练 learning-based policy。

与前作相比，RoboRSI 的重点不是“再发明一种代码生成方式”。Voyager 证明了代码技能可长期积累，Code as Policies 展示了语言模型组合感知与控制 API 的能力，CaP-X 指出机器人 Coding Agent 对人类预设的抽象层级高度敏感，ASPIRE 把失败诊断与程序修复放进开放式循环。RoboRSI 的增量在于： **用技能树规定这些能力的层级、所有权和回流路径** ，让多轮迭代逐步收敛，而不是让技能库随任务增加而失控。

### 代码固化：Agent 从“逐步执行”转向“调用代码”

RoboRSI 从成功的调用链中提取稳定结构，把物体、目标区域、空间关系变成参数。相似任务再次出现时，Agent 只需选择并监控复合技能，重复的工具步骤交给固化代码执行；仅当环境变化或执行失败时才恢复在线推理。随着稳定分支增加，Agent 参与度逐步降低，任务耗时与 Token 消耗同步下降。

![Agent 介入程度随路径稳定而下降](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/html/RoboRSI/images/roborsi-eta-cap-consolidation-v1.svg)

> 图解：随着技能路径趋于稳定，Agent 的角色从“逐个工具做决策”转变为“选择、监控、修订整条技能”，重复执行由 Code 承担。这是 Token 和时间成本下降的直接原因。

### 让技能树收敛的四条设计原则

结构之外，RoboRSI 还提出一组贯穿设计与迭代的原则，这部分工程味很重，但恰恰是系统能稳定运转的关键：

1. **职责清晰与相互信任** ：每项技能只负责一个边界明确、结果可验证的闭环功能，仅通过结构化数据交换必要信息。下游检查成熟上游的结论是否仍有效、适用、安全，而不是重复实现或叠加 try/verify/catch 兜底分支。
2. **正确归因与收敛迭代** ：依据物理证据定位 **最早** 出问题的责任节点，在负责模块内修复，而不是把 workaround 推到下游。一次修改是否有效，不只看当前任务是否成功，还看重复执行、额外验证、模型回退、人工介入和代码分支是否随迭代持续减少。
3. **程序参数化与窗口化修复** ：物体类别、环境条件、目标关系、执行顺序抽象为可配置参数；像素、坐标、姿态等临时观测只服务当次运行，不进入通用程序。常规修改在最近若干次成功与失败组成的 **经验回放窗口（history replay buffer）** 中共同评估，避免“修好新样例、弄坏旧行为”。
4. **人类知识蒸馏与维护** ：每次人工纠正都先问一句“系统是否本可自行发现”，把可复用知识固化为自动检测、结构化状态、运行规则、测试或文档，而不是留在对话记录里。确实需要人类判断时，机器人先进入安全稳定、可等待的状态。

其中“窗口化修复”尤为值得点赞——它本质上是把训练里的 replay buffer 思想搬到了代码修订上，直接针对“改 A 坏 B”这个所有 LLM 工程系统都会踩的坑。

## 实验验证：仿真迭代、代码固化与真机 Demo

### 从零开始：没有任务代码时的冷启动

实验结合 LIBERO-PRO 与 RoboTwin 2.0，验证 RoboRSI 在没有现成任务代码时如何从基础技能开始迭代。如开头图 1、图 2 所示：约一天并行迭代后，LIBERO 累计通过率 95/120，RoboTwin 从 9/50 提升到 36/50。这说明陌生环境下系统确实能持续迭代，而不是靠一次运气。

### 代码固化省了多少

对照实验设置两组：使用相同基础工具，唯一区别是能否调用已固化的复合技能（Code-on 可把稳定流程写成 code policy，Code-off 只能每次在线调用 skill）。结果如下：

| 指标 | Code-on 相比 Code-off |
| --- | --- |
| 中位 Token 消耗 | **-29.4%** |
| 中位 VLM 调用次数 | **-27.2%** |
| 中位墙钟时间 | **-17.0%** |

数字未必惊艳，但方向很扎实：固化机制同时降低了推理成本和执行时间，且让重复任务更稳定——这正好印证了 TSR 的收敛假设。

### 轨迹数据反哺 learning-based policy

RoboRSI 不排斥学习型策略，反而给它们提供数据。在一个案例中，系统通过 TSR 采集 1 条纠正轨迹（304 帧），整理为 8 组训练序列、2,432 个样本，完成 1,000 步微调后，再与代码技能混合执行同一任务。同一任务、同一初始条件下，训练后的策略表现显著改善。

![纠正数据训练前后对比与数据闭环](https://raw.githubusercontent.com/kebijuelun/research-blog-repo/main/html/RoboRSI/images/roborsi-policy-corrective-training-v2.svg)

> 图解：真实训练曲线与三阶段数据闭环——304 帧纠正轨迹 → 2,432 个样本 → 1,000 步 learning-based policy 微调 → 回到同任务的混合执行。这是“执行数据沉淀为能力”的完整证据链。

### 环境变化后的鲁棒性

仿真之外，作者还构建了一个分层扰动面板： **840 个扰动实例 = 7 类扰动 × 每类 120 个** （相机视角、光照条件、物体布局、机器人初始状态等变化），每个实例是在一个 LIBERO 任务上施加一种具体扰动后的独立评测单元，基于 LIBERO-Plus 评测。结果显示环境变化后 RoboRSI 可以继续修订技能并恢复任务覆盖——也就是说，技能树在分布外条件下依然能迭代，而不是推倒重来。

### 真机：家庭场景的两轮地面清理

最有说服力的还是真机 Demo。RoboRSI 在真实机器人上从零迭代出可泛化的家庭移动操作能力，覆盖目标搜索、底盘导航、机械臂抓取与放置。地面清理 Demo 展示了完整的两轮流程：

1. **第一轮目标搜索** ：扫描地面，确认待处理物体数量、位置可操作性，编排处理顺序；
2. **第一轮清理** ：从停靠位驶出，逐一执行接近、抓取、运送、放置；
3. **第二轮目标搜索** ：人在场景中活动后留下新物体，机器人重新扫描，更新目标清单与顺序；
4. **第二轮清理** ：根据新搜索结果重新组合移动与机械臂技能，处理新增目标。

整个真机整理任务共经历了 **104 轮技能树迭代** ：蓝色表示新增能力，橙色表示本轮修订，黄绿色表示已稳定技能。这个 104 轮的数字本身就是一种宣言——系统不是在调试一个 Demo，而是在持续进化一套能力。

## 结论与展望

回到最初的问题：机器人能不能像软件工程师用 AI Coding 一样，从“手写流程”转向“框架自迭代”？RoboRSI 给出的答案是肯定的：

- **首次** 将多智能体框架部署到真实移动机器人上，完成搜索—接近—抓取—运送—放置的长程任务；
- 迭代效率从“两名工程师一个月、数千行代码”压缩到 **约一天** ，且成果可复用；
- 仿真侧约一天并行迭代后 LIBERO 累计通过率 95/120，RoboTwin 从 9/50 提升至 36/50；
- 代码固化带来 Token -29.4%、VLM 调用 -27.2%、墙钟时间 -17.0% 的成本下降；
- 执行轨迹可回流训练 learning-based policy，代码与学习能力在同一框架中协同。

展望上，RoboRSI 下一阶段将探索 Sim-to-Real Learning（作者认为，对持续“感知—规划—执行—纠错”的智能体框架而言，仿真与现实的差距比端到端策略更小）、多机器人共享传感信息与技能协作，以及适配更多真机平台。当然，更严谨的结论仍需更多真机实验验证——这套框架的真正考验，在于它能否走出实验室的家庭场景，进入更杂、更脏、更不可控的真实世界。
