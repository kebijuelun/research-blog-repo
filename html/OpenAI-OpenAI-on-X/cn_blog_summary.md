# OpenAI 嵌入式评估试点：METR 入驻三周，审计内部监控系统

大模型公司说自己有安全监控，外人凭什么相信？OpenAI 今年夏天的做法是把门打开：邀请第三方评估机构 METR 和 Redwood Research 进驻内部，用三周时间深度接触其基础设施，直接审计 OpenAI 用来监测内部 agent 失准（misalignment）行为的监控系统。OpenAI 官方账号在 X 上公布了这次"嵌入式评估试点"，METR 于 10 月 22 日发文确认，一份简短的工作报告已经公开。

## 这次试点具体做了什么

通常第三方评估是"黑箱"式的：评估方拿到模型或 API 在外面跑测试，看不到公司内部怎么运作。这次的不同在于"嵌入式"——据 METR 说明，来自 METR 和 Redwood Research 的两名员工今年夏天直接在 OpenAI 的办公场所工作了三周。评估对象是 OpenAI 用于监控内部 agent 失准迹象的系统本身，而不是某个对外发布的模型。审计目标由此从"模型表现如何"推进到"公司的安全护栏是否真的在运转"——这一层验证，恰恰是从外部最难看到的。

## 为什么要关注

内部 agent 的失准监控是前沿实验室反复强调的一道安全防线：当 AI agent 在内部承担越来越多任务时，需要有系统去捕捉欺骗、规避监督等异常行为。但这类系统的实际效果，过去只能依赖公司自己的声明，这次试点第一次让外部团队带着深度权限去核实它。按 OpenAI 的说法，评估方的发现"帮助在系统扩展过程中加强了安全保障"，试点经验还将用于塑造未来与 METR 及其他第三方评估机构的合作形式。如果这个模式延续下去，"嵌入式审计"可能成为前沿实验室接受外部监督的标准做法，而不只是一次性的公关动作。

## 需要保留的疑问

公开信息目前仅限于两条推文和 METR 提到的"简短报告"。试点的具体发现、监控系统实际暴露过哪些问题、两人三周能覆盖多大的审计范围，这些关键细节推文中都没有展开。METR 那份报告的内容，才是判断这次试点含金量的真正依据。
