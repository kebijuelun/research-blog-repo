# Diffusion-LFM3：1.7B 模型按块自回归、块内扩散

Diffusion-LFM3-1.7B 把文本生成拆成了两种过程：长度为 32 个 token 的文本块仍按顺序自回归生成，块内 token 则通过多轮掩码扩散去噪逐步确定，并按置信度阈值并行解码。它不是在既有自回归模型上简单更换采样参数，而是同时修改了训练目标、注意力掩码和短卷积结构。

不过，这个项目当前更适合作为研究生成机制的实验入口，而不是可直接部署的新模型。模型卡明确标注其为研究预览：仅训练了 377 个优化器步骤，输出可能出现词语重复、单词截断和事实错误，也没有提供质量或速度基准结果。

## 块间保持顺序，块内迭代去噪

自回归生成通常按 token 顺序推进，而 Diffusion-LFM3 的基本生成单位是一个包含 32 个 token 的块。块与块之间仍保持因果关系，后续块可以利用此前已经生成的内容；进入当前块后，模型不再只按从左到右的顺序逐个确定 token，而是通过迭代掩码扩散去噪完成这一块。

块内并行由置信度阈值控制。达到条件的多个 token 可以在同一次前向计算中解码，因此它提供的是一种在计算次数与输出质量之间调节的生成方式，而不是承诺所有文本都能一次性并行生成。

模型卡用 `tau` 表示这一阈值：调低 `tau`，每次前向计算会生成更多 token，速度更快；调高 `tau`，则更有利于质量。这个结论来自项目对参数作用的说明，具体快多少、质量改善多少，仍需在相应任务和硬件上测量，模型卡没有给出数字。

## 从 LFM3 到底改了哪些结构

该模型以 LiquidAI/LFM3-1.7B-Base 为底座，并非从零训练。为支持块扩散目标，项目加入特殊 token `<|mdm_mask|>`，并相应调整共享嵌入层的尺寸；随后对全部权重进行微调，而不是只训练新增部分。

推理时的结构修改由 `blockdiff_inference.py` 在加载模型时完成：

- **注意力改为块因果掩码。** 同一个块内部采用双向注意力，不同块之间保持因果关系。对于滑动窗口层，则保留对称窗口。
- **短卷积改为居中形式。** 原模型的因果短卷积被替换为居中短卷积，以配合块内双向处理。
- **保留原始建模文件。** 仓库包含未修改的原始建模代码，上述变化由专用推理脚本注入。

这些改动也带来一个直接的使用限制：不能把这个仓库当成普通因果语言模型，直接调用标准 `generate()`。模型卡明确说明，那样无法正确工作，必须使用随项目提供的脚本完成加载和生成。

## 训练目标围绕“一个加噪块”展开

微调数据来自 HuggingFaceFW/fineweb-edu 的 `sample-10BT` 子集。这里的 `sample-10BT` 是所用数据子集名称，模型卡并未说明这 377 个优化器步骤实际消耗了多少 token，因此不能把它直接当作本次训练的数据量。

训练配置包括：块长度 32，上下文最多覆盖 15 个块，学习率为 $2\times10^{-5}$，优化器采用 AdamW，计算精度为 bf16。所有权重都使用块扩散目标微调，其中包括干净上下文块与一个加噪块、按 $1/t$ 加权的交叉熵、互补掩码，以及 Dream 风格的 logit shift。

这些配置说明了模型如何被改造成块扩散生成器，但并不构成效果验证。尤其是 377 步这一训练规模，与模型卡列出的重复、截断和事实错误风险放在一起看，现阶段更应关注机制能否运行、参数如何影响生成，而不宜据此推断其通用语言能力超过底座或其他模型。

## 调用方式体现了专用推理路径

模型卡给出的示例会先下载推理脚本，再动态导入并加载模型：

```python
# pip install -U "transformers>=5.12" huggingface_hub
from huggingface_hub import hf_hub_download
import importlib.util, sys
path = hf_hub_download("summerAIO/Diffusion-LFM3", "blockdiff_inference.py")
spec = importlib.util.spec_from_file_location("blockdiff_inference", path)
bd = importlib.util.module_from_spec(spec); spec.loader.exec_module(bd)

model, tok, mask_id = bd.load("summerAIO/Diffusion-LFM3")
print(bd.generate(model, tok, mask_id, "The capital of France is", gen_len=128, tau=0.9))
```

依赖要求为 `transformers>=5.12` 和 `huggingface_hub`。示例将生成长度设为 128、`tau` 设为 0.9；这只是项目提供的调用配置，不是质量或速度测试结果。若要研究并行程度的影响，可以在相同提示词和生成长度下调整 `tau`，分别记录输出质量与实际耗时，同时保留模型卡所述的错误风险。
