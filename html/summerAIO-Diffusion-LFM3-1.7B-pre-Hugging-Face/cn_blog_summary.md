# Diffusion-LFM3：1.7B 模型按块自回归、块内扩散

Diffusion-LFM3-1.7B 将文本生成拆成两种过程：每 32 个 token 组成一块，块间仍按顺序自回归，块内则通过多轮掩码扩散去噪确定 token，并按置信度阈值并行解码。它同时修改训练目标、注意力掩码和短卷积，不只是调整采样参数。不过，模型卡将其标注为研究预览：仅训练 377 个优化器步骤，可能出现词语重复、单词截断和事实错误，也没有质量或速度基准，因此现阶段更适合研究生成机制，而非直接部署。

## 块间有序，块内并行去噪

后续块可以利用此前生成的内容，保持块间因果关系；当前块内部则不必从左到右逐 token 生成，而是迭代去噪。达到置信度条件的多个 token 可在同一次前向计算中解码，但这不等于所有文本都能一次并行生成。

模型卡用 `tau` 表示阈值：调低可增加每次前向计算生成的 token 数、提高速度，调高则更有利于质量。这只是项目对参数作用的说明；具体收益取决于任务和硬件，模型卡未给出量化结果。

## 底座、训练与推理都被专门改造

模型以 LiquidAI/LFM3-1.7B-Base 为底座，加入特殊 token `<|mdm_mask|>`，调整共享嵌入层尺寸，并微调全部权重。推理脚本 `blockdiff_inference.py` 会在加载时注入结构变化：块内使用双向注意力、块间保持因果，滑动窗口层保留对称窗口；原因果短卷积改为居中短卷积，以配合块内双向处理。仓库也保留未修改的原始建模代码。

微调数据来自 HuggingFaceFW/fineweb-edu 的 `sample-10BT` 子集，但这是子集名称，不能视为 377 步实际训练的数据量。配置包括块长 32、最多 15 个上下文块、学习率 $2\times10^{-5}$、AdamW 和 bf16；训练目标包含干净上下文块与一个加噪块、按 $1/t$ 加权的交叉熵、互补掩码及 Dream 风格的 logit shift。

这些改动意味着它不能按普通因果语言模型直接调用标准 `generate()`，必须使用项目脚本加载和生成。示例依赖 `transformers>=5.12` 与 `huggingface_hub`，采用生成长度 128、`tau=0.9`，但这并非性能测试结果。

## 研究价值与使用边界

该仓库提供了一条可运行的改造路径，却没有下游任务分数、基座对比或生产稳定性证据。它采用 LFM Open License v1.0：仅年收入低于 1000 万美元的个人或法律实体可商业使用，符合条件的非营利组织可不受该门槛限制地用于非商业或研究目的；再分发须附带许可证、保留署名并说明修改，项目也未获 Liquid AI 关联或背书。

因此，想观察块扩散如何接入现有模型、调节并行解码阈值的研究者，可把它作为小规模实验样本；追求稳定输出或准备上线的团队，则仍需等待更充分的训练与评估，并自行检查质量、速度和许可条件。
