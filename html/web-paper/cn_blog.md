# GLM-Legal：轻量模型如何炼成法律专业 Agent

让大模型写一段代码不难，难的是让它像律师一样，把散乱的事实、法条和论证串成一条完整链路，最后交出一份能直接用的法律文书。智谱最新发布的 GLM-Legal 就瞄准了这件事：在轻量的 GLM-5.3-Flash 基座上，通过领域 Mid-training 加与 Agent Harness 协同进化的 Post-training，把通用模型炼成法律专业 Agent。最硬的成绩是：在 Harvey 公司的真实律所工作流评测 Harvey LAB 上，GLM-Legal 拿下 **19.2%** 的 All-Pass 通过率，比基座模型提升 **12.5 个百分点**，同时在 LegalBench 和中文场景的 PLawBench 上与一线闭源前沿模型打平。

## 为什么法律是 Agent 能力的“压力测试”

大模型正在从单轮的代码生成走向更广义的 Professional Cowork（专业协作）。但真实知识工作和写代码很不一样：源文件是碎片化的，任务有明确目标和交付期限，输出还必须全程保持领域严谨性。

法律工作恰好把这些挑战浓缩到了一起。法律实务要求事实、法条教义、分析推理、客户可交付成果之间环环相扣、不能断链。一个 Agent 接到专业任务后，必须自己完成三件事：

- 从源文件中提炼核心争议点；
- 构建站得住脚的论证；
- 严格按任务规格排版交付。

能同时满足这三条，才是领域模型的真正试金石。换句话说，法律场景不是 GLM-Legal 的终点，而是检验“模型能否在高风险专业环境干活”的最佳试验场。

几个值得点出的数字：

- **Harvey LAB（19.2% All-Pass）**：这是 Harvey 公司基于真实律所工作流构建的评测，覆盖 24 个执业领域，采用严格的全通过（All-Pass）评分。GLM-Legal 得 19.2%，比基座提升 12.5 个百分点。这个指标苛刻在：端到端执行中任何一环掉链子都不得分，所以它证明的是“全程不退化”的可靠执行能力。
- **LegalBench（领域推理对齐）**：解析专业合同、并购文件、司法意见书时，达到顶级闭源前沿模型的精度，而参数量级明显更小。
- **PLawBench（中文本地化实务）**：在中文法律咨询、案例分析、文书起草的细粒度评分下，与领先的前沿系统打平。

笔者认为这里最值得注意的不是某个单一分数，而是 **“轻量基座 + 领域训练”打出了越级表现**——尤其在 Harvey LAB 这种端到端任务上，相对基座接近翻三倍，说明训练方法本身才是主角。

## 训练方法：领域知识如何变成执行力

GLM-Legal 的核心思路是 **训练效率优先**：不重新训一个大模型，而是在轻量基座上，用专门的 Mid-training 加高效 Post-training 把领域能力“长”出来，并且把预训练和下游任务执行直接绑定。整个流程分为三步。

### 1. Mid-training：先打牢法律地基

Mid-training 阶段的任务是建立系统化的法律基础。做法是扩大高质量法律语料的规模，让模型在高密度的领域语境中学习法律概念、成文法规则和解释框架。

这一步的意义在于强化“事实 → 规则 → 结论”之间的演绎链条。没有这个知识底座，后面的任务执行就是无源之水——模型可能流程走得很顺，但引用的法条是错的。

### 2. Post-training：模型与 Harness 协同进化

这是整篇方法论里最新颖的部分。Post-training 通过强化学习，在 **数万个真实法律环境** 中把领域知识转化为执行力，让模型学会规划分析、推进工作流、在约束下产出交付物。

这里的 Harness 指运行时编排框架，负责任务上下文管理、工具集连接、执行反馈路由。关键在于两者是 **共同迭代** 的：

- **协同优化**：Harness 架构和模型训练锁步迭代。任务结构化、上下文注入、运行时反馈回路共同支配 Agent 的探索行为。
- **双向学习**：模型训练中暴露的边缘案例，反过来定位 Harness 的架构瓶颈；Harness 的改进又让模型直面真实执行约束，训练它检索相关上下文、根据中间执行信号自我调整，从接收指令到最终交付全程达到生产级标准。

打个比方：传统做法是先练好“大脑”再配“手脚”，而这里是大脑和手脚一起长。这个设计的聪明之处在于，模型的能力边界和工程框架的瓶颈被放在同一个优化回路里，避免了“模型很强但系统接不住”的常见错位。

### 3. 生产反馈闭环：把主观质量变成 Loss 信号

解决了训练之后，下一个问题是：怎么持续知道模型在真实场景里够不够好？答案是让执业律师的评价直接驱动优化路线图。生产中，法律专业人士按四条具体标准评估输出：

- 所有关键问题和边缘案例是否都覆盖了？
- 论证是否充分、引用是否合法有效？
- 交付物是否严格遵守案件简报（matter brief）？
- 下游团队能否直接使用、无需人工返工？

这些要求把主观的“质量好坏”变成了具体的工程化损失信号。发现漏事实、分析浅、格式偏等问题时，团队会检查整条执行管线，把锅精确地分到原始模型智能、上下文准备、工作流逻辑三者之一头上，再把结论反哺到任务环境、评分细则和 Harness 设计中，用生产基准验证改进。

## 实战演示：三个法律任务的真实对比

这些能力很快会通过智谱的桌面 Agent 平台 AutoClaw 落地。官方给了三个对比案例，每个都是基座 GLM-5.3-Flash 与 GLM-Legal 的同题作答，差异相当直观。

### 案例一：合同审查——让退出条款真正保护客户

> 任务：为客户审查一份软件服务合同，客户正准备更换服务商，重点关注终止与交接条款。

**GLM-5.3-Flash** 的回答偏向“复述现状 + 温和建议”：指出合同允许 60 天通知终止、重大违约有 30 天补救期，“可以考虑”缩短通知期，建议要求返还已付款的交付物。

**GLM-Legal** 则直接给出可执行的修改方案：将任意终止通知期从 **60 天压缩到 30 天**；对知识产权、保密、数据安全类违约 **取消补救期**，客户可立即终止；引用合同第 4 条，要求返还全部交付物和在制品，**无论是否已付款**；追加 **最长 90 天的过渡协助**，覆盖源代码、文档、数据和知识转移。

![合同审查对比](https://z-cdn-media.chatglm.cn/prompts-rich-media-resources/glm-legal/img_v3_0216d_1cc88948-2550-4e94-8f27-d2443768470g.jpg)

> 图解：AutoClaw 界面截图，展示 GLM-Legal 将上述修改以修订模式（tracked changes）和批注写入 Word 文档，团队可直接审阅并用于谈判。

差距在哪？基座模型在“描述问题”，GLM-Legal 在“解决问题”——具体到天数、条款号、例外情形，这是能直接拿去谈判的文本。

### 案例二：证据分析——把矛盾连成案件理论

> 任务：分析一个软件项目纠纷中的 40 份文档，找出服务商进度报告中的矛盾。

**GLM-5.3-Flash** 找到了主要矛盾：9 月 30 日对客户报告称项目进展正常、完成 60%（BR-000024），而内部快照只记录了约 41%（BR-000027），并提示“可能支持客户立场”，建议进一步审查。

**GLM-Legal** 则把证据串成了链：那份“ON TRACK – 60%”的报告应对照 9 月 8 日内部“里程碑无法诚实达成”的警告（BR-000014）来读；CEO 指示 **隐瞒风险并继续开票**（BR-000015），把内部知情与披露决策连了起来；再引用主服务协议（MSA）第 2、5 条——**付款不构成权利放弃、质保在付款后依然有效**（BR-000001），说明继续付款并不能平息争议。这些连接支撑起一个隐瞒理论（concealment theory）。

![证据分析对比](https://z-cdn-media.chatglm.cn/prompts-rich-media-resources/glm-legal/img_v3_0216d_c9cf36a1-cc41-44b0-98a8-82959e43561g.jpg)

> 图解：AutoClaw 生成的矛盾图谱界面，将对外声明与内部冲突记录两两配对并标注来源文档编号，帮助团队评估证据、决定下一步调查方向，同时保持事实与推断的分离。

这个案例最能体现领域训练的价值：单点矛盾谁都能发现，但把“内部知情 → 披露决策 → 合同条款”连成一条指向特定法律理论的链，需要的是真正的法律推理。

### 案例三：合规调研——跨境上线的隐私优先级

> 任务：为一个即将在新加坡、马来西亚、印尼上线的网站规划隐私合规，涉及追踪、邮件营销和海外云存储。

**GLM-5.3-Flash** 给出的是通用清单：上线前发布隐私声明、确认 Cookie 和分析工具是否需要同意、营销邮件加退订选项、检查三国适用隐私法。

**GLM-Legal** 输出的是带优先级的行动方案：P0（上线前必须完成）包括发布英文和印尼语双语隐私声明，覆盖目的、跨境传输、权利与投诉渠道；非必要分析和广告采用 opt-in，并 **保留同意记录**；营销许可与注册流程分离；退订请求进入 **suppression list（退订黑名单）**；把云、支付、邮件、分析、CDN 供应商映射到各自的数据目的地，然后 **逐个市场确认所需合同与传输保障措施**——并直接引用了具体法条：新加坡 PDPA 第 26 条、马来西亚 PDPA 第 129 条、印尼 PDP 法第 55–56 条。

![合规调研对比](https://z-cdn-media.chatglm.cn/prompts-rich-media-resources/glm-legal/image.png)

> 图解：AutoClaw 输出的优先级清单界面，隐私要求被拆成同意追踪、营销许可、海外数据传输三类可执行步骤，每条附对应市场的法律依据，通用控制项作为保守上线基线，各国特有问题单独标注待确认。

三个案例看下来，模式很一致：基座模型给“方向正确的建议”，GLM-Legal 给“可立即执行的交付物”——这正是生产反馈闭环里“下游团队能否直接使用”那条标准的直接体现。

## 总结

- **定位**：GLM-Legal 是法律垂直领域的 Agent 模型，基于轻量 GLM-5.3-Flash 打造，主打训练效率而非参数规模。
- **成绩**：Harvey LAB 真实律所工作流 19.2% All-Pass（较基座 +12.5pp），LegalBench、PLawBench 与前沿闭源模型打平。
- **方法三板斧**：法律语料 Mid-training 打地基；数万个真实环境的 RL Post-training，且模型与 Harness 协同进化；生产反馈把律师的主观评价转成工程化损失信号。
- **实战差异**：在合同审查、证据分析、合规调研中，输出从“建议”升级为带条款、法条引用和优先级的可交付成果。
- **落地路径**：能力将通过桌面 Agent 平台 AutoClaw 交付，API 已开放申请。

展望来看，这篇工作真正的启示不在法律本身：它展示了一套“轻量基座 + 领域 Mid-training + Harness 协同 RL + 生产闭环”的可复制配方。法律只是第一个压力测试场，这套范式能否平移到医疗、金融等其他高风险专业领域，是值得关注的下一步。
