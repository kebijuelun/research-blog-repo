# QuickE2E：大白话写 E2E 测试，小模型只点按钮，代码判对错

E2E 测试是前端工程里最"脆"的一环——选择器一改全红，而通用大模型驱动浏览器又慢又贵还会自报"假 DONE"。QuickE2E 卡进了两者之间的甜点位：用最小模型承担最小决策职责，其余全交给确定性代码。硬数字：同一购票任务上，本地引擎 Shisa DE-1 跑出 **2.94 秒、5/5 通过、每次 $0**，对比 Claude Code + Playwright MCP（Sonnet 5）的 25.29 秒、$0.0896——**快 8.6 倍且零成本**；托管引擎 Jev 快 6.7 倍、便宜 234 倍。

## 核心设计：职责切分是灵魂

一份 spec 只含三样东西：plain English 目标、要输入的值、断言。没有选择器（字段靠 label 子串匹配），没有任何"怎么点"。

- **模型只做低维离散决策**：每步从几十个"合法动作"候选里挑一个 key（如 `CLICK 7 Pay`），返回列表外的 key 直接记 BLOCKED。模型无法发明动作、选择器或值——幻觉没有通道。
- **值只来自 spec**：本地模型只读候选标签的 logits，不生成任何文本，输出空间被结构性锁死。
- **通过与否代码判定**：六种断言在每个页面快照上检查，全是确定性逻辑，模型永远无权说"测试通过"。
- **WEAK_ASSERTION 防"假绿"**：起始页加载后断言已成立的 spec 直接拒绝——它什么都没证明。

## 工作原理：三段流水线，只有一段调用模型

- **Discover**：纯 Playwright 爬出应用"地图"，零模型调用；完整爬取会真实提交表单，须指向一次性数据库或用 `--safe` 模式。
- **Decide**：唯一调用模型的环节。工程细节包括候选"分组淘汰赛"（并行裁决再决赛）、投机执行（提前发请求，仅与 settled 页面请求逐字节相同时才采用，结果与不开投机完全一致）、map 导航。
- **Verify**：断言由代码逐条检查，第一个全部成立的快照即判 PASS。

## 从探索到回归的闭环

`--emit` 把一次 PASS 固化为普通 Playwright spec：每个 locator 在运行期间于真实页面上构建验证，恰好匹配实际操作的那个元素。CI 回放零模型调用、每次约 0.8 秒；saucedemo.com 上 9/9 导出回放通过。密钥输入绝不写入文件——宁可让测试 skip，也不把凭证落盘。

## 攻击用例与密钥脱敏

- 攻击用例**必须双断言**：拒绝文案进 `expect`，成功状态进 `expectAbsent`——因为应用完全可以一边报错一边照样给你打折。
- 强密钥从所有引擎请求、trace、导出文件中擦除（含掩码变体）；弱密钥靠历史判定识别回显。自动"看起来像密钥"规则曾误伤四个正常流程而被放弃——敏感内容必须显式 `redact`。

## 引擎与成本结构

本地 Eikos-4B（4.1 GB 内存）和 Shisa DE-1（MoE 每 token 仅激活 3.8B）在 TicketBay 四 spec 上均 20/20，Shisa DE-1 端到端 2.0 秒甚至跑赢托管 Jev。八种 UI 技术栈（含 shadow DOM、iframe）× 三任务，Jev 拿下 120/120。配套 agent skill 让大模型只跑一次写 spec，之后每步决策由小引擎完成——**"大模型写一次，小模型跑一万次"**，这才是便宜 234 倍的根本原因。

官方也坦诚列出局限：不支持 canvas、跨域 iframe、跨标签页；无 SCROLL 动作；本地引擎仅限 Apple Silicon。

QuickE2E 验证了"专项小模型 + 确定性代码围栏"路线的可行性：决策空间被结构性约束后，4B 量级模型足以胜任原本被认为需要旗舰大模型的 UI 自动化工作。
