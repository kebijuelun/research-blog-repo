# A Thousand Fewer Paths：一次扫出 948 个提权漏洞

Linux 内核超过 4000 万行代码，静态扫描可以轻易制造数千条告警，真正的瓶颈却是复现、判断能否提权，并给出可审查的修复。OpenAI 用一个即将发布的网络模型搭建五阶段流水线。据其报告，2026 年 10 月中旬的一次运行从 2308 个候选中动态复现 1724 个漏洞，最终确认 948 个不同的本地提权（LPE）漏洞并生成对应补丁，总 API 成本为 121.343 万美元，平均每个约 1279 美元。

LPE 指低权限本地账户取得 root，并非远程入侵入口，却能突破云主机、Android 设备和 Linux 系统的权限边界。因此，这套系统的价值不在于多报漏洞，而在于用运行证据收敛人工审核范围。

## 从候选到补丁，逐层留下证据

流水线分为发现、动态验证、可利用性评估、补丁生成和人工审核。Scout 先按低权限用户可触达性和安全相关性筛选目标，只留下 5034 个目标、约 280 万行代码，即内核代码的 7%；Analyst 再在 12 小时内生成去重后的 2308 个候选。

Triage 为候选编写概念验证（PoC），在启用 KASAN 的隔离虚拟机中运行并迭代。30 小时内复现的 1724 个漏洞占候选约 74.7%；未复现不等于不存在，部分问题受竞态、特定内存分配失败等条件限制，只有 3.1% 被归为模型分析错误。

随后，系统在启用 SMEP、SMAP、KASLR 和 HARDENED_USERCOPY 的标准 Linux 桌面环境中开发利用，得到 291 个信息泄露 PoC 和 1169 个可运行的 LPE 利用。经变体分析，以 948 个不同补丁对应的漏洞作为唯一 LPE 数量。

## 自动拿到 root，也可能答错题

早期一次运行报告了 200 个成功 LPE，人工审核却发现其中 20 个改用了另一个 0-day，并未利用分配的漏洞。只看 root shell 会把它们全部误判为成功。团队随后收紧任务约束，并独立检查利用路径。这说明自动审计不能只验证终点，还必须验证到达终点的方式。

成本同样需要控制。利用开发花费 77.5929 万美元，是整次运行最大的开销；成功案例平均约 359 美元，69 个未成功案例却平均消耗 3922 美元。团队据此建议设置明确的放弃条件，并强调此次研究未专门优化成本，这些数字更像当前实现的上界。

模型升级也值得触发重扫：GPT-5.6 Sol 在 2026 年 7 月末得到 166 个唯一 LPE，成本 51.369 万美元；新网络模型在持续加固了 3 个月的内核上得到 948 个。这不能证明每个新漏洞都更复杂，却说明一次审计无法把问题“扫完”。

## 生成补丁，不等于修复完成

初版补丁可能扩大修改范围、牺牲性能或遗漏漏洞变体，因此还需要静态检查、邻近代码风格约束、变体分析和人工审核。10 天扫描与分析期间，已有 61 个 LPE 在上游修复、43 个已有暂存补丁；948 个候选补丁也不等于 948 个修复已经合并。

回到最初的问题，自动化的关键不是把告警列表变长，而是持续完成复现、利用路径核验和可审查修复。不过，这些结果只适用于特定 Linux 目标、威胁模型和高额 API 预算，维护者与安全研究员的审核仍不可省略。
