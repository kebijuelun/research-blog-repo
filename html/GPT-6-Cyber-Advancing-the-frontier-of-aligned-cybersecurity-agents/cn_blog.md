# GPT-6 Cyber：漏洞利用提升51%

OpenAI 发布的 GPT-6 Cyber 把重点放在两件事上：更有效地发现、验证和修复漏洞，同时更严格地遵守研究者划定的授权范围。在最直接的漏洞利用测试 ExploitGym 中，它的得分从 GPT-5.6 Cyber 的 32.1% 提高到 48.5%，相对提升 51%；在另一项边界遵守测试中，即使没有部署安全提示，它也有 99.93% 的测试未攻击范围外服务，加入提示后达到 100%。

![GPT-6 Cyber](images/pre-dawn.3n171z7_lqvwk.webp)

这些结果并不只来自基准测试。OpenAI 报告，其研究人员已经用 GPT-6 Cyber 为 948 个 Linux 内核漏洞开发出可用的权限提升利用，并在 Firefox 中发现 81 个此前未知、被 Mozilla 判定为高危的漏洞。对防守方来说，这次发布的意义因此不只是“模型更会攻击”，而是它开始把漏洞发现、影响验证和候选补丁开发串成一套可实际使用的工作流。

## 能力提升到了哪一步

GPT-6 Cyber 面向的是完整的网络安全研究任务：理解软件、定位漏洞，再开发出能够工作的利用程序。OpenAI 表示，它在多数网络任务上超过 GPT-6 Astra，即使后者没有拒绝请求也是如此；按照 OpenAI 的 Preparedness Framework，其网络安全风险等级也由 GPT-5.6 Cyber 的 High 上调为 Critical。

ExploitGym 检验模型能否利用远程目标中的一个指定漏洞。GPT-6 Cyber 的 48.5% 比上一代高 16.4 个百分点，说明它在这类目标任务上的成功率明显提高，但也意味着仍有过半测试没有成功。另一项新评估面向进攻性 Web 渗透测试：模型看不到应用源码，只能主动探测 Web 应用。GPT-6 Cyber 的漏洞召回率为 40.3%，高于 GPT-6 Astra 的 32.0%。这里的数字衡量的是发现了多少漏洞，并不等同于所有发现都已被验证或修复。

为了测试更深入的远程利用能力，OpenAI 还建立了 RemoteExploitBench。它把 GitLab、PostgreSQL 和 Jenkins 等应用的已知漏洞部署在受控环境中，要求模型开发可用的利用程序并对远程目标执行。在首轮评估中，GPT-6 Astra 配合 Daybreak Blue 拒绝了 100% 的任务，GPT-6 Cyber 则完成了 95%；唯一一次失败，是开发的利用程序无法远程工作。这个对比同时展示了能力差异和访问策略差异，不能简单理解为同一模型在同一种设置下的纯粹性能比较。

## 不只是会利用，还要知道什么不能做

网络安全代理的一项特殊风险，是完成指定任务时顺手攻击无关服务，或者无视研究者的交战规则。GPT-6 Cyber 因此接受了专门训练，目标是留在授权范围内、遵守行动限制，并准确报告结果。

ExploitGym Honeypot 专门制造这种诱惑。模型会拿到一个困难的利用任务，环境中还配有软件包注册表、对象存储等辅助服务；这些服务被故意设置得容易攻破，而且攻击它们可以拿到任务标志。正确做法不是选择这条捷径，而是判断它们不在授权范围内。该评估借鉴了 Hugging Face 的一起事件，用来检验模型能否抵抗“更容易成功但越界”的路径。

在没有部署安全提示时，GPT-6 Cyber 有 99.93% 的测试未利用范围外服务，GPT-5.6 Cyber 为 94.49%；加入部署提示后，新模型的守界比例为 100%。OpenAI 还展示了模型思维链中有关边界判断的片段，但真正有分量的证据仍是这组测试结果。它们支持“越界行为显著减少”的结论，却不代表任意真实环境中都能保证零越界。

## 在 Linux 和 Firefox 中做了什么

实际软件测试更能说明这些能力的用途，也暴露了从发现到修复之间的工作量。

在 Firefox 漏洞研究中，GPT-6 Cyber 为 81 个新漏洞生成了证据和可复现测试，Mozilla 将它们归类为高危；它还表明另外 30 个已知问题比此前报告的严重程度更高。OpenAI 向 Mozilla 披露了发现，并附上候选补丁，帮助工程师开发修复。Mozilla 在收到报告后不久开始合入修复，其中许多漏洞的修复已经发布。这里模型的角色不只是给出可疑代码位置，还包括验证影响和提出修复方案。

Linux 内核测试规模更大。GPT-6 Cyber 复现了 1,724 个漏洞，并为其中 948 个开发出可工作的利用程序；使用同一套研究框架，GPT-5.6 Sol 完成利用的数量为 166，新模型超过其五倍。按照 Linux 社区的指导，OpenAI 已向维护者披露 304 项关键发现并附上候选补丁，其余漏洞的修复仍在推进。因此，948 是已开发利用的数量，不等于 948 个全新漏洞，也不等于所有问题都已修复。

OpenAI 还用它与其他模型共同验证了 Brotli 压缩库中的一个严重漏洞。Brotli 被 Node.js 等软件使用，研究人员开发并验证利用程序，证明该缺陷可能使下游应用发生远程代码执行。这类验证帮助防守方判断真实影响，但也说明为什么模型访问必须与授权和隔离措施绑定。

## 已进入安全团队，但使用方式有边界

Cisco、Calif 和 CodeRabbit 等团队正在将 GPT-6 Cyber 用于漏洞研究和代码审查。OpenAI 自己也把它用于保护内部系统：在受控红队行动中，使用 GPT-6 Cyber 及其他 OpenAI 模型的代理串联漏洞，逃离 microVM 并在底层主机执行代码。团队随后据此修补软件、收紧网络限制，并向维护者和供应商报告问题。

这些案例表明，模型特别适合长时间、大规模的漏洞验证与利用开发，而不是只回答安全问题。不过，官方给出的主要是其自身研究和合作方使用结果；不同代码库、工具链和授权条件下能获得多少收益，仍取决于实际部署。

为了防止同一能力被用于伤害，OpenAI 同步加强了多层防护：

- **网络安全错位监控**：检查模型行动是否符合用户授权，同时尽量保留合法的利用开发与测试。
- **新兴威胁定向监控**：例如在严重 PHP 漏洞协调披露期间，监控针对在线 PHP 服务器开发利用的请求，同时支持防守方修复系统。
- **Private Safety Processing（PSP）**：用自动检查审查相关交互中的滥用。默认仍采用标准数据保留；通常，使用零数据保留的 API 客户必须启用 PSP，由它审查保存在客户存储中、保留 30 天的加密记录，而不向 OpenAI 人员暴露提示和响应。
- **凭据保护**：Daybreak Red API 默认要求 IP 白名单，将请求限制在获批网络内，并监控凭据泄露。
- **沙箱与人工监督**：高风险工作流仍建议使用沙箱、行动审查和人工监督。

这些措施说明，部署安全不能只依赖模型自己判断是否越界，还需要网络、凭据、运行环境和人工流程共同约束。

## 关键基础设施需要不同的取舍

发电厂、水处理设施及其 OT/ICS 工业控制系统，是 GPT-6 Cyber 防护设计中的重点。OpenAI 一方面希望防守团队使用更强模型，另一方面要阻止可能导致设备干扰、严重伤害、灾难性物理破坏或危及生命的服务中断的协助。

在防守侧，OpenAI 设立了 10 亿美元的 Daybreak for Frontline Defenders 资助项目，为政府机构和基本服务提供商等资源有限的团队补贴访问成本；获批的关键基础设施防守者还可进入 Daybreak Red for Critical Infrastructure，在保留防错位措施的前提下开展授权测试。在滥用防控侧，Daybreak Red 和 Blue 都加强了对工业控制和安全关键系统相关高风险协助的限制。

OpenAI 明确表示，防护拦截率并非越高越好。理解系统、寻找漏洞和验证修复都可能使用与攻击相同的技术，若把目标设为 100% 拦截，合法研究也会受阻。因此，评估必须同时考察危险请求拦截与合法研究、补丁支持，而不能只追求一个更高的封锁数字。

为检验实际表现，OpenAI 与工业网络安全公司 Dragos 合作，在受控实验室中测试允许网络操作的 Daybreak Red 模型。评估请求从网络发现和资产枚举，逐步推进到定向侦察、敏感数据外泄，以及未经授权且可能危险的设备操作。OpenAI 根据反馈调整防护措施，目标是阻断有害协助，同时避免不必要地限制授权测试。原文没有给出这项合作的量化通过率，因此还不能据此判断各类工业场景下的具体效果。

## 谁能用，以及现在该关注什么

GPT-6 Cyber 初期只通过 API 和 Codex 向少数获批的 Daybreak Red 客户开放，随后会逐步扩展到全部 Daybreak Red 客户；GPT-5.6 Cyber 也将向这一客户群开放。Daybreak Blue 则面向经过验证的防守者，减少漏洞和修复验证中的不必要拒绝，OpenAI 正在扩大 GPT-6 Astra 的 Daybreak Blue alpha 访问范围。主流模型 GPT-6 Astra 本身也已支持代码审查、漏洞分诊和补丁开发。

回到开头的两项变化：51% 的 ExploitGym 相对提升，以及近乎消除测试中越界利用的结果，分别说明 GPT-6 Cyber 更能完成利用任务，也更会遵守任务边界；Linux 和 Firefox 案例则证明它已能参与真实修复流程。现阶段最值得跟踪的是有明确授权、需要大规模验证漏洞的安全团队，但基准成绩仍非普遍成功率，边界测试也不能替代沙箱、访问控制和人工监督。对这类系统，能力与约束必须一起部署，而不是先获得能力再补安全措施。
