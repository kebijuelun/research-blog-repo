# Qwen3.5-4B Draft：27B推理单步平均接受5.58个token

NVIDIA发布了一个为Qwen3.8-27B配套的外部草稿模型：Qwen3.5-4B-Qwen3.8-27B-Draft。在SPEED-Bench定性子集、草稿块大小为16的测试中，它每个目标模型步骤平均返回5.58个token，Qwen3.8-27B内置MTP头则为3.81个；在33k至46k token的长上下文子集上，两者分别为5.11和3.86。

这里的5.58不是速度提升5.58倍，也不是回答质量得分，而是“接受率”：目标模型每执行一次验证步骤，平均能接受并返回多少个token。模型卡没有给出端到端延迟、实际吞吐或资源占用对比，因此这些结果展示的是降低解码延迟的潜力，不能直接换算成部署后的加速倍数。

## 用完整的4.21B模型替27B模型预写token

推测解码的基本分工是：让小模型先连续写出一段候选token，再交给大模型统一验证。这个草稿模型参数量为4.21B，基于Qwen3.5-4B和Qwen3.8-27B开发，采用`Qwen3_5ForCausalLM` Transformer架构。它不是依附于目标模型的草稿头，而是一个完整的语言模型，只是与Qwen3.8-27B共享tokenizer和词表。

实际推理时，输入必须使用Qwen3.8-27B的tokenizer处理。草稿模型按照目标模型的服务策略自回归采样一组候选token；该策略为temperature 1.0、top-k 20、top-p 0.95。随后，Qwen3.8-27B依据同一策略通过拒绝采样验证整段候选，被拒绝的token会从残差分布中重新采样，最终文本仍由目标模型产生。

这一过程是概率采样，而不是贪心接受。NVIDIA称，在这种验证机制下，被接受序列的分布与Qwen3.8-27B独立运行时完全一致。换句话说，它试图减少目标模型的解码步骤，而不是通过改变目标模型的输出分布来换取速度。

## 训练信号来自目标模型的逐位置分布

草稿模型要提出高接受率的候选，关键不是模仿人工参考答案，而是预测目标模型下一步会怎么输出。NVIDIA使用Nemotron-Post-Training-Dataset-v2中的199,998段单轮对话，但只取其中的提示词，回答全部由Qwen3.8-27B合成。

提示词使用固定随机种子，从九个类别中等量抽取：STEM、代码、数学、聊天，以及德语、西班牙语、法语、意大利语和日语多语数据。超过3,072 token的提示词会被丢弃。对于回答中的每个位置，训练流程记录目标模型在服务策略下的top-20输出分布，并把这个分布作为训练信号，让草稿学习匹配目标模型。

模型卡将训练文本规模标为10亿至10万亿token，这个区间很宽，并未提供更精确的token数量。已知训练序列长度为12,288 token，检查点版本为1.0，使用NVIDIA Model Optimizer的外部推测解码模式训练，训练工具版本为`nvidia-modelopt v0.48.0rc0`。

## 接受率提升出现在哪些任务

评估使用SPEED-Bench。它覆盖代码、人文、数学、多语、问答、RAG、推理、角色扮演、STEM、摘要和写作，包含两个与本文结果相关的子集：定性子集有1,138个对话轮次；throughput-32k长上下文子集有1,536个单轮提示，每类512个，输入长度为33k至46k token。

### 定性子集：所有类别都高于内置MTP头

以下结果均使用大小为16的草稿块，数值表示每个目标步骤平均返回的token数。

| 类别 | 本草稿模型 | Qwen3.8-27B MTP头 |
| --- | ---: | ---: |
| 代码 | 5.22 | 3.78 |
| 人文 | 5.39 | 3.61 |
| 数学 | 5.61 | 3.63 |
| 多语 | 6.55 | 4.38 |
| 问答 | 5.39 | 3.75 |
| RAG | 6.58 | 4.68 |
| 推理 | 5.98 | 3.93 |
| 角色扮演 | 4.41 | 3.16 |
| STEM | 5.44 | 3.61 |
| 摘要 | 6.19 | 4.13 |
| 写作 | 4.59 | 3.29 |
| 总体平均 | **5.58** | **3.81** |

总体平均上，外部草稿比MTP头多返回1.77个token。分类来看，RAG和多语的接受率最高，分别为6.58和6.55；角色扮演与写作相对较低，分别为4.41和4.59，但仍高于MTP头在对应类别中的3.16和3.29。

这组结果说明，完整草稿模型的优势并不只出现在某一种任务中。不过，它只说明候选token更容易被目标模型接受，并不意味着草稿模型本身在这些任务上的回答质量优于目标模型。

### 长上下文：高熵文本的接受率下降更明显

throughput-32k子集按文本熵分为低熵、混合和高熵三类，草稿块大小同样为16。

| 类别 | 本草稿模型 | Qwen3.8-27B MTP头 |
| --- | ---: | ---: |
| 低熵 | 5.80 | 4.73 |
| 混合 | 5.53 | 3.85 |
| 高熵 | 4.01 | 3.00 |
| 总体平均 | **5.11** | **3.86** |

低熵类别中，草稿模型平均每个目标步骤返回5.80个token；到了高熵类别，数值降至4.01。MTP头也从4.73降至3.00。这个对比符合推测解码对候选可预测性的依赖：目标输出越难预测，草稿候选越不容易被连续接受。即使如此，外部草稿在三个类别中仍都高于MTP头。

## 更大的草稿模型换来了更高接受率

NVIDIA还比较了同一系列的两个外部草稿、一个Llama草稿和目标模型内置MTP头。三者使用相同语料、相同目标模型和相同评估框架，草稿块大小均为16，结果按类别取平均。

| 草稿方案 | Embedding参数 | 非Embedding参数 | 总参数 | 定性子集 | throughput-32k |
| --- | ---: | ---: | ---: | ---: | ---: |
| Qwen3.5-4B（本模型） | 0.64B | 3.57B | 4.21B | **5.58** | **5.11** |
| Qwen3.5-0.8B | 0.25B | 0.50B | 0.75B | 3.92 | 3.60 |
| Llama-3.2-1B | 0.51B | 0.97B | 1.48B | 3.42 | 3.07 |
| Qwen3.8-27B内置MTP头 | 0（共享） | 0.42B | 0.42B | 3.81 | 3.86 |

4.21B的Qwen3.5-4B草稿取得了两组最高接受率，但参数量也最大。0.75B的Qwen3.5-0.8B在长上下文测试中与MTP头接近，定性子集略高；1.48B的Llama-3.2-1B则分别为3.42和3.07。

参数表还有一个容易忽略的细节：目标词表包含248,320个token，因此embedding与输出头并不小。三个外部草稿都将输入embedding与输出头绑定，表中embedding列只计算这份共享矩阵一次。Llama草稿的embedding和输出层也为该词表重新构建，所以检查点比原始Llama-3.2-1B更大。

MTP头没有自己的embedding和输出头，而是读取目标模型的对应参数。目标模型这两部分另有2.54B参数，MTP头不必单独存储它们，但运行时也不能脱离目标模型。因此，单看0.42B与4.21B，并不能完整反映两种方案的系统开销；反过来，接受率更高也不保证实际延迟一定更低，仍需把草稿自身的计算、显存和运行硬件计入测试。

## 部署路径与适用条件

这个检查点明确面向正在服务Qwen3.8-27B、希望通过推测解码降低解码延迟的开发者和推理服务商，不推荐把它当作通用聊天模型单独使用。模型于2026年11月17日发布到Hugging Face，可用于商业或非商业用途；下载与使用受NVIDIA Open Model Agreement约束，Qwen3.5-4B草稿基座和Qwen3.8-27B目标模型则采用Apache 2.0许可证。

模型卡将加速引擎列为vLLM，测试硬件列为NVIDIA Groq 3 LPU，并说明预期部署方式是将草稿编译到该LPU、通过其运行时执行。发布检查点仍是标准Hugging Face模型，也能加载到vLLM、SGLang和TRT-LLM。兼容性字段另外列出了NVIDIA Blackwell微架构，首选操作系统为Linux；这些字段描述的是不同运行环境信息，并不等于模型卡已经给出跨硬件性能对比。

输入是一维文本序列，输出也是一维文本序列，但草稿本身发出的是供目标模型验证的候选token块，最终回答由Qwen3.8-27B生成。NVIDIA同时强调，将基础模型或微调模型集成进实际系统前，还需要使用具体场景数据进行测试，并在单元和系统层面持续验证功能、安全与合规要求。

## 谁值得测试这个草稿模型

如果已经在服务Qwen3.8-27B，并且推理栈能够接入外部推测解码，这个4.21B草稿提供了清楚的测试理由：在两项SPEED-Bench评估中，它每个目标步骤平均接受的token数都高于内置MTP头，而且保持目标模型原有输出分布的验证机制已经明确。

但现有证据止于接受率，不是端到端加速报告。实际采用前，应在自己的目标硬件和真实提示分布上测量延迟、吞吐与资源占用，尤其关注高熵文本和长上下文；同时完成安全测试，因为模型卡没有提供去偏措施或偏见指标。对无法接受额外完整模型开销的部署，内置MTP头仍是参数更少的对照方案，只是这次测试中的接受率较低。
