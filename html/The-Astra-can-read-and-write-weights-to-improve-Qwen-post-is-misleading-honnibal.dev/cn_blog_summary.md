# Astra：改权重不等于读懂权重

把 Qwen3.5-0.8B 的 MATH-500 成绩从 7.9% 提到 48.1%，只修改 0.016% 的权重且不使用梯度，这个结果确实醒目。但原文作者提醒，Astra 并非“只看原始权重”就完成修复：它能编写 Python 程序，还能让模型在最多 50 批练习题上运行。这展示的是工具辅助的模型分析与修改能力，不能直接证明大模型已经读懂权重。

原帖摘要还把几项能力并列呈现：仅凭原始权重判断网络用途；在没有环境反馈时，从零写出胜过 1 亿步 PPO（近端策略优化）训练的网络；修复 Qwen 的数学推理问题，并让 IFEval 指令遵循成绩提升至原来的 3 倍。相似的结果容易让人以为它们来自同一种技术，实验设置却并不相同。

## “只看权重”有严格边界

这里的严格设置是：把原始浮点数放进上下文，不使用工具，也不运行网络。模型必须直接根据数字判断，不能先用代码计算统计特征、观察中间激活，再依据程序输出推理。前者接近对权重本身的理解，后者更像自动化机器学习工程；两者都有价值，但不能共享同一句结论。

真正满足“原始浮点数、无工具、不运行网络”的只有实验 1、2 和 4，网络规模介于 17K 到 172K。前两项分别正确识别了 PPO MLP 对应的游戏（4/4）和扩散 MLP 生成的形状（3/3）；第四项把卡住的 Kinetix 汽车策略从 0% 修复到 100%。这些结果值得讨论，却不能直接外推到 800M 参数的 Qwen，更不能替使用 Python 的实验作证。

## Qwen 实验实际展示了什么

所有涉及真实语言模型的实验都使用了 Python。“不使用梯度”只排除了通过反向传播更新模型，并未把任务限制为静态阅读权重；Qwen 实验还允许最多 50 轮运行。因此，所谓修复导致推理循环的权重问题，必须连同这些条件一起理解。

Gemma 3 的对照进一步说明信息来源很重要：不能查看注意力模式时，识别谄媚模型的任务失败；允许运行网络并查看注意力模式后，3 次判断全部正确。而在 Gemma 3 上重复 Qwen 的修复流程，即使用 Python 并运行 50 轮，仍然失败。这说明最亮眼的结果有明确对象和条件，并非普遍成立的语言模型权重编辑能力。

作者并未否定 Astra 的工程价值：如果它能根据提示自行设计代码、分析并修改网络，就已经是有用的能力，一两年前的 AI 模型很可能做不到。争议只在证据边界。7.9% 到 48.1% 可以证明一次具体的工具辅助修复，却不能替代“直接读懂原始权重”的证据；后者目前应限定在实验 1、2 和 4 的小规模网络上。这篇评论没有提供新的复现实验，其价值正是把原帖摘要中容易被合并的能力重新拆开。
