# SFR-AutoR&D 精华总结：AI Agent 自己跑完整个研发闭环

AI 会写代码不新鲜，但让它**自己决定研究什么、动手实验、并拿出可复现的证据证明改进有效**，才是真正的研发。Salesforce AI Research 发布的 SFR-AutoR&D 就是这样一套自主 R&D 系统：给定研究目标、可操作的代码仓库或模型、预算约束，剩下的"假设—实现—验证—迭代"闭环全部由 Agent 完成。结果相当硬：pandas 行级归约最高提速 **1.84 倍**、USearch 检索 QPS **+17.5%**、自家 RL 训练栈生成速度 **3.14 倍**；TrainForge 自主发明的训练方法在留出基准上带来 **+11 到 +14 个百分点** 的提升。

## 核心设计：验证是闭环的中心

- 定位不是代码助手，而是对结果负责的"虚拟研究员"：**未通过验证的改进一律不采纳**，每个交付物必须附带可复现的基准证据。
- 闭环为 Discover → Build → Evaluate → Learn，每轮实验结果直接指导下一轮。

## 系统组成

- **AutoR&D-Engineer**：面向已有代码库，输出补丁 + 基准证据。
- **TrainForge**：面向模型训练，自主发明训练方法，输出已验证 checkpoint。
- **AutoInfra**：共享训练/推理底座，支持 **1T 参数、100 万 token 上下文** 的全参数训练；两个 Agent 验证过的改进回流其中，形成"自我改进"飞轮。

## 关键成果

- **pandas 1.84× 提速**：消除行级归约中与整个 DataFrame 等大的临时标签数组，改用转置视角单分组调用聚合内核，结果**逐位相同**；40 个 benchmark 提速 1.22–1.84×，峰值内存降 12–15%。
- **证据链厚度惊人**：134,064 个差分测试用例零差异，437 个新测试 + 44,458 个存量测试全过——已接近人类资深工程师提交上游 PR 的验证规格。
- **改造策略保守**：为符合条件的输入提供 fast path，其余走原实现，适合上游合入。
- **TrainForge 发明新方法**：在 Qwen3-4B 上围绕"保留推理结构而非只要最终答案"自主生成训练策略，用冻结的留出数据集评估，避免自评自夸；十几个点的提升通常是研究团队数月迭代的成果，这里由 Agent 闭环完成。

## 局限与展望

目前案例集中在有明确可度量指标的领域；对"好"难以定义的开放性研究问题，这套证据驱动闭环能走多远尚待验证。路线方向：更多目标、更深自主性、打包成附完整证据的上游 PR。
