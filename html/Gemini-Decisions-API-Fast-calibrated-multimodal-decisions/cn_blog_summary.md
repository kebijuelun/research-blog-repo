# Gemini Decisions API：一次前向计算评估千项多模态问题

一张茶水柜台面的照片，加上“上午 9 点客户会议前检查”的说明，系统要同时判断是否有未清理液体、该采取什么清理动作、污渍有多严重。这类任务不需要长篇分析，而要尽快返回明确选项和置信度，让程序决定下一步。

Google 新发布的 Gemini Decisions API 正面向这种封闭集合判断。它由 Gemini Decision 1 驱动，可在文本、图片、音频、视频和 PDF 上评估是非、多选和评分问题：一次请求最多接收 256K token 的共享输入，并提出 1,000 个相互独立的问题。

## 不生成文本，直接给选项打分

Gemini Decision 1 跳过逐 token 解码，共享输入只处理一次，在一次前向计算中为候选项打分，返回概率与 0 到 1 的置信度。它适合工具调用、内容审核、模型路由等已有固定选项的任务；开发者也能设置阈值，把模糊案例交给备用模型或人工审核，而不必训练专用分类器或等待完整生成回答。

## 官方数据强调校准，也限定测试条件

Google 报告称，在覆盖智能体路由、推理、排序和多模态理解的基准套件中，Gemini Decision 1 整体领先，并取得最低校准误差。校准关注高置信度是否对应更高可靠性，对依赖概率自动分流的系统尤其重要，但不等于每次判断都正确。

官方模型计算中位延迟为 50–100 ms，端到端为 150–250 ms，条件是多模态输入和最长 16K token 上下文，不能外推到 256K 上限。每请求从 1 个问题增至 100 个时延迟基本平稳，但这不构成 1,000 个问题下的同样承诺。

价格为每百万输入 token 0.10 美元，输出不收费。官方称其在共享基准上比 Gemini 3.5 Flash-Lite 搭配 Interactions API 有近 5 倍成本优势，该比例仍限于特定测试组合。

## 三类问题共享一次输入

一次请求可混合 `noul` 是非题、`choice` 多选题和 `score` 有序评分：多选支持 2 到 255 个候选并返回归一化概率，评分则返回连续加权分数及各等级概率。共享输入只计费一次，每个问题仅增加指令和判定标准 token。

Google 披露的内部案例也围绕快速判断展开：Gemini Notebook 用它动态路由模型，日常查询延迟最多降低 40%；CC 从 200 多个表情中在不到一秒内选择反应；Search 将其用于 MCP 工具安全检测，但未公布具体分数。

回到茶水间例子，Decisions API 的价值是让状态检查、动作选择和等级评分直接接入后续流程。若你的任务已有清楚选项并需要多模态快速分流，值得优先验证置信度阈值；但它不是通用生成模型的替代品，且现有性能和成本数据均来自 Google，采用前仍需用自己的输入分布和延迟预算复测。
