# GPT-6 家族实战指南精华：选型、Prompt 与长任务管理

GPT-6 系列发布后，"模型更强"不等于"用得更对"。OpenAI 这份官方指南直击开发者最头疼的问题：三个模型怎么选、Prompt 要不要重写、动辄数小时的 Agent 任务怎么管住、成本怎么压下来。最硬的两个数字：缓存命中的输入 token 最高可省 **95%** 成本；GPT-6.1 Sol 能以**五分之一**的价格提供接近旗舰的智能水平。

## 模型选型：一道算术题

三档定位，先估任务难度再查价格表：

- **GPT-6 Astra**：旗舰，攻坚最难推理（输入 $10 / 输出 $50 每百万 token）
- **GPT-6.1 Sol**：接近旗舰智能，价格仅五分之一，适合复杂编码、研究与 Computer Use（$2 / $10）
- **GPT-6 Luna**：日常主力，规模化处理目标明确的重复任务（$0.10 / $0.50）

在此之上还有两级"权衡旋钮"：推理档位（Low / Medium / High / Extra high，可在对话中途调整且不破坏缓存）和速度模式（Fast 与 Ultrafast，为响应时间付费）。

## 成本与效率：缓存是最大杠杆

- **Prompt Caching**：稳定指令和参考材料前置、任务细节后置、工具定义保持一致，缓存输入最高省 95%
- **Compaction**：长对话压缩上下文，保留工作所需状态
- **上线前必测**：任务成功率、延迟、单次成功任务成本；估算时别漏算缓存写入和长上下文费率

## Prompt 要瘦身：从"技巧活"到"管理活"

反直觉观点：模型对细微差别的理解已大幅提升，过度具体的"保姆级 Prompt"反而有害。正确姿势是写一份"委派书"：

- 说清要什么结果、给谁看、约束条件和"完成"的判定标准
- Skills 描述要短，细节按需加载，取代僵化的"菜谱式"步骤
- 设定决策边界：哪些可自主执行、哪些必须请示
- 严格定义"done"：实现变更 + 运行验证 + 检查结果 + 修复失败

## 长任务管理：三件套防跑偏

GPT-6 已能承担跨数小时甚至数天的任务，管理工具分两条线：

- **API 侧**：Mid-turn steering 中途纠偏（不会中断已运行的工具调用）；异步工具调用，慢任务后台跑、独立工作继续推进；GPT-6.1 Sol 支持 multi-agent 委派（beta），子任务分派给子智能体并行处理
- **Codex 侧**：工作中主动请求澄清；需求变化时明确"什么要改、什么不变"，避免在过时方案上继续烧钱；离开前约定哪些任务可继续、何时必须暂停

## Computer Use：最后手段而非首选

三个模型都支持直接操作无 API 的网站和桌面应用（如修完 bug 后在浏览器里验证修复）。原则是"最简单的可靠路径"：能用 API 就不绕界面；确需看屏点击时才用 Computer Use——Playwright 管浏览器，PyAutoGUI 管桌面。

## 结语

这份指南的信号很清晰：模型能力的竞争正在让位于"Agent 工程化"的竞争。谁把转向、委派、缓存、监控这套基础设施玩熟，谁就能以更低成本把更强的智能落进生产环境——现在正是按 GPT-6 思路重构 Prompt 资产和工作流的好时机。
